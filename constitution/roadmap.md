# 项目路线图

状态：初始化路线图

本文件只记录已经确认的阶段目标。未确认的产品功能不得因出现在讨论或示例中而被视为承诺。

## 阶段 0：项目治理初始化

目标：

- 建立项目级 Agent 规范；
- 建立 Constitution 基础文件；
- 建立多 Agent 工作流和 Prompt；
- 建立决策、代码变更、测试和 Git 规则；
- 明确文档语言、职责边界和授权方式。

完成标准：

- 基础文档已创建且相互引用一致；
- 重要初始化决策已写入 `.ai/decisions/`；
- 尚未确认的产品和技术信息被明确标记为待确认。

## 阶段 1：产品与技术基线

进入条件：阶段 0 完成。

目标：

- 确认项目使命、目标用户和第一阶段产品范围；
- 确认前端、后端、数据存储、部署和测试技术栈；
- 确认安全、隐私、性能和兼容性基线；
- 根据已确认目标建立首批业务 Spec。

## 阶段 2：按 Spec 迭代

进入条件：相关 Spec 已由用户确认。

每个功能按“Spec → 实施 → 独立验收 → 必要返工 → 用户审查”的闭环交付。

## 阶段 3：发布准备

具体范围待产品与部署目标确认后补充。至少应覆盖：

- 发布检查和回滚策略；
- 数据迁移与兼容性检查；
- 安全、性能和可靠性验收；
- 运维与用户文档；
- 发布后的监控和问题响应。

## 路线图维护规则

- 路线图变化由协调开发 Agent 与用户确认。
- 影响范围、优先级或发布日期的重要变化必须记录决策。
- 路线图不代替功能 Spec，也不授权实施 Agent 开发。
