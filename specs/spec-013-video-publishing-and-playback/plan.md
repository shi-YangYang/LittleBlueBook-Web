# SPEC-013 实施计划

- Spec：`specs/spec-013-video-publishing-and-playback/spec.md`
- 当前 Spec 状态：Accepted
- 计划状态：Completed
- 负责人：协调开发 Agent
- 实施约束：只有用户确认完整 Spec 后才能创建一个新的单一实施 Agent；数据库、后端、前端、Docker 和 E2E 必须由同一 Agent 串行完成；实施 Agent 不得创建子 Agent。

## 1. 实施目标

- 建立向后兼容的图文/视频笔记联合模型；
- 完成安全、流式、可取消且可清理的视频发布管线；
- 完成原始 MP4 的本地持久化与 HTTP Range 播放；
- 接通推荐、频道、视频页、搜索、个人主页、详情和既有互动；
- 保持图文、认证、法律门禁、滚动模型和常规 CI 边界不回归。

## 2. 预计影响范围

### 数据库与迁移

- 笔记内容类型枚举/字段；
- 一对一视频与封面元数据；
- 视频聚合、作者、频道和搜索相关索引；
- 历史笔记无损回填 `IMAGE`；
- 空库与 SPEC-012 历史库升级探针。

### 后端

- 发布前认证、法律、年龄、并发和频率门禁；
- 独立视频发布的流式 multipart 接入；
- Node.js 内部 MP4 元数据与编码验证；
- 临时文件、活动占用、启动/定时清理和补偿事务；
- 原始媒体与封面存储；
- GET/HEAD/Range 媒体响应；
- 推荐、频道、视频聚合、搜索、主页、互动和详情联合读模型；
- OpenAPI、配置、日志和错误映射。

### 前端

- 发布模式选择、视频预览、浏览器封面提取、自定义封面；
- XHR 或等价真实上传进度、取消、阶段和重试；
- 全局【视频】链接与 `/videos` 页面；
- 联合卡片、视频标识和时长；
- 搜索视频、个人页和公开主页；
- 详情播放器、错误重试和现有互动；
- 自适应高度、滚动与无障碍。

### 部署与测试

- Docker 媒体持久化、请求大小与 Range；
- 小型永久 MP4/封面夹具；
- 后端、前端、迁移、存储和三浏览器 E2E；
- 不改变常规手动 CI 的 Browser E2E 边界。

## 3. 实施顺序

### 阶段 A：模型与兼容迁移

1. 增加内容类型和视频元数据关系；
2. 回填全部历史笔记为 `IMAGE`；
3. 增加必要索引和关系约束；
4. 更新 Prisma 类型和联合读模型；
5. 验证空库、历史库、关系和计数无损。

### 阶段 B：流式上传基础设施

1. 在读取正文前完成写操作门禁；
2. 建立每账号一个活动上传和每小时 10 次限制；
3. 建立私有临时目录和有界流式写入；
4. 建立取消、超限、断网和异常清理；
5. 建立启动检查、定时清理和活动文件保护；
6. 完成权限、限流、并发和资源上限测试。

### 阶段 C：验证、封面与发布原子性

1. 接入 Node.js MP4 容器、轨道、编码、时长和尺寸解析；
2. 复用/扩展封面图片验证；
3. 建立视频、封面最终对象和数据库归属；
4. 用 `clientRequestId` 保证幂等；
5. 完成存储/数据库故障补偿与孤立对象测试；
6. 更新 OpenAPI 和安全错误。

### 阶段 D：媒体读取与播放器

1. 扩展媒体存储接口支持元数据和区间读取；
2. 实现 GET、HEAD、单 Range、`206` 和无效 Range；
3. 保持路径安全、有界内存和正确 MIME；
4. 详情按内容类型切换图片或视频播放器；
5. 完成封面、预加载、错误、重试和详情返回回归。

### 阶段 E：发布 UI

1. 增加图文/视频模式和切换确认；
2. 增加本地视频解析、预览和首帧封面提取；
3. 增加自定义封面、校验和失败降级；
4. 增加真实上传进度、取消、阶段和重试；
5. 保留文本、频道、未保存和登录后恢复；
6. 完成高度、滚动和可访问性测试。

### 阶段 F：列表、搜索与个人页

1. 扩展统一笔记卡片联合类型；
2. 推荐与频道混合两种内容；
3. 建立 `/videos` 页面和只视频分页接口；
4. 把搜索视频空页替换为真实 PostgreSQL 查询；
5. 扩展当前用户笔记/收藏/点赞与公开主页；
6. 保持图文查询和卡片行为不变。

### 阶段 G：互动、通知与浏览量

1. 让现有互动服务接受视频笔记；
2. 通知映射使用联合封面；
3. 保持评论定位、关注和事务语义；
4. 保持详情成功展示后的浏览量上报；
5. 验证 Range/播放操作不重复计数。

### 阶段 H：集成与回归

1. 更新永久小型媒体夹具和正式 E2E；
2. 运行数据库、静态、单元/集成、构建和 Docker 验证；
3. 运行 Chromium 完整视频主流程；
4. 运行 Firefox/WebKit 媒体差异场景；
5. 按初次实施要求运行相关 Browser E2E；
6. 清理临时媒体、容器、卷、网络和测试产物并返回报告。

## 4. 关键实现门禁

- 不得用完整内存缓冲接受视频；
- 不得仅依赖扩展名、MIME 或客户端验证；
- 不得要求用户安装 FFmpeg 或第二套 Node.js；
- 不得在认证/法律/年龄门禁前写入视频字节；
- 不得把“视频”写成频道；
- 不得破坏现有图文发布契约或历史数据；
- 不得用删除测试产物掩盖运行期泄露、孤立文件或资源问题；
- 不得加入自动播放、转码、断点续传、笔记删除等非范围功能。

## 6. 风险控制

- 先建立流式与清理基础，再接 UI，避免 100 MiB 内存回归；
- 用小型合法/非法夹具覆盖解析，不用真实用户文件；
- 将视频发布与现有图文 multipart 路径隔离，减少兼容风险；
- Range 和存储抽象先做后端探针，再接播放器；
- 查询统一使用内容类型联合结构，防止各页面出现不同媒体判断；
- 任何新依赖必须锁定版本、检查许可证和维护状态，并只服务于已确认方案。
