## 1. 背景

项目已经具备图文笔记发布、推荐与频道信息流、个人主页、搜索、笔记详情、点赞、收藏、评论、关注、通知和浏览量，但“视频”仍只是全局菜单占位，搜索结果的【视频】Tab 也固定为空。

本 Spec 建立第一条真实视频内容闭环：登录用户发布单个 MP4 视频，视频进入推荐、所属频道、视频聚合页、搜索和个人主页；任何用户可以在笔记详情中播放，并继续使用现有社区互动能力。

本期以单机本地持久化和原始文件播放为目标，不引入转码、多清晰度、CDN 或对象存储。视频是笔记的一种内容类型，不是新的发布频道；“数码、汽车、游戏、其它”等频道继续表达内容主题。

## 2. 已确认目标

- 一条笔记只能是图文笔记或视频笔记，不允许图片与视频混合；
- 发布页提供【发布图文】和【发布视频】两种模式；
- 视频笔记包含标题、正文、频道、一个视频和一张封面；
- 仅接受不超过 `100 MiB`、时长 `1 秒～10 分钟`的 MP4；
- 视频轨道必须为 H.264；允许无声视频，存在音频轨道时必须为 AAC；
- 用户可上传封面；未上传时由浏览器提取首个可用画面生成封面；
- 首页推荐和普通频道同时展示图文与视频；
- 所有全局【视频】入口统一进入公开 `/videos` 页面；
- 搜索结果【视频】Tab 接入真实视频搜索；
- 当前用户和他人公开主页展示视频笔记；当前用户的收藏、点赞列表也支持视频；
- 视频详情复用现有作者、正文、关注、点赞、收藏、评论、回复、通知和浏览量；
- 视频默认不自动播放，使用浏览器原生控制并支持 Range 请求；
- 上传使用有界内存的流式临时存储，并显示进度、支持取消和失败重试；
- 本地媒体存储保持可替换抽象，未来可以迁移至 S3 兼容对象存储和 CDN；
- 现有图文数据、接口行为和用户内容必须无损兼容。

## 3. 范围

### 3.1 本期包含

- 笔记内容类型及视频元数据模型；
- 对全部历史笔记无损回填图文类型的兼容迁移；
- 单视频发布、客户端封面提取、自定义封面和上传进度；
- 服务端实际 MP4、H.264、AAC、时长、尺寸和字节数验证；
- 认证、法律状态、年龄门禁、单账号并发占用和视频上传限流；
- 流式临时文件、原子归属、异常恢复和超时临时文件清理；
- 本地原始视频与封面持久化；
- 支持完整响应、HTTP Range、HEAD 和安全错误的媒体读取；
- 首页推荐、普通频道和 `/videos` 的真实视频卡片；
- 搜索【视频】Tab 的真实查询、排序和分页；
- 当前用户及他人公开主页的图文/视频展示；
- 当前用户收藏、点赞列表中的视频展示；
- 视频详情播放器及现有社区互动闭环；
- 加载、上传、取消、失败、重试、空状态和无障碍体验；
- REST/OpenAPI、数据库迁移、单元/集成/组件测试和 Browser E2E；
- Docker 本地持久化、上传限制和媒体读取兼容性验证。

### 3.2 本期不包含

- 多视频笔记、图片与视频混合笔记、GIF 动图笔记；
- 视频转码、多清晰度、自适应码率、切片转码或 HLS/DASH；
- 服务端 FFmpeg/ffprobe 依赖；
- 断点续传、分片上传、秒传或跨设备续传；
- 首页卡片悬停播放、自动播放或静音预览；
- 视频编辑、裁剪、滤镜、水印、字幕、弹幕或倍速的定制 UI；
- 视频内容审核、版权识别、病毒扫描或推荐算法；
- 独立播放次数指标；
- 直播；
- 笔记编辑、删除、替换视频或替换已发布封面；
- 草稿、定时发布、私密发布或审核状态；
- S3 兼容对象存储、CDN 或多机共享媒体；
- 移动 App 或独立移动端设计；
- 对常规手动 CI 增加浏览器安装或 Browser E2E。

## 4. 核心内容模型

### 4.1 内容类型

- 笔记增加稳定内容类型，语义至少包含 `IMAGE` 和 `VIDEO`；
- 现有全部笔记在兼容迁移中回填为 `IMAGE`，不得删除、重建或改变 ID、作者、频道、互动、浏览量和时间；
- `IMAGE` 笔记继续要求 `1～9` 张现有图片且不得关联视频；
- `VIDEO` 笔记必须且只能关联一条视频元数据，不得关联笔记图片；
- 服务层和数据库关系共同维护上述互斥不变量；任何非法组合不得公开返回。

### 4.2 视频元数据

每条视频元数据至少包含：

- 稳定记录 ID 和所属笔记 ID；
- 随机视频对象 Key；
- 权威 MIME 类型；
- 文件字节数；
- 视频像素宽度和高度；
- 毫秒级时长；
- 视频编码标识；
- 可为空的音频编码标识；
- 随机封面对象 Key、封面 MIME、字节数、宽度和高度；
- 创建时间。

对象 Key 不使用原始文件名、邮箱、用户 ID 或服务器路径。数据库不保存媒体二进制、临时路径或宿主机绝对路径。

### 4.3 封面语义

- 视频笔记始终具有一张持久化封面；
- 用户上传的封面优先于自动提取封面；
- 自动封面由浏览器从本地视频的首个可解码画面生成，再作为普通封面文件上传；
- 自动提取失败时必须要求用户上传封面，不允许无封面发布；
- 封面用于信息流、搜索、个人主页、通知预览和播放器 `poster`；
- 封面不是 `NoteImage`，不得使视频笔记被图文查询误判。

## 5. 角色、权限与入口

### 5.1 未登录用户

- 可以访问首页推荐、普通频道、`/videos`、视频搜索、公开主页和视频详情；
- 可以加载公开封面和视频媒体；
- 点击发布时沿用现有登录弹框及登录后继续 `/publish`；
- 不能发起或占用视频上传，不得先接收大型请求体后再返回未登录；
- 点赞、收藏、评论和关注继续按现有登录后恢复规则处理。

### 5.2 登录用户

- 在法律状态有效、年龄门禁通过时可以发布视频；
- 会话失效、条款待确认或年龄受限时，服务端必须在接收视频字节前拒绝；
- 可以同时浏览和互动，但同一账号同一时刻只能占用一个视频上传；
- 视频作者由服务端会话确定，客户端不得提交或覆盖作者 ID。

### 5.3 全局视频入口

- 首页、个人页、搜索页、通知页、私信页、帮助/关于等复用全局侧栏的页面，现有【视频】入口统一为 `/videos` 链接；
- `/videos` 路由公开、可刷新、可直接访问、可分享并支持浏览器前进/后退；
- 位于 `/videos` 时，全局菜单向辅助技术和视觉状态表达【视频】已选中；
- “视频”不是 `Channel`，不得加入发布频道表或频道选择器。

## 6. 发布页面

### 6.1 模式选择

- `/publish` 增加【发布图文】和【发布视频】两个可键盘操作的模式选项；
- 默认进入图文模式，保留现有用户习惯与兼容性；
- 两种模式共用标题、正文、频道、话题占位、未保存状态和发布结果规则；
- 已选择媒体后切换模式必须先显示二次确认；确认后清除不兼容媒体、预览和上传状态，取消则保持当前模式；
- 不得把图文图片自动转换为视频封面，也不得把视频封面计入图文图片数量。

### 6.2 文本与频道

- 标题继续为去除首尾空白后的 `1～50` 个用户可见字符；
- 正文继续为去除首尾空白后的 `1～2000` 个用户可见字符；
- 标题、正文保持纯文本和换行，不解析 Markdown、HTML 或话题；
- 频道必选，使用现有公开、启用且可发布的权威频道列表；
- “其它”可以选择；“推荐”“未分类”和“视频”不得成为发布频道；
- 发布成功后进入现有 `/explore/{noteId}` 详情路由。

### 6.3 视频选择与预览

- 视频模式只允许选择一个本地文件；拖放或再次选择时不得静默叠加第二个视频；
- 选择后展示封面预览、文件大小、视频宽高、格式和 `分:秒` 时长；
- 客户端先做即时格式、大小、时长和可解码性提示，但客户端结果不能替代服务端验证；
- 用户可以移除视频、替换视频、上传/替换发布前封面；
- 视频或封面改变后进入未保存状态；
- 未选择有效视频、封面未就绪、文本或频道无效、正在上传时，发布按钮不可重复触发；
- 页面刷新、关闭和站内离开继续使用现有未保存内容确认规则。

### 6.4 上传进度、取消和重试

- 上传过程中展示真实已发送字节进度，不使用伪造进度条；
- 展示正在上传、正在校验、正在发布三个可理解阶段；
- 用户可以取消正在进行的上传；取消后保留标题、正文、频道和本地文件选择，允许重新发起；
- 网络失败、服务端失败或校验失败时保留表单和本地预览，显示安全、具体且可重试的错误；
- 重试继续使用同一 `clientRequestId`，不得创建重复笔记；
- 成功后清除未保存状态和上传占用，并导航到新视频详情。

### 6.5 高度与滚动

- 初始视频发布页和单个视频预览不得产生无意义的 `html` 根滚动条；
- 上传状态、校验错误和封面区域出现时不得引起明显布局跳动；
- 内容超过支持视口时由明确内容容器或页面按既有滚动模型滚动，不得出现双重滚动；
- 遵守最低 `960×600` CSS 视口与连续自适应基线，不枚举固定高宽组合。

## 7. 媒体校验规则

### 7.1 视频

- 单个视频最大 `100 MiB`，即 `100 × 1024 × 1024` 字节；
- 权威时长必须不少于 `1,000 ms` 且不超过 `600,000 ms`；
- 容器必须是有效 MP4，视频轨道必须可识别为 H.264；
- 允许没有音频轨道；存在音频轨道时必须为 AAC；
- 横屏、竖屏和方形视频均允许，宽高必须为有效正整数；
- 服务端使用 Node.js 内部媒体解析验证容器、轨道、编码、时长和尺寸，不要求系统安装 FFmpeg/ffprobe；
- 文件扩展名、客户端 MIME 和客户端解析结果都不能作为唯一依据；
- 空文件、损坏文件、伪造 MP4、超限文件、非 H.264 视频或非 AAC 音频必须拒绝；
- 错误响应不得包含文件内容、原始私密路径、解析堆栈或服务端绝对路径。

### 7.2 封面

- 接受 JPEG、PNG、WebP，单张最大 `10 MiB`；
- 服务端继续验证真实图片格式、尺寸和解码有效性；
- SVG、GIF、视频、空文件、损坏文件和伪造扩展必须拒绝；
- 自动生成封面与用户自定义封面遵守相同服务端规则；
- 封面失败不得留下已经公开的视频对象。

## 8. 上传安全、限流与临时文件

### 8.1 前置门禁

- 认证、法律版本状态、年龄限制、单账号占用和上传频率门禁必须在读取大型媒体请求体前完成；
- 无权限请求不得创建临时文件、媒体对象、笔记或 Redis 上传占用；
- 请求字段和媒体数量设置明确上限，拒绝额外视频、额外封面和异常字段膨胀。

### 8.2 并发和频率

- 同一账号同时只能存在一个活动视频上传；
- 每个账号滚动 `60` 分钟内最多发起 `10` 次视频上传；
- 请求在通过前置门禁并取得上传资格时计入次数；用户取消、格式错误、上传失败和发布失败同样计入；
- Redis 只用于限流和短期上传占用，不缓存视频、媒体内容、搜索结果或权威发布状态；
- 活动连接期间占用自动续期；异常中断后占用必须自动过期，不能永久锁死账号；
- 频率和并发拒绝返回统一、可理解的 `429`/冲突类业务错误，不接收媒体正文。

### 8.3 流式临时存储

- 视频上传不能由 Multer 内存缓冲或等价方式完整放入 Node.js 堆；
- 字节以有界内存流式写入媒体根目录下的私有任务临时区；
- 临时对象不可通过公开媒体 URL 读取；
- 流式写入过程中达到大小上限时立即停止并清理；
- 用户取消、断网、解析失败、数据库失败或任何异常都清理本次未归属文件；
- 服务启动时和定时任务均扫描未归属且停止写入超过 `1` 小时的临时文件并删除；
- 活动文件不得被清理任务误删，清理失败需要安全日志和后续重试；
- 测试必须证明上传实现的内存使用不随完整 `100 MiB` 文件线性缓冲。

## 9. 发布原子性与存储

- 视频与封面验证全部通过后才可以创建公开笔记；
- 视频对象、封面对象、视频元数据和笔记归属以事务或具有补偿清理的等价原子流程提交；
- 数据库失败不得留下公开孤立媒体；媒体最终化失败不得留下可见笔记；
- 同一作者与同一 `clientRequestId` 最终只能有一个笔记；
- 成功响应丢失后的重试返回或恢复已有结果，不创建第二条笔记；
- 媒体根目录继续通过统一存储接口访问，不在业务代码中拼接宿主机绝对路径；
- Docker 后端容器继续把媒体根目录挂载到宿主机目录或 Docker Volume；
- 视频和封面不得写入容器临时层作为唯一副本；
- 磁盘不足、只读目录和存储不可用时安全失败并保留用户表单，不暴露内部路径。

## 10. 信息流与视频聚合页

### 10.1 推荐与频道

- 首页推荐按现有发布时间倒序同时返回 `IMAGE` 和 `VIDEO`；
- 普通频道按现有发布时间倒序同时返回该频道下两种内容；
- 现有游标分页、最短骨架屏时间、错误重试和空状态规则保持；
- 图文卡片不得因新增类型改变顺序、尺寸或互动行为。

### 10.2 `/videos`

- `/videos` 只返回 `VIDEO` 内容，按发布时间倒序和稳定 ID 游标分页；
- 页面采用现有首页主内容与瀑布流，不显示频道筛选栏；
- 页面不做推荐、热度或个性化排序；
- 空状态使用“还没有视频，发布第一条视频吧”等完成态文案，不显示“功能开发中”；
- 未登录用户可浏览；登录用户可通过发布操作进入视频发布模式；
- 加载失败、加载更多失败和重试遵守现有 NoteFeed 语义。

### 10.3 视频卡片

- 继续使用统一笔记卡片结构，封面保持自身宽高比并遵守现有瀑布流；
- 视频卡片显示明确播放图标和 `分:秒` 时长；
- 标题、作者、头像、点赞和浏览量继续使用真实数据；
- 卡片不自动播放，鼠标悬停、聚焦和进入视口也不加载完整视频；
- 点击卡片进入详情；点击点赞不触发详情导航；
- 图文卡片不显示视频时长或播放标识。

## 11. 搜索与个人主页

### 11.1 搜索

- `/search?...&type=video` 从固定空状态改为真实视频查询；
- 匹配字段、关键词规范、AND 语义、中文子串、英文大小写、参数化安全和日志隐私沿用 SPEC-008；
- 排序、稳定游标和分页沿用图文笔记搜索，只额外限定 `VIDEO`；
- 【笔记】Tab 继续只查询 `IMAGE`，不得重复返回视频；
- 视频结果使用统一视频卡片；无结果显示稳定空状态；
- 搜索仍以 PostgreSQL `pg_trgm`/GIN 为唯一来源，不引入 Redis 搜索缓存或独立搜索服务。

### 11.2 当前用户主页

- 【笔记】按发布时间倒序展示当前用户发布的图文和视频；
- 【收藏】和【点赞】展示对应的图文和视频，并保留现有取消互动后的列表移除行为；
- 一行内容和第二行后滚动边界继续满足 SPEC-005；
- 视频卡片与首页保持一致，不在主页自动播放。

### 11.3 他人公开主页

- 他人主页【笔记】展示该用户公开的图文和视频；
- 公开笔记计数包含两种内容；
- 关注、私信和公开资料规则不变；
- 不公开收藏、点赞列表或任何私密媒体信息。

## 12. 视频详情与播放

### 12.1 详情结构

- 继续使用 `/explore/{noteId}` 和现有双栏详情；
- `IMAGE` 笔记左侧继续展示图片媒体；
- `VIDEO` 笔记左侧展示带封面的 HTML 视频播放器；
- 右侧作者、频道、标题、正文、时间、浏览量、关注、评论和底部互动栏保持同一信息结构；
- 详情返回来源、安全回退、查询参数和滚动恢复不得回归。

### 12.2 播放行为

- 默认不自动播放；
- 默认只预加载媒体元数据，不预下载完整文件；
- 点击播放前不得产生声音；
- 使用浏览器原生控制支持播放、暂停、进度、音量和全屏；
- 播放器 `poster` 使用视频封面；
- 视频保持原始宽高比，不拉伸、不遮挡详情返回按钮；
- 播放错误显示“视频加载失败，请重试”，允许重新加载；右侧正文和互动在媒体错误时仍可访问；
- 本期不自定义倍速、画中画或下载按钮；浏览器原生能力不作为额外产品承诺。

### 12.3 浏览量和互动

- 视频详情成功展示后沿用现有 `30` 分钟有效浏览量上报；
- 列表封面曝光、预加载、Range 请求和重复分段请求不单独计数；
- 作者自访问、登录/匿名去重和隐私哈希规则不变；
- 点赞、收藏、关注、评论、回复、评论点赞和通知复用现有事务与幂等语义；
- 视频互动通知使用视频封面预览；
- 不新增独立播放次数、播放完成率或观看时长数据。

## 13. 媒体读取与 HTTP Range

- 公开媒体接口按随机对象 Key 读取已归属视频与封面；
- 视频完整请求返回正确 `Content-Type`、`Content-Length` 和 `Accept-Ranges: bytes`；
- 合法单 Range 请求返回 `206 Partial Content`、准确 `Content-Range` 和对应字节；
- HEAD 返回与 GET 一致的元数据头但不返回正文；
- 无效、越界或不支持的 Range 返回标准安全错误，不能读取相邻对象或服务器其他文件；
- 不允许通过路径穿越、编码变体、原始文件名或绝对路径访问对象；
- 视频流必须按请求区间读取，不能为了返回一个 Range 把完整视频载入内存；
- 封面继续支持缓存和正确 MIME；视频缓存策略不得阻止 Range 和内容更新安全；
- 媒体错误日志不得记录文件内容、Cookie、授权信息或宿主机绝对路径。

## 14. 失败与一致性规则

- 客户端预校验失败时不发起上传；服务端仍必须独立验证；
- 会话失效时打开现有登录流程并保留表单与本地预览，重新登录后可手动重试；
- 条款待确认或年龄受限时使用现有不可绕过门禁，不接收视频字节；
- 频道在选择后停用或改为不可发布时，发布失败并要求重新选择；
- 上传取消、超限、格式错误、解码失败、存储失败、数据库失败和响应中断均不得产生半成品公开笔记；
- 媒体对象不存在或损坏时，详情显示媒体错误但不泄露内部信息；
- 视频搜索、信息流或详情接口发生临时错误时，不伪造视频数据；
- 旧客户端图文发布契约继续可用，不要求新增视频字段。

## 15. 可访问性与视觉规则

- 发布模式选择、文件选择、封面选择、取消、重试和发布可通过键盘操作；
- 进度使用可访问的 `progress` 或等价语义，并提供文本阶段；
- 模式切换确认框具备焦点进入、循环、Escape、关闭后恢复和可理解标题；
- 视频卡片播放标识不能只依赖颜色，并提供“视频”辅助文本；
- 视频播放器具有可识别名称，浏览器原生控制可键盘操作；
- 播放错误、上传错误和校验错误使用适当 live region，避免重复播报；
- `/videos` 当前导航状态、空状态和加载状态对辅助技术可识别；
- 使用小蓝书蓝色品牌和现有组件语言，不复制第三方商标、素材或品牌文案。

## 16. 性能、部署与兼容性

- 桌面 Web 最低支持 `960×600` CSS 视口并连续自适应；低于范围仍保证内容可访问；
- 上传和 Range 服务必须保持有界内存，不随 `100 MiB` 文件完整缓冲；
- 信息流只加载封面和必要元数据，不预取所有视频正文；
- 本地开发和 Docker 部署均使用现有持久化媒体根；
- 后端容器不得要求宿主机安装 FFmpeg；
- Docker/运行配置需要允许 `100 MiB` 视频及少量 multipart 开销，但仍拒绝超限请求；
- Chromium 承担完整主业务回归；MP4 加载、播放、暂停、拖动、Range 和封面在 Chromium、Firefox、WebKit 做关键差异验收；
- 常规 `ci.yml` 保持手动触发、不安装浏览器、不运行 Browser E2E；
- 本期不为视频引入 Redis 缓存、消息队列、后台转码进程或额外基础设施。

## 17. 接口与 OpenAPI

- 保留现有图文发布接口的兼容契约；视频发布可以使用独立受保护端点，以隔离流式限制和媒体字段；
- 视频发布端点公开描述标题、正文、频道、`clientRequestId`、视频、可选自定义封面及错误语义；
- 推荐、频道、当前用户列表、互动列表、公开主页和详情 DTO 增加内容类型及可辨识的媒体联合结构；
- `/videos` 数据接口提供稳定游标；
- 视频搜索端点从固定空页改为真实稳定游标页；
- 媒体接口文档明确完整 GET、HEAD、Range `206` 和错误响应；
- 所有新增或变化接口更新 OpenAPI，并保持未登录公开读取与受保护写入边界。

## 18. 数据迁移与兼容

- 历史笔记全部无损标记为 `IMAGE`；
- 历史图片、频道、点赞、收藏、评论、通知、浏览量和私信引用保持不变；

## 19. 测试与验收策略

### 19.1 自动化分层

- 数据库：空库迁移、历史库升级、类型回填、关系唯一性和索引；
- 后端单元/集成：格式解析、编码/时长/大小、前置门禁、限流、流式大小中止、原子清理、幂等、Range、查询过滤和 DTO；
- 前端组件：模式切换、封面提取降级、进度、取消、错误、卡片、搜索、详情播放器和无障碍；
- Browser E2E：真实小型 MP4 发布、推荐/频道/视频页/搜索/主页/详情/互动、失败恢复与跨浏览器播放；
- 存储探针：取消、损坏、超限、数据库失败、进程遗留和一小时清理，不使用真实用户媒体；
- 回归：现有图文发布、频道、搜索、个人主页、互动、通知、详情返回和滚动模型。

### 19.2 视频夹具

- E2E 使用体积很小、无隐私、无第三方版权风险的 H.264/AAC 或无声 H.264 MP4；
- 必要封面夹具同样无隐私并可纳入 Git；
- 夹具不得包含真实账号、邮箱、设备元数据或地理信息；
- 测试发布产生的视频、封面、临时文件、数据库记录和报告按项目规则清理；
- Playwright 配置和永久 E2E 脚本纳入 Git，运行产物不纳入 Git。

### 19.3 执行范围

- 实施阶段先运行定向测试，再运行静态检查、前后端测试、构建、迁移和相关 Chromium E2E；
- 初次独立验收运行一次完整 Browser E2E；
- Chromium 运行视频主流程，Firefox/WebKit 运行媒体加载、播放、暂停、进度、Range、封面和关键导航差异场景；
- 返工复验按项目分层规则运行历史失败项和受影响回归；
- 常规手动 CI 不运行 Browser E2E，CI 结果不作为 Spec 完成门禁。

## 20. 验收标准

### AC-001：迁移与历史兼容

- 空库和 SPEC-012 历史库迁移成功；
- 全部历史笔记无损变为 `IMAGE`，ID、关系、计数、时间和媒体不变；
- `IMAGE`/`VIDEO` 关系和必要索引正确，不存在伪造历史视频。

### AC-002：入口、权限和前置门禁

- 所有全局【视频】入口进入 `/videos` 并正确表达选中状态；
- 未登录可公开浏览视频，不能上传；
- 未登录、条款待确认、年龄受限和并发占用请求在接收大型正文前被拒绝且不产生临时文件。

### AC-003：发布模式与表单

- 图文/视频模式、切换确认、标题、正文、频道、未保存状态和发布后导航符合规格；
- 视频选择、预览、封面、自定义封面、进度、取消、失败保留和重试可用；
- 初始页面无假滚动，支持范围内连续自适应。

### AC-004：视频与封面验证

- 有效 H.264 MP4、无声视频及 AAC 音频视频可以发布；
- 非 MP4、非 H.264、非 AAC 音频、损坏、伪造、空文件、少于 1 秒、超过 10 分钟或超过 `100 MiB` 均被服务端拒绝；
- 封面格式、大小、损坏和自动提取失败降级正确，错误不泄露内部信息。

### AC-005：流式、安全与临时清理

- 视频不会完整进入 Node.js 内存，Range 也不会完整读取文件；
- 超限在流式写入阶段停止；取消、断网、解析、存储和数据库失败均清理未归属对象；
- 停止写入超过 1 小时的临时文件能在启动检查和定时任务中删除，活动文件不被误删。

### AC-006：限流、并发和幂等

- 每账号同时一个上传，滚动 60 分钟最多 10 次；取消和失败计数；异常占用自动释放；
- Redis 只保存短期限制状态；
- 同一 `clientRequestId` 的并发或超时重试最终只有一条笔记和一组归属媒体。

### AC-007：推荐、频道和视频页

- 推荐与普通频道按现有稳定顺序混合展示图文和视频；
- `/videos` 只展示真实视频，分页、刷新、分享、前进/后退、加载、空、错和重试正确；
- 不产生演示视频，不把视频建立为频道。

### AC-008：卡片与个人主页

- 视频卡片显示封面、时长、播放标识和真实作者/互动数据，且不自动播放；
- 当前用户【笔记】【收藏】【点赞】和他人公开主页按已确认范围展示视频；
- 图文卡片及一行/第二行滚动边界不回归。

### AC-009：详情播放器与媒体协议

- 视频详情使用封面、原生控制、无自动播放、元数据预加载、正确宽高比和可重试错误；
- 完整 GET、HEAD、合法 Range `206`、边界和无效 Range 结果正确；
- 路径穿越和越权对象读取被拒绝，详情返回来源与滚动恢复不回归。

### AC-010：互动、通知与浏览量

- 视频点赞、收藏、关注、评论、回复、评论点赞和通知遵守既有权限、事务、幂等和取消语义；
- 通知使用视频封面且目标定位正确；
- 详情展示沿用现有浏览量规则，列表曝光和 Range 请求不新增计数。

### AC-011：视频搜索

- 【视频】Tab 按 SPEC-008 字段、关键词、排序和稳定游标返回真实 `VIDEO`；
- 【笔记】只返回 `IMAGE`，两类不重复；
- 未登录、登录、无结果、错误、URL 恢复和搜索隐私正确。

### AC-012：失败一致性与兼容

- 各类失败不产生公开半成品、孤立媒体或重复笔记；
- 表单与本地预览按规格保留；
- 存储不可用和磁盘失败安全降级；
- 现有图文发布、读取、搜索、频道、主页和互动保持兼容。

### AC-013：可访问性与自适应

- 模式、确认框、上传、进度、错误、视频导航和播放器可通过键盘和辅助技术使用；
- 最低支持范围内无根假滚动、双重滚动、裁切或固定分辨率依赖；
- 加载、进度、错误和选中状态不只依赖颜色。

### AC-014：部署、存储与 OpenAPI

- 本地和 Docker 持久化媒体目录正确，容器不要求 FFmpeg；
- 上传大小配置容纳 `100 MiB` 加必要开销并拒绝超限；
- OpenAPI 覆盖发布、读取、Range、列表、详情、搜索及错误；
- 源码、日志、测试产物和响应不泄露宿主机路径或用户媒体内容。

### AC-015：跨浏览器媒体行为

- Chromium 完成端到端视频发布和社区闭环；
- Chromium、Firefox、WebKit 均验证 MP4 加载、播放、暂停、进度拖动、Range、封面和关键导航；
- 使用永久、小型、无隐私夹具，运行产物和临时媒体全部清理。

### AC-016：分层回归与 CI 边界

- 数据库、后端、前端、OpenAPI、静态检查、构建和相关 Browser E2E 通过；
- 初次独立验收执行一次完整 Browser E2E，并独立验证流式、清理和 Range；
- 常规 CI 仍为手动触发且不安装浏览器、不运行 Browser E2E；
- 未运行项必须说明分层依据，不得描述为通过。

## 21. 风险与后续事项

- 原始 MP4 不转码，部分合法但非 H.264/AAC 的用户视频会被拒绝；
