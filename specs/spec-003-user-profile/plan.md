# SPEC-003 实施计划

- Spec：`specs/spec-003-user-profile/spec.md`
- Spec 状态：Accepted
- 计划状态：Completed
- 更新日期：2026-07-26

本计划只拆分 `spec.md` 版本 1.0 的已确认范围。实施期间只能由一个实施 Agent 串行完成前端、后端、数据库和 E2E 改动。

## 1. 数据模型与迁移

- 为用户模型增加 10 位数字字符串小蓝书号；
- 为用户模型增加受约束的性别字段，默认“保密”；
- 设计碰撞安全的小蓝书号生成逻辑；
- 为既有用户回填小蓝书号和默认性别；
- 建立非空约束和小蓝书号唯一索引；
- 验证迁移同时适用于空数据库和已有用户数据库；
- 更新新用户注册事务，保证账号与小蓝书号同时创建成功或同时失败。

## 2. 当前用户资料 API

- 增加当前用户资料模块、查询服务和受会话保护的读取接口；
- 只返回昵称、小蓝书号、性别、默认头像展示信息和三项统计；
- 三项未实现业务统计返回真实 `0`；
- 对未登录、会话失效和异常数据使用统一错误结构；
- 补充接口文档和后端自动化测试。

## 3. 前端导航与路由保护

- 将首页登录态个人入口文案从昵称改为“我”；
- 让头像和“我”组成的入口整体导航至 `/profile`；
- 移除首页个人入口原有的退出菜单；
- 增加个人主页路由和会话检查；
- 未登录直接访问或会话失效时返回首页并自动打开登录弹窗；
- 避免保护页面在鉴权完成前闪现资料。

## 4. 个人主页

- 复用现有全局导航和顶部区域；
- 实现资料头部、默认头像、昵称、小蓝书号、性别和三项统计；
- 实现个人主页设置菜单，并迁移现有退出登录能力；
- 实现“笔记”“收藏”“点赞”三个可访问 Tab；
- 实现三个已确认的真实空状态；
- 实现加载骨架、普通错误、重试和会话失效处理；
- 在三个目标桌面宽度下校验布局与品牌视觉。

## 5. 自动化测试

- 覆盖小蓝书号格式、唯一性、碰撞处理和注册集成；
- 覆盖性别默认值、既有用户回填和迁移约束；
- 覆盖资料接口授权、字段最小化、统计和错误响应；
- 覆盖首页“我”入口、个人主页展示、Tab、设置菜单和错误状态；
- 覆盖未登录访问、登录后进入主页、Tab 切换和退出登录 E2E；
- 沿用项目现有 Chromium、Firefox、WebKit 测试配置；
- 运行数据库校验、lint、类型检查、单元/集成测试、E2E 和构建。

## 6. 交付与验收

- 实施 Agent 返回完整改动清单、迁移说明和测试证据；
- 协调开发 Agent 释放实施 Agent；
- 协调开发 Agent 创建新的独立验收 Agent；
- 验收 Agent 依据 `acceptance.md` 和 AC-001 至 AC-013 逐项验收，不修改业务代码；
- 未通过时由新的单一实施 Agent 返工，再由新的独立验收 Agent 复验；
- 独立验收通过后交由用户审查；
- 用户确认验收完成后，将 Spec 状态改为 `Accepted` 并提供中文 Conventional Commit 信息。

## 7. 用户反馈修复

2026-07-26，用户要求在不创建新验收 Agent 的前提下由新的实施 Agent 修复：

- 个人主页空状态下的无意义纵向滚动条；
- 个人主页“发现”菜单错误触发“功能正在开发中”，应导航到首页 `/`。

实施 Agent 必须：

- 查明滚动条的实际布局根因，不得通过全局 `overflow: hidden` 掩盖真实溢出；
- 为三个目标桌面视口增加无无意义纵向滚动条的验证；
- 为个人主页点击“发现”返回首页增加前端或 E2E 回归测试；
- 运行与修改相称的静态检查、测试和构建；
- 不扩大到其他导航或页面重构。

## 8. 首次直达滚动条二次修复

用户实际检查确认“发现”导航已修复，但 `html` 根元素滚动条仍会在第一次直接进入 `/profile` 时出现；从首页再次跳转进入则不出现。

新的实施 Agent 必须：

- 使用全新浏览器页面或上下文复现首次将 `/profile` 作为首个文档加载的场景；
- 分别记录加载阶段和资料完成阶段的 `html`/`body` 尺寸、关键容器盒模型与相关样式，定位首次直达和站内导航不一致的实际原因；
- 独立验证首次直达、硬刷新、从首页点击“我”三条路径；
- 修复 `html` 根元素的无意义纵向溢出，不得全局关闭页面滚动；
- 补充能在修复前稳定失败、修复后通过的回归测试；
- 保留已经修复的“发现”首页导航，并防止回归。

第 2 轮独立验收通过后，用户再次实测发现：首次进入和站内跳转正常，但浏览器刷新时仍会在 `html` 根元素上出现滚动条。用户要求本阶段只诊断，不创建实施 Agent。

完成只读诊断后，用户明确授权协调开发 Agent 直接修复，且本轮不创建实施 Agent 或验收 Agent。直接修复限定于窄视口刷新布局和对应回归测试。

直接修复已完成：

- 为宽度小于 `960px` 的个人主页增加可收缩的资料头部、骨架、统计和 Tab 布局；
- 骨架标题和骨架线不再超过可用内容宽度；
- 未通过隐藏 `html`、`body` 溢出来掩盖问题，长内容仍保持正常滚动；
- 增加 `850×800` 与 `800×700` 两个硬刷新回归场景，同时验证 loading 和 loaded 阶段的根元素宽高；
- lint、typecheck、单元/集成测试、生产构建与完整三浏览器 E2E 均通过，用户实际复查后确认验收完成。
