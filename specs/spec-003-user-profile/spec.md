## 1. 背景

SPEC-002 已建立邮箱注册、登录、会话恢复和退出登录能力。登录后的首页目前仍以用户昵称表示个人入口，项目也没有用于承载用户资料、内容归属和后续社交关系的个人主页。

本 Spec 建立登录用户自己的个人主页，形成从首页个人入口到个人资料展示的基础闭环，并为后续资料编辑、笔记、收藏、点赞、关注和粉丝功能预留稳定的数据与页面结构。

## 2. 已确认目标

- 登录后，首页左侧菜单中的个人入口名称固定显示为“我”；
- 点击“我”进入当前登录用户的个人主页；
- 个人主页展示头像、昵称、小蓝书号和性别；
- 个人主页展示“关注”“粉丝”“获赞与收藏”三项统计；
- 个人主页提供“笔记”“收藏”“点赞”三个 Tab；
- 三个 Tab 可以切换，并在对应业务尚未实现时展示真实空状态；
- 页面信息结构参考小红书 Web 个人主页，视觉使用小蓝书蓝色品牌体系；
- 本期不提供头像、昵称、年龄、性别等个人资料的编辑能力。

## 3. 范围

### 3.1 本期包含

- 登录后首页左侧“我”入口；
- 当前登录用户个人主页路由 `/profile`；
- 当前用户基础资料查询接口；
- 默认头像展示；
- 昵称、小蓝书号和性别展示；
- 三项真实统计值展示；
- “笔记”“收藏”“点赞”Tab 和空状态；
- 未登录访问保护；
- 将现有退出登录入口迁移到个人主页的设置菜单；
- 现有用户的小蓝书号和性别数据迁移；
- 新注册用户的小蓝书号生成和默认性别初始化；
- 与本功能相称的单元、集成、组件和端到端测试。

### 3.2 本期不包含

- 头像上传、裁剪、删除或更换；
- 昵称修改；
- 年龄或出生日期的录入、修改和展示；
- 性别修改；
- 个人简介、地区、职业、学校等扩展资料；
- 公开访问其他用户的个人主页；
- 关注、取消关注、粉丝列表或关注列表；
- 发布、编辑、删除或查看笔记详情；
- 实际收藏或点赞功能；
- 个人资料设置页面；
- 演示用统计数据、虚假内容卡片或可伪装成真实业务数据的占位数据。

## 4. 页面入口与导航

### 4.1 首页登录态

- 用户未登录时，左侧菜单继续显示 SPEC-002 的“登录”按钮；
- 用户登录后，该位置显示用户默认头像和固定文字“我”，不得再以用户昵称替代菜单名称；
- 点击头像或“我”所在的整个个人入口区域，均跳转到 `/profile`；
- `/profile` 为当前用户自己的个人主页，不接收用户 ID 参数；
- 个人主页中的“我”入口保持选中状态，使用小蓝书蓝色选中样式；
- 首页个人入口不再通过点击展开退出登录菜单。

### 4.2 退出登录入口

- 个人主页资料区提供明确可发现的“设置”或更多操作按钮；
- 点击后打开轻量菜单，菜单中提供“退出登录”；
- 本期不创建完整的设置页面，除退出登录外不放置尚未实现的可操作设置项；
- 退出登录沿用 SPEC-002 规则，只结束当前设备的当前会话；
- 退出成功后返回首页并恢复未登录状态；
- 退出失败时保留当前页面和会话显示，并提示用户稍后重试。

## 5. 访问控制

- `/profile` 只允许已登录用户访问；
- 未登录用户直接访问 `/profile` 时，必须跳转回首页并自动打开登录弹窗；
- 登录弹窗沿用 SPEC-002 的邮箱验证码流程；
- 未登录跳转过程中不得短暂展示个人资料；
- 登录成功后关闭弹窗并进入正常登录态；本期不强制自动返回 `/profile`；
- 用户在个人主页停留期间会话失效时，页面必须清除受保护资料，返回首页并自动打开登录弹窗；
- 当前用户资料接口在未登录或会话无效时返回统一的 `401` 错误，不得返回任何用户资料。

## 6. 个人主页信息结构

### 6.1 整体布局

- 页面保留与首页一致的全局左侧导航和顶部区域；
- 主内容区采用小红书 Web 个人主页相同层级的信息结构：用户资料头部、统计信息、内容 Tab、内容区域；
- 只参考信息层级、空间关系和交互结构，不复制小红书商标、文案、图片或其他受保护资源；
- 小蓝书 Logo、主按钮、选中态、焦点态和强调色统一使用现有品牌蓝；
- 桌面端必须在 `1280px`、`1440px` 和 `1920px` 宽度下保持内容可见、无遮挡、无横向滚动；
- 本 Spec 不新增移动端 App 或独立移动端页面要求。

### 6.2 用户资料头部

资料头部按以下顺序展示：

1. 当前用户头像；
2. 当前用户昵称；
3. 文案“小蓝书号：{10 位数字编号}”；
4. 当前用户性别；
5. “关注”“粉丝”“获赞与收藏”三项统计；
6. 设置或更多操作按钮。

展示规则：

- 本期头像沿用当前默认头像规则：以昵称首个可见字符生成圆形文字头像；
- 昵称显示数据库中的当前真实昵称；
- 性别使用中文“男”“女”“保密”展示；
- 新用户和没有设置过性别的既有用户均显示“保密”；
- 不显示邮箱、内部 UUID、会话 ID 或其他敏感/内部字段；
- 页面不得提供任何资料编辑按钮、头像上传入口或可编辑表单。

## 7. 小蓝书号

- 每个用户必须拥有一个小蓝书号；
- 小蓝书号由系统自动生成，用户不能自行填写或修改；
- 小蓝书号由恰好 10 位十进制数字组成；
- 小蓝书号使用字符串存储和传输，允许以 `0` 开头；
- 数据库必须对小蓝书号建立唯一约束；
- 新用户完成注册时必须同时获得小蓝书号；
- SPEC-003 上线前已经存在的用户必须在迁移中获得符合规则的小蓝书号；
- 生成或迁移发生碰撞时必须重试或以其他安全方式保证唯一，不得创建缺失或重复编号的用户；
- 小蓝书号一经生成永久不变；删除账号等未纳入本期的能力不得影响此规则；
- 小蓝书号用于面向用户展示，不替代后端内部 UUID 主键。

## 8. 性别

- 用户数据增加性别字段；
- 可用业务值为“男”“女”“保密”；
- 新注册用户默认值为“保密”；
- 既有用户迁移后的默认值为“保密”；
- 数据库存储应使用受约束的枚举或等价的强约束方式，不能保存任意文本；
- 本期只展示性别，不提供修改入口。

## 9. 统计信息

个人主页展示以下三项独立统计：

| 统计项 | 本期含义 | 本期展示 |
| --- | --- | --- |
| 关注 | 当前用户已关注的用户数量 | `0` |
| 粉丝 | 关注当前用户的用户数量 | `0` |
| 获赞与收藏 | 当前用户发布内容收到的点赞数与收藏数合计 | `0` |

规则：

- 当前业务尚未实现关注、笔记、点赞和收藏，因此三项真实统计均为 `0`；
- 必须展示真实的 `0`，不得生成随机数、演示数或静态非零数据；
- 统计项本期不可点击，不跳转到空白页面或未实现页面；
- 后续功能引入真实数据时，可以在不改变页面字段含义的前提下替换统计来源。

## 10. 内容 Tab

- Tab 顺序固定为“笔记”“收藏”“点赞”；
- 首次进入个人主页默认激活“笔记”；
- 用户点击不同 Tab 后，激活样式和内容区域同步切换；
- 选中态使用小蓝书品牌蓝和清晰的下划线或等价视觉标记；
- 三个 Tab 本期都不请求或展示虚假卡片；
- 各 Tab 空状态文案分别为：
  - 笔记：`还没有发布笔记`
  - 收藏：`还没有收藏内容`
  - 点赞：`还没有点赞内容`
- 空状态可以包含统一的轻量图形，但不得加入会误导用户的“发布”“去收藏”或“去点赞”等未实现操作；
- 刷新页面后可以恢复默认“笔记”Tab，本期不要求将 Tab 状态写入 URL 或浏览器存储。

## 11. 后端接口与数据

### 11.1 数据模型

在现有用户模型上至少补充：

- 唯一、非空、不可变的 10 位数字字符串小蓝书号；
- 非空、默认“保密”的受约束性别字段。

数据库迁移必须：

- 保留所有既有用户、邮箱、昵称和时间字段；
- 为所有既有用户完成小蓝书号回填；
- 为所有既有用户完成默认性别回填；
- 在回填成功后建立非空约束和小蓝书号唯一约束；
- 可以在空数据库和已有用户数据的数据库上安全执行。

### 11.2 当前用户资料接口

后端提供受会话保护的当前用户资料读取能力，返回至少包括：

- 昵称；
- 小蓝书号；
- 性别；
- 默认头像展示所需信息；
- 关注数；
- 粉丝数；
- 获赞与收藏数。

接口规则：

- 只返回当前会话所属用户的资料；
- 不接受客户端提交任意用户 ID 来读取其他用户；
- 不返回邮箱、内部会话信息或不必要的内部字段；
- 统计值必须为非负整数；
- 未登录统一返回 `401`；
- 用户不存在或数据异常时使用项目现有统一错误结构，不泄漏数据库细节。

## 12. 加载、错误与空状态

- 页面首次加载资料时显示稳定的骨架或加载状态，不得造成大幅布局跳动；
- 资料加载失败时显示“个人资料加载失败，请稍后重试”及重试按钮；
- 重试只重新获取必要的当前用户资料，不得刷新或清除有效会话；
- `401` 不使用普通网络错误状态处理，必须执行第 5 节的重新登录流程；
- Tab 的空状态与资料加载失败状态必须视觉和语义可区分；
- 后端错误、数据库错误和内部标识不得原样显示给用户。

## 13. 可访问性与交互

- “我”入口、设置按钮、退出登录和三个 Tab 均可通过键盘操作；
- Tab 使用 `tablist`、`tab`、`tabpanel` 或语义等价实现；
- 当前激活 Tab 必须向辅助技术暴露选中状态；
- Tab 支持方向键移动焦点，并可通过 Enter 或 Space 激活；
- 所有交互元素具有清晰可见的焦点样式；
- 头像具有可理解的无障碍名称，或在邻近昵称已提供等价信息时标记为装饰；
- 文本和背景对比度不得仅依赖低对比浅蓝色；
- 设置菜单打开后可以通过 Escape 关闭，关闭后焦点返回触发按钮。

## 14. 兼容性与回归要求

- 不改变 SPEC-002 的邮箱验证码、注册、登录、会话恢复和 Cookie 安全规则；
- 新用户注册必须在原有成功条件全部满足后同时写入小蓝书号和默认性别；
- 旧用户登录不应因数据迁移而失败；
- 未登录首页仍展示“登录”按钮并能打开原有登录弹窗；
- 首页现有频道、卡片和未实现入口行为不得因个人主页改动而失效；
- 端到端测试沿用项目现有 Chromium、Firefox 和 WebKit 配置；
- 自动化测试不得发送真实邮件，也不得依赖生产服务或外部内容资源。

## 15. 安全与隐私

- 所有资料读取依赖服务端会话验证，不能只依赖前端隐藏；
- 不得通过接口或页面暴露用户邮箱、内部 UUID、Redis 键或 Cookie 值；
- 小蓝书号不是登录凭据、授权凭据或安全令牌；
- 日志不得记录会话 Cookie 或其他认证秘密；
- 数据库迁移和编号回填不得覆盖或重排既有用户身份；
- 页面不加载来自小红书或其他第三方站点的用户内容和媒体资源。

## 16. 延后但已记录的产品方向

以下能力已经讨论，但明确不属于 SPEC-003 的实施与验收范围，必须通过后续 Spec 再次确认完整规则后才能开发：

- 头像上传与更换；
- 昵称、年龄、出生日期和性别编辑；
- 头像候选规则：JPG、PNG、WebP，单文件不超过 5 MB，提供正方形裁剪，使用项目本地持久化媒体目录；
- 真实笔记、收藏、点赞、关注、粉丝数据和交互；
- 对外公开的其他用户主页。

## 17. 验收标准

### AC-001：首页“我”入口

- 已登录时左侧个人入口固定显示“我”和默认头像；
- 点击入口进入 `/profile`；
- 未登录时仍显示“登录”按钮；
- 首页个人入口不再承担退出登录菜单功能。

### AC-002：路由保护

- 已登录用户可以访问 `/profile`；
- 未登录用户直接访问时返回首页并自动打开登录弹窗；
- 跳转过程中不泄露或闪现个人资料；
- 会话在页面中失效时执行相同的重新登录流程。

### AC-003：个人资料展示

- 页面展示默认头像、真实昵称、小蓝书号和性别；
- 页面不展示邮箱、内部 UUID 或会话信息；
- 页面不存在头像、昵称、年龄、出生日期或性别的编辑入口。

### AC-004：小蓝书号

- 新用户注册时获得恰好 10 位、允许前导零的数字小蓝书号；
- 多个用户的小蓝书号满足数据库唯一约束；
- 既有用户迁移后均获得有效小蓝书号；
- 小蓝书号不能通过本期页面或接口修改。

### AC-005：性别默认值

- 新用户默认性别为“保密”；
- 既有用户迁移后性别为“保密”；
- 页面按“男”“女”“保密”中文值展示受约束的数据；
- 本期不存在修改性别的入口。

### AC-006：统计信息

- 页面展示“关注”“粉丝”“获赞与收藏”三项统计；
- 三项值均来自真实业务结果并在本期显示为 `0`；
- 不存在随机或演示非零数字；
- 三项统计本期不可点击。

### AC-007：内容 Tab

- Tab 顺序为“笔记”“收藏”“点赞”，默认激活“笔记”；
- 点击或键盘操作可以正确切换激活状态和内容区域；
- 三个 Tab 分别展示已确认的空状态文案；
- 不展示虚假卡片或未实现操作。

### AC-008：布局与品牌

- 页面具有用户资料头部、统计、Tab 和内容区的既定层级；
- 使用小蓝书 Logo 和品牌蓝，不出现小红书商标或红色品牌替换；
- 在 `1280px`、`1440px`、`1920px` 宽度下无关键内容遮挡、溢出或横向滚动。

### AC-009：退出登录

- 个人主页的设置菜单可以执行退出登录；
- 退出只结束当前设备会话，成功后返回未登录首页；
- 菜单支持键盘操作、Escape 关闭和焦点恢复；
- 退出失败时提供反馈且不伪造成功状态。

### AC-010：接口与安全

- 当前用户资料接口只返回当前会话用户的必要字段；
- 未登录请求返回统一 `401`；
- 客户端不能借此接口读取任意其他用户；
- 页面和日志不暴露认证秘密或非必要内部数据。

### AC-011：加载与错误处理

- 首次请求期间有稳定加载状态；
- 普通请求失败显示已确认错误文案和可用的重试操作；
- `401` 与普通网络错误分别处理；
- 加载失败不显示旧用户或伪造资料。

### AC-012：迁移与回归

- 数据迁移可在空库和含既有用户的数据库上完成；
- 既有账号可以继续登录；
- 新用户注册、登录、会话恢复和退出行为不回归；
- 首页现有主要布局和交互不回归。

### AC-013：自动化验证

- 数据模型、编号生成、迁移、资料接口和访问控制具有后端自动化测试；
- 首页“我”入口、个人主页、Tab、错误状态和退出入口具有前端测试；
- E2E 覆盖登录后进入个人主页、Tab 切换、退出，以及未登录直接访问 `/profile`；
- E2E 沿用 Chromium、Firefox、WebKit，且相关 lint、类型检查、单元/集成测试和构建全部通过。

### AC-014：个人主页空状态与全局导航修正
