# SPEC-007 实施计划

- Spec：`specs/spec-007-social-interactions/spec.md`
- 当前 Spec 状态：Accepted
- 计划状态：Completed
- 负责人：协调开发 Agent
- 实施约束：完整任务只能交给一个新的实施 Agent，不得按前端、后端、数据库或 E2E 并行拆分。

## 1. 实施目标

由一个实施 Agent 串行完成点赞、收藏、评论和关注的数据、API、前端交互、个人主页接入、登录意图恢复、迁移、OpenAPI 与自动化测试，并保持既有认证、发布、频道和自适应布局不回归。

## 2. 前置门禁

- 用户审查并明确确认 `spec.md`；
- Spec 状态更新为 `Confirmed`；
- 不存在未解决的产品、数据或验收决策；
- 实施 Agent 开始前按仓库规则读取 AGENTS、Constitution、当前 Spec、关联决策、工作流和相关代码；
- Node.js 只检查一次；当前符合 Node.js 24 时不得调用 NVM。

## 3. 实施阶段

### 阶段一：数据库与迁移

- 增加点赞、收藏、评论和关注模型；
- 建立外键、组合唯一约束、自关注保护和查询索引；
- 编写无损迁移；
- 验证空库、含既有数据数据库及关系约束。

### 阶段二：后端领域服务

- 建立互动模块或等价清晰职责；
- 实现点赞、收藏和关注的幂等目标状态写入；
- 实现评论发布、游标分页和权限删除；
- 接入真实计数和个人统计；
- 避免无界 N+1；
- 保证公开读取与可选会话边界。

### 阶段三：API 与 OpenAPI

- 增加四类互动接口；
- 扩展卡片、详情和个人主页读取结构；
- 统一认证、校验、权限和安全错误；
- 同步 OpenAPI 描述与示例。

### 阶段四：共享登录意图恢复

- 将现有邮箱登录弹框整理为首页与详情可复用的交互；
- 支持点赞、收藏、关注登录后单次继续；
- 支持评论草稿保留但不自动发送；
- 保持现有注册昵称补充、关闭、焦点和会话行为。

### 阶段五：首页与详情

- 把首页卡片点赞占位改为真实交互；
- 把详情关注、点赞、收藏和评论占位改为真实交互；
- 实现评论输入、长度提示、发送、列表、分页、删除确认和错误恢复；
- 保留分享占位和详情返回、频道、图片轮播。

### 阶段六：个人主页

- 接入真实统计；
- 接入收藏和点赞分页列表；
- 点赞 Tab 支持取消后移除；
- 保持笔记 Tab 与键盘 Tab 交互；
- 处理加载、空、错误、重试和会话失效。

### 阶段七：自适应与可访问性

- 验证 `960×600` 最低范围；
- 保证详情右侧评论区滚动归属；
- 保证个人页第二行内容才形成有效滚动；
- 完成按钮选中态、评论输入、确认对话框和登录弹框的键盘/辅助技术语义。

### 阶段八：自动化与回归

- 数据库迁移和约束测试；
- 后端权限、幂等、并发、计数、游标和可选会话测试；
- 前端卡片、详情、评论、个人 Tab 和登录意图恢复测试；
- 两账号正式 Browser E2E；
- 静态检查、单元/集成测试、构建和相关 Browser E2E。

## 4. 建议实现顺序

1. 数据模型和迁移；
2. 后端互动服务与权限；
3. 读取模型和个人统计；
4. OpenAPI；
5. 共享认证弹框与意图状态；
6. 首页卡片；
7. 详情关注、点赞、收藏；
8. 评论输入、列表和删除；
9. 个人主页收藏、点赞和统计；
10. 自适应、可访问性与自动化回归。

该顺序只用于降低集成风险，不授权拆分为多个并行实施 Agent。

## 5. 测试计划

### 数据与后端

- 空库迁移；
- 含既有用户、笔记和频道的数据迁移；
- 点赞、收藏、关注组合唯一约束；
- 自点赞和自关注拒绝；
- 重复 PUT/DELETE 幂等；
- 评论长度、纯文本、排序、游标和跨笔记游标隔离；
- 评论者、笔记作者和无权限用户删除矩阵；
- 关注、粉丝、获赞与收藏统计；
- 公开读取在无会话、有效会话和过期 Cookie 下的差异；
- 并发操作后的真实关系和非负计数；
- 查询数量与索引检查。

### 前端

- 卡片点赞不触发详情导航；
- 详情点赞、收藏和关注状态；
- 自己笔记的受限状态；
- 评论输入长度、提交中、失败保留、成功插入；
- 评论分页、删除确认和权限；
- 登录后动作继续与评论不自动发送；
- 收藏、点赞 Tab 的排序、空状态和取消移除；
- 统计刷新；
- 键盘、焦点和辅助技术属性；
- 最低视口与连续尺寸下的滚动归属。

### Browser E2E

- 账号 A 发布笔记；
- 账号 B 点赞、收藏、评论并关注账号 A；
- 账号 A 查看收到的统计，删除账号 B 的评论；
- 账号 B 查看收藏、点赞和关注统计并执行取消操作；
- 匿名用户浏览真实数量并分别触发四类登录；
- 登录后点赞、收藏、关注只继续一次，评论草稿保留且不自动发送；
- 首页、频道、详情和个人页数据一致；
- Chromium 完整流；
- Firefox/WebKit 验证详情交互、登录弹框、评论输入/确认和键盘关键路径；
- 完整 Browser E2E 由初次独立验收运行一次。

## 7. 风险控制

- 数据库约束承担重复关系的最终保护；
- 写接口采用目标状态语义，支持登录恢复和安全重试；
- 评论发布不自动重试；
- 可选会话失败不能阻断公开读取；
- 禁止用前端临时计数代替服务端真实数据；
- 查询实现需要避免卡片级 N+1；
- 不修改无关业务和样式；
- 不新增依赖，除非发现无法在现有栈内完成并返回协调 Agent 决策；
- 实施 Agent 遇到 Spec 歧义必须停止相关部分并返回协调 Agent，不得自行决定。
