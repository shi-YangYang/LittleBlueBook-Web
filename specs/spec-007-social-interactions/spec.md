## 1. 背景

笔记详情页当前保留了点赞、收藏、评论和关注控件，但这些控件只显示固定为 `0` 的占位数据并提示“功能正在开发中”。首页卡片只展示不可操作的点赞占位，个人主页的“收藏”“点赞”Tab 和“关注”“粉丝”“获赞与收藏”统计也尚未接入真实业务数据。

本 Spec 建立基于登录用户的四类社交互动数据与完整 Web 交互闭环，使互动结果能够在首页卡片、笔记详情和当前用户个人主页之间保持一致。

## 2. 已确认目标

- 登录用户可以点赞和取消点赞他人的笔记；
- 登录用户可以收藏和取消收藏任意笔记，包括自己的笔记；
- 登录用户可以发表和删除符合权限规则的一级纯文字评论；
- 登录用户可以关注和取消关注其他用户；
- 首页卡片和详情页展示真实互动数量与当前用户状态；
- 个人主页“收藏”“点赞”Tab 展示真实笔记；
- 个人主页三项互动统计展示真实数据；
- 未登录用户仍可公开浏览笔记、评论和数量，互动时进入现有邮箱登录流程；
- 登录后按规则继续登录前的互动意图；
- PostgreSQL 是互动数据唯一真实来源，本期不使用 Redis 缓存。

## 3. 范围

### 3.1 本期包含

- 笔记点赞、取消点赞及点赞数；
- 笔记收藏、取消收藏及收藏数；
- 一级纯文字评论的发布、列表、分页和删除；
- 关注、取消关注及关注/粉丝数量；
- 首页卡片点赞交互；
- 笔记详情的点赞、收藏、评论和关注交互；
- 当前用户个人主页的收藏、点赞列表与真实统计；
- 未登录互动触发登录及登录后意图恢复；
- 数据库迁移、唯一约束、外键、索引与并发一致性；
- OpenAPI、单元、集成、组件和 Browser E2E。

### 3.2 本期不包含

- 评论回复、楼中楼或评论编辑；
- 图片、视频、表情包或富文本评论；
- 评论点赞、置顶、热度排序或精选评论；
- 关注列表、粉丝列表、点赞用户列表或收藏用户列表；
- 他人个人主页；
- 私信、互动通知或通知中心接入；
- 分享功能，分享继续保持不可用占位；
- 内容举报、敏感词系统、审核后台或自动内容审核；
- 推荐算法因点赞、收藏或关注而改变；
- Redis 缓存、消息队列、异步计数或搜索索引；
- 笔记编辑、删除和用户注销流程。

## 4. 核心业务规则

### 4.1 点赞

- 点赞对象仅为笔记，不包含评论点赞；
- 同一用户对同一笔记最多存在一条有效点赞记录；
- 首次操作建立点赞，再次操作取消点赞；
- 用户不能点赞自己的笔记；
- 自己笔记上的点赞控件显示真实数量，但不可执行点赞，并提供可理解的状态说明；
- 点赞和取消点赞均采用幂等的目标状态操作，重复请求不得产生重复记录或错误计数；
- 点赞成功后首页卡片、详情页、个人主页“点赞”Tab和作者收到的统计必须使用同一真实数据；
- 用户在“点赞”Tab 中取消点赞后，该笔记应从当前列表移除；
- 点赞记录的操作时间用于个人主页“点赞”Tab 排序。

### 4.2 收藏

- 收藏对象仅为笔记；
- 同一用户对同一笔记最多存在一条有效收藏记录；
- 首次操作建立收藏，再次操作取消收藏；
- 用户可以收藏自己的笔记；
- 有效的本人收藏也计入该笔记收藏数和“获赞与收藏”统计；
- 收藏和取消收藏均采用幂等的目标状态操作；
- 收藏入口本期只在笔记详情页提供，首页和个人主页卡片不新增收藏按钮；
- 收藏记录的操作时间用于个人主页“收藏”Tab 排序。

### 4.3 评论

- 本期只支持一级纯文字评论；
- 评论正文去除首尾空白后必须为 `1～500` 个字符；
- 评论不解析 HTML 或 Markdown，按纯文本安全展示并保留合理换行；
- 用户可以在任意公开笔记下评论，包括自己的笔记；
- 评论按 `createdAt DESC, id DESC` 稳定倒序展示；
- 每页默认 `20` 条，使用游标分页；
- 评论者可以删除自己的评论；
- 笔记作者可以删除自己笔记下的任何评论；
- 删除操作需要二次确认；
- 删除采用真实删除；成功后评论立即从列表移除并同步评论总数；
- 评论不能编辑、回复、点赞、置顶或附带媒体；
- 笔记作者发表的评论显示“作者”标识；
- 评论展示作者头像、昵称、正文和相对时间，不公开邮箱等私密字段。

### 4.4 关注

- 关注关系方向为“关注者 → 被关注者”；
- 同一对用户最多存在一条有效关注关系；
- 用户不能关注自己；
- 自己笔记的详情页不显示关注按钮；
- 其他作者的详情页根据当前状态显示“关注”或“已关注”；
- 点击“关注”建立关系，点击“已关注”取消关系；
- 关注和取消关注采用幂等的目标状态操作；
- 当前用户个人主页“关注”表示当前用户关注的用户数量；
- “粉丝”表示关注当前用户的用户数量；
- 本期统计仅展示数量，不提供关注列表、粉丝列表或他人主页入口。

### 4.5 获赞与收藏

- “获赞与收藏”是当前用户发布的全部笔记收到的有效点赞数与有效收藏数之和；
- 取消点赞、取消收藏后统计同步减少；
- 删除评论或取消关注不影响该统计；
- 统计值不得来自前端累加、随机数或固定占位。

## 5. 数据模型与迁移

数据库至少新增以下逻辑实体，具体 Prisma 命名可在不改变语义的前提下调整：

### 5.1 笔记点赞

- 用户外键；
- 笔记外键；
- 创建时间；
- 用户与笔记组合唯一约束；
- 支持按笔记统计和按用户操作时间倒序查询的索引。

### 5.2 笔记收藏

- 用户外键；
- 笔记外键；
- 创建时间；
- 用户与笔记组合唯一约束；
- 支持按笔记统计和按用户操作时间倒序查询的索引。

### 5.3 评论

- 唯一标识；
- 笔记外键；
- 作者外键；
- 纯文字正文；
- 创建时间；
- 支持按笔记、创建时间和 ID 稳定倒序分页的组合索引；
- 支持评论作者及删除权限判断的索引或等价查询能力。

### 5.4 用户关注

- 关注者外键；
- 被关注者外键；
- 创建时间；
- 关注者与被关注者组合唯一约束；
- 数据库层阻止关注者与被关注者相同；
- 支持分别统计关注数和粉丝数的索引。

### 5.5 迁移规则

- 空数据库可以安全执行迁移；
- 含既有用户、频道、笔记和图片的数据库可以无损执行迁移；
- 迁移不得改变既有用户、资料、笔记、频道或图片数据；
- 既有笔记的四类互动初始为空，数量自然为 `0`，不生成虚假历史记录；
- 唯一约束和外键必须由数据库实际承载，不能只依赖前端或服务层判断；
- 删除未来可能发生的笔记或用户时，互动关系不得形成孤立记录；具体级联规则需与现有用户、笔记删除限制兼容。

## 6. API 契约

实际路径可以遵循现有 NestJS 模块约定，但必须提供语义等价且写入幂等的接口。

### 6.1 点赞与收藏

- `PUT /notes/:noteId/like`：目标状态为已点赞；
- `DELETE /notes/:noteId/like`：目标状态为未点赞；
- `PUT /notes/:noteId/favorite`：目标状态为已收藏；
- `DELETE /notes/:noteId/favorite`：目标状态为未收藏；
- 写接口要求有效登录会话；
- 响应至少返回最终激活状态和服务端确认的最新数量；
- 重复 `PUT` 或重复 `DELETE` 返回成功的最终状态，不重复增减计数。

### 6.2 评论

- `GET /notes/:noteId/comments`：公开读取评论列表，支持游标和每页数量；
- `POST /notes/:noteId/comments`：登录用户发布评论；
- `DELETE /notes/:noteId/comments/:commentId`：按权限删除评论；
- 列表返回评论 ID、作者公开信息、正文、创建时间、作者标识和下一页游标；
- 发布成功返回完整评论展示数据和服务端确认的评论总数；
- 删除成功返回删除结果和服务端确认的评论总数。

### 6.3 关注

- `PUT /users/:userId/follow`：目标状态为已关注；
- `DELETE /users/:userId/follow`：目标状态为未关注；
- 详情接口为作者提供稳定、公开、不可推导邮箱的用户标识，用于关注操作；
- 响应至少返回最终关注状态；
- 服务端同时校验目标用户存在且不是当前用户。

### 6.4 读取模型

公开推荐、频道信息流和笔记详情继续无需登录，但在存在有效会话时返回当前用户相关状态：

- 卡片：真实点赞数、当前用户是否点赞、当前用户是否为作者或能否点赞；
- 详情：真实点赞数、收藏数、评论数、当前用户是否点赞、是否收藏、是否关注作者及能否关注；
- 未登录或没有有效会话时，公开内容仍正常返回，用户相关状态为未激活；
- 过期或无效 Cookie 不得让公开信息流、详情或评论列表整体变成 `401`；
- 互动接口仍必须对无效会话返回统一的认证错误。

当前用户个人主页新增或扩展：

- 收藏笔记分页接口；
- 点赞笔记分页接口；
- 真实关注、粉丝和获赞与收藏统计；
- 收藏、点赞列表按互动发生时间倒序，而不是按笔记发布时间排序。

### 6.5 错误语义

- 未登录写操作：`401`；
- 没有删除权限：`403`；
- 笔记、评论或目标用户不存在：`404`；
- 给自己点赞或关注自己：稳定的 `4xx` 业务错误；
- 评论为空或超过长度：稳定的 `4xx` 校验错误；
- 服务端错误使用项目统一安全结构，不返回 SQL、堆栈、Cookie 或内部凭据。

## 7. 首页卡片交互

- 首页推荐和频道信息流卡片展示真实点赞数；
- 点赞图标根据当前用户状态展示未点赞或已点赞视觉状态；
- 点击点赞区域不得触发卡片进入详情；
- 未登录点击点赞时打开登录弹框；
- 登录用户点击时立即给出视觉反馈，失败则回滚并显示明确提示；
- 快速重复点击不得产生重复点赞、负数或前后端最终状态不一致；
- 自己的笔记不可点赞，控件不得伪装为可成功操作；
- 键盘用户可以聚焦和操作点赞控件，选中状态不能只依赖颜色表达。

## 8. 笔记详情交互

### 8.1 作者与关注

- 右侧作者区域沿用现有头像、昵称和关注按钮布局；
- 其他作者显示“关注”或“已关注”；
- 自己的笔记不显示关注按钮；
- 关注失败时回滚视觉状态并提示，不能错误改变个人主页统计。

### 8.2 点赞与收藏

- 底部点赞和收藏控件由占位改为真实按钮；
- 数量来自服务端；
- 已点赞和已收藏具有清晰、可访问的选中状态；
- 成功操作后数量与状态立即更新；
- 失败时回滚；
- 分享按钮继续显示并提示“功能正在开发中”。

### 8.3 评论输入

- 点击“说点什么…”进入可输入状态；
- 输入区域提供评论正文、取消和发送操作；
- 显示剩余长度或当前长度，使 `500` 字限制可理解；
- 空内容不能发送；
- 发送期间防止重复提交；
- 成功后把服务端返回的评论插入列表顶部、清空输入并同步总数；
- 失败时保留输入内容并提供重试提示；
- 会话失效时保留输入内容并打开登录弹框，登录成功后恢复输入状态，但不自动发送。

### 8.4 评论列表

- 首次加载显示稳定加载状态；
- 空列表显示“还没有评论”；
- 加载失败显示错误与重试；
- 有评论时展示真实列表，不显示演示评论；
- 加载更多失败时保留已加载评论和当前游标位置；
- 删除按钮只向有权限的当前用户展示；
- 删除前二次确认，取消确认不改变数据；
- 删除成功后从列表移除并同步总数；
- 笔记作者评论显示“作者”标识；
- 长评论和多页评论只使详情右侧既有内容滚动区滚动，不造成页面根元素假滚动或双重滚动。

## 9. 个人主页

### 9.1 统计

- “关注”“粉丝”“获赞与收藏”均改为真实查询值；
- 每次进入或重新验证个人主页时从服务端获取，不依赖上一次页面的本地累加结果；
- 所有统计必须为非负整数。

### 9.2 收藏 Tab

- 展示当前用户收藏的真实笔记；
- 按收藏时间倒序；
- 沿用现有笔记卡片、分页、加载、空状态、错误和重试结构；
- 空状态文案继续为“还没有收藏内容”；
- 卡片不新增收藏按钮，取消收藏需要进入详情操作；
- 从详情取消收藏后再次进入或刷新该 Tab，不再展示对应笔记。

### 9.3 点赞 Tab

- 展示当前用户点赞的真实笔记；
- 按点赞时间倒序；
- 沿用现有笔记卡片、分页、加载、空状态、错误和重试结构；
- 空状态文案继续为“还没有点赞内容”；
- 卡片点赞按钮可直接取消点赞；
- 取消成功后该笔记从当前 Tab 移除。

## 10. 登录与意图恢复

- 未登录用户可以浏览信息流、详情、评论和真实数量；
- 未登录点击点赞、收藏、关注或评论时复用现有邮箱登录/注册弹框，不跳转到独立登录页；
- 点赞、收藏和关注记录为待执行的目标状态；
- 登录成功后自动执行一次待处理的点赞、收藏或关注目标状态；
- 幂等接口保证登录恢复或网络重试不会重复增减；
- 评论输入内容在登录过程中保留；
- 评论登录成功后恢复输入界面，但必须由用户再次点击发送；
- 关闭登录弹框视为取消本次待执行动作，不改变业务数据；
- 登录失败或补充昵称未完成时不执行待处理动作；
- 会话在已登录操作中失效时采用相同恢复规则；
- 不在 URL、localStorage 或日志中保存评论正文、邮箱验证码或 Cookie。

## 11. 一致性、并发与性能

- PostgreSQL 是点赞、收藏、评论和关注的唯一真实来源；
- 本期不读取或写入 Redis 互动缓存；
- 点赞、收藏和关注通过数据库唯一约束防止重复关系；
- 关注自己需要服务层校验和数据库层约束或等价保护；
- 计数由有效关系计算或由事务保证的等价方案产生，不允许只由前端累加；
- 任何计数不得为负数；
- 列表查询不得针对每张卡片产生无界 N+1 查询；
- 首页和频道分页仍保持原有稳定顺序与游标语义，互动不会改变推荐排序；
- 评论、点赞和收藏查询具备与筛选和排序相匹配的索引；
- 同一控件的并发请求需要串行化、合并或忽略过期响应，最终界面必须反映服务端最终状态；
- 不因本 Spec 增加新的运行时依赖。

## 12. 安全与隐私

- 所有写操作必须从服务端会话确定操作者，不接受客户端提交操作者 ID；
- 评论删除权限必须在服务端检查；
- 点赞自己的限制和关注自己的限制必须在服务端检查；
- 评论正文按纯文本处理，防止脚本或 HTML 注入；
- 公开互动数据不得返回邮箱、验证码、Cookie、SMTP 信息或其他私密资料；
- 作者公开标识只能用于业务交互，不被视为授权凭据；
- 游标不可被用于跨笔记或跨个人列表读取错误数据；
- 日志只记录必要的请求和错误标识，不记录评论正文或认证凭据；
- 本期不承诺反垃圾、内容审核和限流能力，后续以单独 Spec 设计。

## 13. 可访问性与自适应布局

- 点赞、收藏和关注按钮向辅助技术暴露名称、数量和选中状态；
- 评论输入具有标签、长度说明、错误关联和发送状态；
- 评论删除确认支持键盘操作、Escape 取消和合理的焦点恢复；
- 登录弹框继续满足既有焦点约束；
- 所有交互可以通过键盘完成，不能只依赖鼠标悬停；
- 最低支持范围继续为宽度 `960 CSS px`、高度 `600 CSS px`；
- 支持范围内不得因空评论、单条评论或打开输入框出现 HTML 根元素假滚动；
- 评论增长时由详情右侧既有内容区承担滚动，底部互动栏保持可达；
- 个人主页收藏和点赞内容从需要第二行或更多内容时才产生符合 SPEC-005 的有效滚动；
- 低于最低范围时内容仍可滚动访问，不得裁切关键操作。

## 14. 状态与错误处理

- 读取失败和写入失败使用用户可理解的中文提示；
- 点赞、收藏和关注可以采用乐观更新，但失败必须回滚；
- 评论发布以服务端成功响应为准，失败保留输入；
- 评论删除以服务端成功响应为准；
- 页面刷新后所有状态从服务端恢复；
- 跨页面返回时不得用旧的占位数覆盖更新后的真实数量；
- 笔记不存在、作者不存在或评论已被其他请求删除时安全收敛到服务端状态；
- 网络恢复后的重试不得制造重复关系或重复评论；
- 评论发布不自动重试，避免用户不知情地产生重复内容。

## 17. 验收标准

### AC-001：数据模型与迁移

- 空库和含既有业务数据的数据库均可安全迁移；
- 点赞、收藏、评论和关注表、外键、唯一约束及索引符合 Spec；
- 既有数据不变，既有笔记互动自然为 `0`；
- 重复关系由数据库约束阻止，关注自己由数据库约束或等价保护阻止。

### AC-002：公开读取与当前用户状态

- 未登录可以读取推荐、频道、详情、评论和真实数量；
- 有效会话下返回当前用户点赞、收藏和关注状态；
- 无效或过期 Cookie 不使公开读取整体失败；
- 公开响应不泄漏邮箱或内部敏感字段。

### AC-003：点赞闭环

- 首页卡片和详情页可以点赞、取消点赞并同步真实数量；
- 同一用户同一笔记不存在重复点赞；
- 用户不能点赞自己的笔记；
- “点赞”Tab 按点赞时间倒序展示真实笔记，取消后移除；
- 页面刷新后状态与数量保持。

### AC-004：收藏闭环

- 详情页可以收藏和取消收藏并同步真实数量；
- 用户可以收藏自己的笔记；
- 同一用户同一笔记不存在重复收藏；
- “收藏”Tab 按收藏时间倒序展示真实笔记；
- 页面刷新后状态与数量保持。

### AC-005：个人统计

- “关注”“粉丝”“获赞与收藏”显示真实非负整数；
- 跨账号点赞、收藏、关注和取消后统计符合定义；
- 本人收藏按 Spec 计入“获赞与收藏”；
- 评论和关注不会错误改变“获赞与收藏”。

### AC-006：评论发布与分页

- 登录用户可以发布 `1～500` 字一级纯文字评论；
- 空内容和超长内容被前后端拒绝；
- 评论按稳定倒序和每页 `20` 条游标分页；
- 成功后列表顶部和评论总数同步，失败时输入保留；
- 作者评论具有“作者”标识，HTML 按纯文本显示。

### AC-007：评论删除权限

- 评论者和笔记作者可以在二次确认后删除允许删除的评论；
- 无权限用户看不到可用删除操作，直接调用接口也返回拒绝；
- 删除成功后列表和数量同步；
- 取消确认或删除失败不错误移除评论。

### AC-008：关注闭环

- 其他作者详情可以关注和取消关注；
- 自己的详情不显示关注按钮，接口也拒绝关注自己；
- 重复关注和取消关注保持幂等；
- 关注和粉丝统计跨账号正确变化；
- 本期不出现关注列表、粉丝列表或他人主页。

### AC-009：未登录与会话恢复

- 四类未登录互动均打开现有邮箱登录弹框；
- 登录成功后点赞、收藏和关注只自动执行一次；
- 评论内容保留但不自动发送；
- 关闭或未完成登录不会产生业务数据；
- 会话中途失效采用相同恢复规则。

### AC-010：一致性、并发与性能

- 并发或快速重复操作不产生重复关系、负数或旧响应覆盖新状态；
- 首页、详情、个人页和刷新后的数据一致；
- 列表查询无无界 N+1，关键查询使用合适索引；
- PostgreSQL 是唯一真实来源，未引入 Redis 互动缓存或新依赖；
- 互动不改变推荐和频道排序。

### AC-011：交互、可访问性与布局

- 点赞、收藏、关注、评论输入和删除确认具备键盘与辅助技术语义；
- 加载、空、失败、重试和提交中状态明确；
- `960×600` 及以上没有空页面假滚动、关键操作裁切或双重滚动；
- 长评论由详情右侧内容区滚动；
- 个人主页收藏和点赞列表遵守既有自适应滚动模型。

### AC-012：回归、自动化与文档

- 迁移、权限、幂等、计数、分页、意图恢复和前端交互有自动化覆盖；
- 两个账号的完整互动闭环具有正式 Browser E2E；
- OpenAPI 与实际接口一致；
- 登录、发布、个人页、详情、频道和自适应布局无回归；
- 格式、Lint、类型、单元/集成测试和构建通过；
- 初次独立验收完成一次完整 Browser E2E。

## 18. 风险与防护

- 互动计数必须来自真实关系或事务一致的等价方案，避免并发计数漂移；
- 可选会话不能破坏公开读取边界；
- 登录后动作恢复必须使用幂等目标状态，避免重复点赞、收藏或关注；
- 评论发布不得自动重试，避免重复内容；
- 个人收藏和点赞列表按互动时间而非笔记时间分页，游标必须匹配排序字段；
- 评论增长不得破坏 SPEC-005 已确认的滚动归属；
- 本期不因 Redis 已存在于工程基础而提前引入缓存一致性复杂度。
