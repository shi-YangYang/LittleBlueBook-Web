## 1. 背景

LittleBlueBook-Web 已完成项目工程基础，但尚无用户身份能力。发布内容、互动和个性化功能都需要可验证、可持续登录的用户账号。

本 Spec 建立 Web 端首期邮箱账号闭环，不扩展到手机号或第三方登录。

## 2. 已确认目标

- 用户可以使用邮箱注册；
- 注册必须完成邮箱验证；
- 注册时需要填写昵称；
- 用户可以使用邮箱和邮箱验证码登录；
- 用户可以退出登录；
- 账号体系完全无密码，不设置登录密码；
- 注册或登录功能不使用独立的公开 URL 页面，而是在首页内通过模态弹窗完成；
- 首页不设置顶部“登录”入口，只在左侧菜单下部设置“登录”按钮并打开登录注册弹窗；
- 注册或登录成功后关闭弹窗并回到首页的已登录状态；
- 首页桌面端整体布局参考小红书 Web 探索页，采用左侧菜单、顶部区域、频道导航和多列瀑布流内容区；
- 小蓝书使用蓝色品牌配色，不使用小红书的红色品牌配色；
- 邮件初期通过网易 163 SMTP 发送；
- 登录成功后通过 HttpOnly Cookie 保持30天会话，并允许多设备同时登录。

## 3. 范围确认状态

影响实施结果的产品范围、账号规则、验证码规则、会话规则、首页布局和主要交互已经确认。当前版本不存在未解决的产品决策，但在用户明确确认整份 Spec 前仍不得进入实施。

## 4. 已确认的账号、验证码与会话规则

- 登录与注册使用同一个邮箱验证码入口，不设置独立的注册页签；
- 用户输入邮箱和验证码后，已有账号直接登录；
- 新邮箱验证成功后进入昵称填写步骤，昵称校验通过后才正式创建账号；
- 未完成验证码验证或昵称填写时，不创建待验证账号；
- 昵称必填，长度为2～20个字符；
- 昵称只允许中文、英文字母、数字和下划线；
- 昵称允许不同用户重复，不承担账号唯一标识作用；
- 登录和注册验证码均为6位数字；
- 验证码有效期为10分钟；
- 同一邮箱在发送验证码60秒后才可再次发送；
- 同一邮箱最多发送5次验证码/小时、10次/天；
- 同一来源 IP 最多发送20次验证码/小时；
- 超过发送限制时拒绝本次请求并提示稍后再试；
- 本 Spec 不引入图形验证码或行为验证码 CAPTCHA；
- 同一验证码连续输入错误5次后立即失效，用户需要重新获取验证码；
- 验证码验证成功前，不向客户端透露邮箱是否已经注册；验证码发送接口统一返回不暴露账号状态的成功提示；
- 登录成功后使用 HttpOnly Cookie 保存登录会话；
- 单次登录会话自登录成功起固定有效30天，不采用滑动续期；
- 允许同一账号在多个设备上同时登录；
- 退出登录只结束当前设备的当前会话，不影响其他设备；
- 会话 Cookie 必须设置 `HttpOnly` 和 `SameSite=Lax`，生产环境必须设置 `Secure`。

## 5. 已确认的数据与安全存储规则

- 邮箱验证码只保存于 Redis，不写入 PostgreSQL；
- Redis 中只保存验证码的安全哈希，不保存可直接读取的验证码明文；
- 新验证码发送成功后，同一邮箱此前尚未使用的验证码立即失效；
- 验证码验证成功后立即删除，不能重复使用；
- 登录会话采用 Redis 服务端会话，不使用浏览器可自行解析的身份令牌作为登录凭证；
- 浏览器 Cookie 只保存安全随机、不可预测的会话 ID；
- Redis 保存会话对应的用户标识和必要会话元数据，并设置30天固定 TTL；
- 退出登录时删除当前会话，其他设备的独立会话不受影响；
- 新邮箱验证码验证成功后，后端在 Redis 创建一次性注册凭证；
- 注册凭证有效期为10分钟，并通过临时 HttpOnly Cookie 与当前浏览器关联；
- 临时注册 Cookie 必须设置 `HttpOnly` 和 `SameSite=Lax`，生产环境必须设置 `Secure`；
- 注册凭证只能用于当前已验证邮箱的一次昵称提交，完成注册后立即失效；
- 用户在注册凭证有效期内关闭并重新打开登录弹窗时，继续显示“完善资料”步骤；
- 注册凭证过期后显示“验证状态已失效，请重新获取验证码”，并返回邮箱验证步骤；
- PostgreSQL 用户记录至少包含：UUID、标准化邮箱、昵称、创建时间、更新时间和最近登录时间；
- 邮箱在校验前去除首尾空格并统一转换为小写；
- 标准化邮箱必须具有数据库唯一约束，同一邮箱只能创建一个账号；
- 用户表不包含密码或密码哈希字段。

## 6. SMTP 配置边界

已确认的 SMTP 基线：

- SMTP 主机：`smtp.163.com`；
- SMTP 端口：`465`；
- 连接安全方式：隐式 TLS；
- SMTP 用户名：用于服务器身份认证的完整邮箱地址，与当前发件邮箱账号相同；
- 发件人显示名称：`小蓝书`；
- 发件邮箱地址：由运行时环境变量提供，不写入版本化 Spec 和示例配置；
- SMTP 授权码：由运行时秘密环境变量提供，不得使用网易邮箱网页登录密码。

验证码邮件规范：

- 邮件标题：`【小蓝书】您的登录验证码`；
- 正文必须清晰显示6位验证码；
- 正文必须说明验证码在10分钟内有效；
- 正文必须提示“如非本人操作，请忽略此邮件”或含义一致的文案；
- 邮件正文不包含验证链接或重置密码链接。

真实 SMTP 授权码、邮箱密码和其他凭据不得写入 Spec、示例文件、日志、测试输出或 Git。示例环境文件只允许提供占位值；自动化测试不得真实发送外部邮件。

用户曾在对话中发送过一项 SMTP 授权码。该值视为已经暴露，必须在网易邮箱后台撤销并重新生成；新授权码不得再次发送到对话中，只能由用户写入本地或部署环境的秘密配置。

## 7. 已确认的首页与登录入口基线

- 用户未登录时可以直接浏览首页；
- 首页不是登录前的跳转中间页，而是登录弹窗的承载页面；
- 首页布局与小红书参考布局保持一致，不额外增加顶部“登录”按钮；
- 左侧纵向菜单下部设置“登录”按钮，点击后打开模态弹窗，不导航到独立登录页面；
- 弹窗承载登录、注册和邮箱验证流程；
- 弹窗右栏采用统一流程：先输入邮箱和验证码；已有账号直接登录，新用户验证后在同一弹窗内继续填写昵称并创建账号；
- 首页使用小蓝书自己的蓝色品牌视觉；
- 小蓝书主品牌蓝固定为 `#1677FF`；
- 首页桌面端的信息架构参考小红书 Web 探索页：左侧菜单、顶部搜索及操作区、横向频道导航、多列瀑布流内容区；
- 顶部保留小红书式搜索框，占位文案为“登录探索更多内容”；
- 顶部右侧显示“创作中心”和“业务合作”，点击后均提示“功能开发中”；
- 本 Spec 同时交付未登录首页的完整视觉外壳；
- 内容卡片不采用另行设计的原创卡片样式，卡片结构、尺寸关系、间距、圆角、封面区域、标题、作者信息、点赞信息和视频标记均按小红书参考页面复刻；
- 首页使用项目本地演示数据填充卡片，包括演示图片、头像、昵称、标题和互动数字；
- 演示内容不得直接复制、下载、抓取或重新托管小红书用户发布的实际图片、头像和文案；
- 演示数据只用于呈现本 Spec 的首页视觉外壳，不建立真实内容业务语义；
- 真实内容接口、分页、点赞操作和内容详情不属于本 Spec，由后续内容 Spec 实现；
- 尚未实现的搜索、频道、菜单和卡片入口被点击时，统一显示“功能开发中”提示，不导航到不存在的页面；
- 左侧菜单从上到下依次为：发现、视频、直播、发布、通知、登录；
- 左侧菜单底部依次为：更多、关于我们；
- 顶部频道从左到右依次为：推荐、数码、汽车、游戏、运动、健身、户外、穿搭、美食、职场、情感、家居、旅行、视频；
- 本 Spec 只验收桌面 Web，最小验收宽度为1280px；
- 视口宽度1280～1439px时内容区显示3列卡片；
- 视口宽度1440～1919px时内容区显示4列卡片；
- 视口宽度达到1920px及以上时内容区显示5列卡片；
- 登录弹窗采用用户最新参考图中的居中大尺寸圆角弹窗、背景遮罩、右上角关闭按钮、双栏及分隔线、圆角表单控件等视觉结构；
- 弹窗中的红色强调色统一替换为小蓝书蓝色；
- 右栏标题为“邮箱登录”；
- 右栏包含邮箱输入框、验证码输入框、“获取验证码”操作和蓝色“登录/注册”主按钮；
- 邮箱输入框占位文案为“输入邮箱”，验证码输入框占位文案为“输入验证码”；
- 右栏底部提示“未注册邮箱验证后将创建账号”；
- 用户必须勾选“我已阅读并同意《用户协议》《隐私政策》”后才能获取验证码；
- 《用户协议》和《隐私政策》在本 Spec 中点击后均提示“功能开发中”，不导航到不存在的页面；
- 保留双栏结构，但不提供扫码登录；左栏用于展示小蓝书 Logo、品牌介绍和蓝色主题插画；
- 左栏品牌文案为“登录后，发现更懂你的内容”；
- 弹窗可通过右上角关闭按钮或键盘 `Esc` 关闭；
- 点击弹窗外的遮罩区域不关闭弹窗；
- 新用户邮箱验证成功后，弹窗右栏标题切换为“完善资料”；
- 完善资料步骤显示占位文案为“设置昵称”的昵称输入框和“完成注册”主按钮；
- 登录成功后，左侧菜单原“登录”按钮替换为蓝色圆形默认头像和用户昵称；
- 默认头像显示昵称的首个字符；
- 点击登录身份区域后显示包含“退出登录”的菜单；
- 刷新页面时自动恢复尚未过期的登录会话；
- 会话过期后静默恢复未登录状态，不自动打开登录弹窗；
- 退出登录成功后恢复侧栏“登录”按钮；
- 小蓝书 Logo 参考用户提供的圆角胶囊字标，使用蓝色背景和白色“小蓝书”文字，并采用原创字形；

“1:1 复刻”指布局结构、空间比例、内容密度和交互层级保持高度一致。小蓝书仍使用自己的品牌名称、蓝色视觉、图标、文案和内容素材，不直接复用小红书的商标、Logo、专有图片或页面内容。

## 8. 已确认的加载、错误与兼容性规则

错误提示文案：

- 邮箱格式错误：`请输入有效的邮箱地址`；
- 未勾选协议：`请先阅读并同意用户协议与隐私政策`；
- 验证码错误：`验证码错误，还可尝试 X 次`，其中 `X` 为真实剩余次数；
- 验证码过期、被新验证码替代或错误次数耗尽：`验证码已失效，请重新获取`；
- 发送频率超限：`操作过于频繁，请稍后再试`；
- SMTP 邮件发送失败：`验证码发送失败，请稍后重试`；
- 网络或服务异常：`网络异常，请稍后重试`；
- 昵称格式错误：`昵称需为2～20个中文、字母、数字或下划线`。

加载和重复提交规则：

- 发送验证码期间禁用发送操作并显示“发送中…”；
- 验证邮箱验证码期间禁用主按钮并显示“验证中…”；
- 完成新用户注册期间禁用主按钮并显示“注册中…”；
- 异步请求未结束时不得重复提交同一操作；
- 验证码发送成功后，重发操作显示60秒倒计时，倒计时结束前不可再次发送。

可访问性与兼容性：

- 登录弹窗必须支持完整键盘操作；
- 弹窗打开后，键盘焦点必须限制在弹窗内部；
- 邮箱、验证码、昵称和协议勾选控件必须具有可访问名称；
- 弹窗关闭后，焦点返回左侧菜单的“登录”按钮；
- 独立验收覆盖 Playwright Chromium、Firefox 和 WebKit；
- 每种浏览器至少在1280px、1440px和1920px桌面视口验证首页布局及登录弹窗核心流程。

## 9. 明确非范围

以下内容不属于本 Spec：

- 手机号注册和短信验证码；
- 微信、QQ、GitHub 等第三方登录；
- 多因素认证；
- 邮箱密码登录；
- 设置或修改登录密码；
- 忘记密码和重置密码；
- 修改登录邮箱；
- 注销账号；
- 用户头像、简介等完整个人资料编辑；
- 管理后台中的用户管理；
- 宽度低于1280px的移动 Web 和窄屏布局。

## 11. 验收标准

### AC-001：首页整体布局与品牌

- 未登录用户访问首页时，不被强制跳转或自动打开登录弹窗；
- 首页包含左侧固定菜单、顶部搜索及操作区、横向频道和瀑布流卡片区；
- 首页不存在顶部登录按钮，左侧菜单下部存在唯一的首页登录入口；
- 页面使用已确认的小蓝书 Logo 和 `#1677FF` 主品牌蓝；
- 1280～1439px显示3列卡片，1440～1919px显示4列卡片，1920px及以上显示5列卡片。

### AC-002：菜单、频道和演示卡片

- 左侧菜单及底部项目、顶部频道的名称和顺序与本 Spec 一致；
- 演示卡片具备封面、标题、作者头像、昵称、点赞图标与数字，并在适用卡片上显示视频标记；
- 卡片的结构、尺寸关系、间距和圆角与归档的小红书首页参考图保持高度一致；
- 卡片使用项目本地演示数据，不包含小红书内容 URL，不复制或重新托管小红书用户的图片、头像或文案；
- 搜索、未实现菜单、频道、卡片、“创作中心”“业务合作”和协议链接被点击时显示“功能开发中”，不导航到不存在的页面。

### AC-003：登录弹窗布局

- 点击侧栏“登录”后在首页内打开模态弹窗，浏览器不导航到独立登录页面；
- 弹窗具有背景遮罩、双栏结构、中央分隔线、右上角关闭按钮和圆角表单控件；
- 左栏显示小蓝书 Logo、文案“登录后，发现更懂你的内容”和蓝色主题插画；
- 右栏显示“邮箱登录”、邮箱输入框、验证码输入框、“获取验证码”、“登录/注册”、协议勾选区和“未注册邮箱验证后将创建账号”。

### AC-004：弹窗关闭与可访问性

- 右上角关闭按钮和键盘 `Esc` 均可关闭弹窗；
- 点击遮罩不会关闭弹窗；
- 弹窗打开后键盘焦点被限制在弹窗内部；
- 邮箱、验证码、昵称和协议勾选控件具有可访问名称；
- 从侧栏登录按钮打开并关闭弹窗后，焦点返回该按钮。

### AC-005：获取验证码与协议门禁

- 未勾选协议时不能发送验证码，并显示约定错误文案；
- 非法邮箱不能发送验证码，并显示约定错误文案；
- 合法请求进入“发送中…”状态且不能重复提交；
- SMTP 发送成功后显示统一的成功反馈和60秒重发倒计时；
- 验证成功前，客户端响应不透露邮箱是否已经注册；
- 邮件标题、6位验证码、10分钟有效期和非本人操作提示符合本 Spec。
- 用户在本地环境配置轮换后的有效 SMTP 授权码时，人工冒烟验证可以收到一封真实验证码邮件，且验证过程不记录凭据或验证码。

### AC-006：验证码安全、生命周期和限流

- 验证码为6位数字，在 Redis 中以安全哈希保存，不写入 PostgreSQL；
- 验证码10分钟后失效，发送新验证码后旧验证码立即失效；
- 同一验证码连续错误5次后失效，错误时显示真实剩余次数；
- 验证成功后验证码立即删除，不能再次使用；
- 同一邮箱遵守60秒冷却、每小时5次和每天10次限制；
- 同一来源 IP 遵守每小时20次限制；
- 超限请求显示约定错误文案，系统不出现 CAPTCHA。

### AC-007：已有账号登录

- 标准化邮箱已存在时，正确验证码直接创建新的服务端会话；
- 浏览器只接收安全随机会话 ID，不接收包含可解析用户身份的客户端令牌；
- 会话 Cookie 设置 `HttpOnly`、`SameSite=Lax`，生产环境设置 `Secure`；
- Redis 会话固定有效30天，不滑动续期；
- 登录成功后弹窗关闭，首页立即显示已登录侧栏状态。

### AC-008：新账号注册

- 标准化邮箱不存在时，正确验证码不会立即创建用户，而是创建10分钟一次性 Redis 注册凭证和临时 HttpOnly Cookie；
- 有效期内关闭并重新打开弹窗时恢复“完善资料”步骤；
- 注册凭证过期后显示约定错误文案，并返回邮箱验证步骤；
- 昵称不符合规则时不创建用户并显示约定错误文案；
- 合法昵称提交时只创建一个用户、消费注册凭证、创建30天会话并进入首页已登录状态；
- 并发注册同一标准化邮箱时，数据库唯一约束保证最多创建一个账号。

### AC-009：用户数据规则

- 邮箱在使用和保存前去除首尾空格并转换为小写；
- 用户使用 UUID 标识，标准化邮箱具有唯一约束；
- 用户记录包含昵称、创建时间、更新时间和最近登录时间；
- 用户数据模型不包含密码或密码哈希；
- 昵称必填、长度2～20个字符，只允许中文、英文字母、数字和下划线，并允许不同账号昵称重复。

### AC-010：登录状态恢复与退出

- 登录后侧栏显示蓝色圆形默认头像和昵称，头像内容为昵称首字符；
- 点击身份区域可以看到“退出登录”；
- 刷新首页后有效会话能够自动恢复；
- 同一账号可以在多个设备或独立浏览器会话中同时登录；
- 退出登录只删除当前会话，其他设备保持登录；
- 会话过期后页面静默恢复未登录状态，不自动弹出登录框。

### AC-011：加载与错误状态

- 发送、验证和注册请求期间分别显示“发送中…”“验证中…”“注册中…”，对应操作不可重复提交；
- 邮箱、协议、验证码、频率、SMTP、网络服务和昵称错误使用本 Spec 规定的文案；
- SMTP 发送失败时不留下可用验证码；
- 可恢复错误不会造成页面崩溃、错误导航或重复创建账号。

### AC-012：配置与敏感信息

- SMTP、验证码哈希和会话相关秘密只通过运行时环境变量提供；
- `.env.example` 只包含占位值，不包含真实邮箱、授权码、验证码、会话 ID 或其他秘密；
- 应用日志、测试输出和 API 响应不暴露 SMTP 授权码、验证码明文、验证码哈希或会话 ID；
- 自动化测试使用模拟邮件发送，不向真实外部邮箱发送邮件。

### AC-013：浏览器与本地质量检查

- Playwright Chromium、Firefox 和 WebKit 均通过登录弹窗核心流程；
- 1280px、1440px和1920px视口下的列数、侧栏、顶部区域和弹窗没有遮挡、溢出或关键内容不可见；
- 前端与后端相关单元、集成和端到端测试通过；
- 项目 lint、类型检查和构建通过；
- CI 不作为本 Spec 验收项，验收结果以本地独立验收为准。
