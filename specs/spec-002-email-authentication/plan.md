# SPEC-002 实施计划

- Spec：`specs/spec-002-email-authentication/spec.md`
- Spec 状态：Accepted
- 计划状态：Completed
- 更新日期：2026-07-24

本计划只拆分 `spec.md` 版本1.0的已确认实现范围，不扩大产品需求。第 4 轮独立验收已完成全部代码、Node.js 24、三浏览器九项目和真实 SMTP 检查；用户已确认实际收信及邮件内容正确，并于 2026-07-24 确认整个 SPEC-002 验收完成。

## 1. 后端认证基础

- 新增认证模块、邮件发送抽象、验证码服务、注册凭证服务和会话服务；
- 增加 SMTP、验证码哈希秘密、Cookie 和代理来源识别所需的环境配置校验；
- 通过依赖注入隔离真实 SMTP 与测试邮件发送器；
- 为跨端口本地开发启用带凭据的 CORS，并保持生产来源白名单。

## 2. 数据库与 Redis

- 在 Prisma Schema 中新增无密码用户模型和必要索引；
- 创建并验证 PostgreSQL 迁移，确保标准化邮箱唯一；
- 在 Redis 中实现验证码哈希、错误次数、冷却和小时/日限流；
- 实现10分钟一次性注册凭证；
- 实现30天固定 TTL 的服务端会话；
- 使用明确的 Key 命名和 TTL，避免验证码、注册凭证和会话相互覆盖。

## 3. REST API

计划提供以下 `api/v1` 能力，具体 DTO 命名可遵循现有 NestJS 约定：

- 请求邮箱验证码；
- 验证邮箱验证码；
- 完成新用户昵称注册；
- 获取当前登录会话；
- 退出当前会话。

接口必须：

- 使用 DTO 校验邮箱、验证码、昵称和协议确认状态；
- 统一验证码发送响应，不在验证前泄露账号是否存在；
- 对已有用户建立登录会话，对新邮箱建立一次性注册凭证；
- 正确设置、轮换和清除临时注册 Cookie 与登录会话 Cookie；
- 返回稳定、可测试且不包含秘密信息的错误结构；
- 在 Swagger 中生成非生产环境 API 文档。

## 4. 邮件发送

- 通过网易 163 SMTP 端口465和隐式 TLS 发送验证码邮件；
- 使用运行时环境变量读取发件邮箱、SMTP 用户名、显示名称和授权码；
- 生成符合 Spec 文案的验证码邮件；
- SMTP 失败时不留下可验证的 Redis 验证码；
- 自动化测试只使用模拟邮件发送器；
- 在用户本地配置轮换后的有效授权码时执行一次人工 SMTP 冒烟验证，不记录授权码或验证码。

## 5. 首页视觉外壳

- 使用确认的 Logo 稿制作适合网页使用的优化资产；
- 实现固定左侧菜单、顶部搜索及操作区、频道栏和3/4/5列瀑布流；
- 使用项目本地演示数据和本地素材呈现卡片；
- 卡片视觉严格对照归档参考图，不引入新的卡片设计语言；
- 为未实现入口提供统一“功能开发中”反馈；
- 不实现真实内容接口、分页、点赞或详情页。

## 6. 登录注册弹窗

- 实现双栏弹窗、左栏品牌展示、协议门禁和邮箱验证码表单；
- 实现发送、倒计时、验证、完善资料、注册和错误状态；
- 实现关闭按钮、`Esc`、遮罩不关闭、焦点限制与焦点恢复；
- 有效注册凭证重新打开时恢复完善资料步骤；
- 登录或注册成功后关闭弹窗并更新首页身份状态。

## 7. 登录状态与退出

- 页面初始化时读取当前会话；
- 有效会话显示昵称首字符头像和昵称；
- 身份区域提供退出当前设备入口；
- 会话失效时静默恢复访客状态；
- 多个独立浏览器上下文之间的会话互不影响。

## 9. 主要风险与控制

- SMTP 凭据或网络不可用：自动化使用模拟发送器，真实发送单独冒烟验证；
- Redis 数据丢失：验证码和注册凭证允许失效重试，会话失效时安全回到访客状态；现有 Compose 已启用 AOF；
- 代理 IP 识别错误：只信任明确配置的生产代理，避免伪造来源绕过限流；
- 同邮箱并发注册：依赖数据库唯一约束并返回稳定结果；
- Cookie 跨源配置错误：前后端请求、CORS 和 Cookie 属性进行集成测试；
- 视觉复刻偏差：使用归档截图在三个验收视口进行独立对照；
- 第三方内容风险：演示资产保持本地、原创或具有明确可用授权，不引用小红书内容地址。
