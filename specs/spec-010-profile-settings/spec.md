## 1. 背景

SPEC-003 已建立当前用户个人主页、他人公开主页、小蓝书号和默认性别，但当时明确不包含完整个人资料设置。当前“设置”菜单只有退出登录；用户头像仍由昵称首字生成，后端也没有出生日期、年龄公开状态、个人简介或自定义头像字段。

本 Spec 建立登录用户的个人资料设置页面，使用户可以安全修改头像、昵称、性别、出生日期公开状态和个人简介，并让最新公开资料在个人主页、历史内容、互动通知和搜索结果中一致展示。

## 2. 目标

- 在个人主页设置菜单增加可发现的“编辑资料”入口；
- 建立仅本人可访问的 `/settings/profile` 页面；
- 支持头像上传、裁剪、更换和删除；
- 支持昵称、性别、出生日期、公开年龄和个人简介编辑；
- 只保存出生日期，由服务端计算年龄；
- 保持小蓝书号和登录邮箱不可修改；
- 一次保存作为一个整体操作，避免部分字段成功、部分字段失败；
- 使用资料版本避免多窗口静默覆盖；
- 让最新头像和昵称在现有公开内容中统一生效；
- 遵守现有媒体存储、自适应布局、隐私、安全和可访问性基线。

## 3. 范围

### 3.1 包含

- 个人主页设置菜单中的“编辑资料”；
- `/settings/profile` 私有设置页；
- 当前完整资料读取；
- 昵称修改；
- 性别修改；
- 出生日期设置、清空和年龄计算；
- 年龄公开开关；
- 个人简介设置和清空；
- 自定义头像选择、预览、裁剪、缩放、上传、更换和删除；
- 未保存修改确认；
- 统一保存、错误保留、重复提交保护和版本冲突；
- 当前个人主页和他人公开主页资料展示；
- 笔记、评论、通知和搜索结果中的最新头像、昵称传播；
- 数据迁移、媒体生命周期、OpenAPI、自动化测试和 Browser E2E。

### 3.2 不包含

- 修改小蓝书号；
- 修改登录邮箱或重新绑定邮箱；
- 修改登录方式、注销账号或密码；
- 资料修改历史或版本浏览；
- 管理员审核、头像内容审核或昵称审核后台；
- 修改频率限制；
- 用户级资料可见范围列表；
- 性别单独的公开开关；
- 个人简介单独的公开开关；
- 昵称唯一约束；
- App 端；
- Redis 资料缓存、CDN 或新的对象存储服务。

## 4. 页面入口与认证

- 个人主页“设置”菜单增加“编辑资料”菜单项；
- 菜单保留现有“退出登录”；
- 点击“编辑资料”进入 `/settings/profile`；
- 设置菜单仍支持 Escape 关闭和焦点恢复；
- `/settings/profile` 只允许有效登录用户访问；
- 未登录点击入口时打开现有邮箱登录弹框；
- 未登录直接访问 `/settings/profile` 时进入现有登录流程；
- 登录成功后自动返回 `/settings/profile`；
- 登录取消、失败或会话失效时不得渲染私有邮箱和出生日期；
- 登录意图不得在 URL、localStorage 或日志中保存验证码、Cookie 等凭据。

## 5. 字段与业务规则

### 5.1 昵称

- 昵称必填；
- 去除首尾空白后必须符合现有规则；
- 长度为 `2～20` 个字符；
- 允许中文、英文字母、数字和下划线；
- 不允许空格、HTML、Emoji 或其他符号；
- 昵称不要求唯一；
- 不同用户可以使用相同昵称，小蓝书号继续作为面向用户的区分标识；
- 本期不限制修改频率。

### 5.2 性别

- 选项固定为“男”“女”“保密”；
- 数据库存储继续使用 `MALE`、`FEMALE`、`PRIVATE` 或等价受控枚举；
- 现有用户保持原值；
- 性别没有独立公开开关；
- 选择“保密”时，公开页面显示“保密”，不推断其他值。

### 5.3 出生日期与年龄

- 不直接保存可过期的年龄数字；
- 保存完整出生日期；
- 出生日期可选并可清空；
- 不能晚于服务端当前日期；
- 由服务端按公历完整生日计算当前年龄；
- 计算结果必须位于 `0～120` 岁；
- 超出范围、无效日期、闰日错误或客户端伪造均返回稳定校验错误；
- 本期不把年龄作为注册或使用产品的门槛；
- 数据库和私有设置接口保存完整出生日期；
- 公开接口永不返回完整出生日期。

### 5.4 年龄公开

- `showAge` 默认值为 `false`；
- 只有存在有效出生日期时，用户才能开启“公开年龄”；
- 清空出生日期时必须同时把 `showAge` 设为 `false`；
- `showAge=false` 时，当前个人主页和他人公开主页均不展示年龄；
- `showAge=true` 时，公开页面只展示服务端计算后的整数年龄；
- 公开年龄会随日期自然变化，不需要每年更新数据库；
- 客户端提交的年龄数字不被信任或保存。

### 5.5 个人简介

- 个人简介可选并可清空；
- 去除无意义的首尾空白后最多 `100` 个字符；
- 按纯文本处理；
- 不解析 HTML、Markdown、链接、话题或 `@`；
- 允许合理换行；
- 空简介在公开页面不显示占位段落；
- 本期没有独立的简介隐私开关。

### 5.6 小蓝书号和邮箱

- 设置页展示当前小蓝书号；
- 设置页展示当前登录邮箱；
- 两者均为只读；
- 小蓝书号保持永久唯一和不可修改；
- 邮箱继续只作为当前登录身份，不通过本期接口修改；
- 公开页面和公开 API 不返回邮箱；
- 完整邮箱只在本人设置页展示。

## 6. 头像规则

### 6.1 默认头像

- 没有自定义头像时继续使用昵称首字符默认头像；
- 修改昵称后默认头像字符同步变化；
- 中文、英文或数字均取 Unicode 字符序列的第一个字符；
- 无法取得有效字符时使用“蓝”；
- 删除自定义头像后恢复当前昵称首字符头像。

### 6.2 输入文件

- 支持 JPEG、PNG 和 WebP；
- 不支持 GIF、动图、SVG、HEIC 或其他格式；
- 原始选择文件最大 `5 MiB`；
- 客户端检查只用于即时反馈，服务端必须重新验证；
- 服务端根据实际解码结果和魔数判断格式，不能只信任扩展名或 `Content-Type`；
- 损坏文件、解码炸弹、超大像素、动画帧或格式伪装必须拒绝；
- 原始图片和可选择裁剪区域必须至少为 `512×512`；
- 低于最低尺寸时提示用户重新选择，不允许强行放大。

### 6.3 裁剪与输出

- 选择图片后打开头像裁剪对话框；
- 裁剪区域固定为 `1:1`；
- 支持拖动和缩放；
- 不允许裁剪区域超出原图；
- 用户确认裁剪后生成 `512×512` 预览；
- 服务端再次按已确认裁剪结果生成统一 `512×512 WebP`；
- 服务端移除 EXIF、定位、设备信息、颜色配置中的非必要元数据；
- 透明区域使用安全、稳定的中性浅色背景合成，不保留可造成不同页面显示差异的透明底；
- 输出质量在清晰度和体积之间使用固定、可测试的工程参数；
- 客户端生成结果不替代服务端处理。

### 6.4 存储与缓存

- 头像复用现有 `MediaStorage` 抽象和本地持久化目录；
- 用户表只保存头像对象 Key 或稳定引用，不保存图片二进制；
- 对象 Key 不包含用户邮箱、昵称、原始文件名或磁盘绝对路径；
- 新头像使用新的不可预测对象 Key；
- 公开头像 URL 通过既有媒体访问能力生成；
- 新对象 Key 本身承担缓存版本标识，保存后不得继续显示旧头像；
- 业务代码不得绑定本地绝对路径，未来仍可迁移至 S3 兼容存储和 CDN。

### 6.5 更换、删除和清理

- 头像操作状态固定为“保持”“替换”“删除”；
- 替换成功后旧头像不再被用户资料引用；
- 删除成功后用户资料引用为空并恢复默认头像；
- 任何验证、处理、版本冲突或数据库失败路径必须清理本次新建的暂存文件；
- 旧头像删除失败不得被静默遗忘，需要保留可重试的清理记录或等价可追踪机制；
- 清理失败不得让公开资料指向不存在或未确认的文件；
- 自动化测试必须使用可控存储失败验证补偿和清理路径；
- 不删除笔记图片或其他用户头像。

## 7. 页面设计

### 7.1 整体布局

- 页面沿用小蓝书现有左侧导航和顶部区域；
- 左侧“我”保持当前登录入口语义；
- 主区域使用清晰的纵向资料编辑表单；
- 页面标题为“编辑资料”或等价明确文案；
- 提供返回个人主页的入口；
- 不创建与现有产品不一致的管理后台式布局。

### 7.2 表单内容

按合理信息层级展示：

1. 头像和“更换头像”“删除头像”操作；
2. 昵称；
3. 小蓝书号，只读；
4. 登录邮箱，只读；
5. 性别；
6. 出生日期；
7. “公开年龄”开关；
8. 个人简介和剩余字符提示；
9. “取消”和“保存”操作。

### 7.3 加载、保存和错误

- 首次加载至少稳定展示约 `300ms` 骨架；
- 实际请求超过 `300ms` 时继续加载；
- 加载失败显示明确错误和重试；
- 保存按钮只在资料加载成功后可用；
- 保存期间禁用重复提交；
- 保存成功后返回当前用户个人主页，并展示最新资料；
- 保存成功后清除未保存状态，不得触发离开确认；
- 保存失败时保留用户尚未保存的表单内容和头像裁剪预览；
- 字段错误应关联到具体输入；
- 全局错误不得覆盖或清空合法输入；
- 会话过期时不得把当前私有资料泄露给后续用户。

### 7.4 取消和未保存确认

- 没有未保存修改时，取消直接返回个人主页；
- 存在未保存修改时，取消、内部导航、浏览器后退、刷新或关闭页面均需要二次确认；
- 确认放弃后回到目标页面或继续原浏览器动作；
- 取消放弃后保持当前表单；
- 浏览器刷新和关闭使用平台标准离开确认；
- 应用内部导航使用可访问的确认对话框；
- 保存成功后不再触发未保存确认。

## 8. 统一保存和并发

### 8.1 整体保存

- 一次点击“保存”提交当前全部可编辑字段和头像操作；
- 所有字段必须先完整校验；
- 头像替换必须先完成安全解码和标准化；
- 任意字段校验或头像处理失败时，本次数据库资料修改均不生效；
- 数据库写入失败时所有字段保持原值；
- 新头像暂存文件在失败时清理；
- 不允许出现昵称已更新但头像、简介或生日仍失败的部分成功；
- 成功响应必须返回服务端最终资料和新资料版本。

### 8.2 资料版本

- 私有设置读取返回不透明 `profileVersion`；
- 保存时必须回传该版本；
- 服务端以版本执行条件更新；
- 其他窗口已保存较新资料时返回 `409 PROFILE_VERSION_CONFLICT`；
- 冲突时本次所有修改不生效；
- 页面提示“资料已在其他窗口更新，请重新加载后再编辑”；
- 用户重新加载后才可基于最新资料继续修改；
- 不允许静默使用最后写入覆盖其他窗口的新资料。

### 8.3 文件与数据库补偿

- 文件系统和 PostgreSQL 之间使用明确的暂存、提交和补偿顺序；
- 新文件在数据库未确认引用前不得作为正式头像暴露；
- 版本冲突或事务失败后必须删除新文件；
- 旧文件只有在新资料引用确认后才可进入清理；
- 无法即时删除的旧文件必须进入可追踪待清理状态并在后续安全时机重试；
- 任何补偿失败都必须记录不含敏感路径的稳定错误标识；
- 本期不要求引入消息队列，但不能用“最佳努力且无记录”掩盖孤立文件。

## 9. 数据模型与迁移

用户模型新增或等价承载：

- `birthDate`：可空日期；
- `showAge`：布尔，默认 `false`；
- `bio`：可空、最大 `100` 字符；
- `avatarObjectKey`：可空头像对象 Key；
- 资料版本：可复用可靠的 `updatedAt` 条件版本或增加独立版本字段。

迁移要求：

- 空库可以成功部署；
- 已有用户迁移后 `birthDate=null`；
- 已有用户迁移后 `showAge=false`；
- 已有用户迁移后 `bio=null`；
- 已有用户迁移后 `avatarObjectKey=null`，继续显示默认头像；
- 不改动已有邮箱、昵称、小蓝书号、性别、笔记和互动数据；
- 对头像对象 Key 建立必要约束或索引；
- 如采用持久化待清理记录，需要具备对象 Key、状态、重试时间和必要索引；
- 迁移不得扫描或复制现有笔记图片为头像。

## 10. API

### 10.1 私有设置读取

建议接口：`GET /profile/me/settings`

返回至少包含：

- 当前头像；
- 昵称；
- 小蓝书号；
- 登录邮箱；
- 性别；
- 完整出生日期；
- `showAge`；
- 个人简介；
- 不透明 `profileVersion`。

要求：

- 必须登录；
- 不返回其他用户资料；
- 返回值不包含内部对象 Key或磁盘路径；
- 出生日期使用明确、无时区漂移的 `YYYY-MM-DD`。

### 10.2 统一保存

建议接口：`PATCH /profile/me/settings`

- 使用能够同时提交结构化字段和可选头像文件的受控请求格式；
- 请求包含昵称、性别、出生日期或空值、`showAge`、简介、头像操作和 `profileVersion`；
- 替换头像时只接受一张裁剪后图片；
- 保持或删除头像时不得附带无意义文件；
- 返回更新后的私有设置、公开资料和新版本；
- 必须登录；
- 使用现有统一 API 包装和 OpenAPI 文档。

### 10.3 公开资料响应

当前个人主页、公开主页、笔记、评论、通知和搜索相关响应需要使用统一头像映射：

- 默认头像：`type=initial` 与当前昵称首字符；
- 自定义头像：`type=image` 与公开媒体 URL；
- 不公开对象 Key、文件路径或原始文件名。

公开个人资料额外包含：

- 性别；
- 公开年龄或 `null`；
- 非空个人简介；
- 不包含完整出生日期和邮箱。

### 10.4 错误语义

至少提供稳定错误：

- `401 AUTHENTICATION_REQUIRED`；
- `400 PROFILE_VALIDATION_FAILED` 或字段级等价错误；
- `400 AVATAR_INVALID`；
- `413 AVATAR_TOO_LARGE`；
- `409 PROFILE_VERSION_CONFLICT`；
- `500 PROFILE_SAVE_FAILED` 或安全等价错误。

错误不得泄露：

- PostgreSQL、Prisma 或 Sharp 堆栈；
- Cookie、邮箱验证码；
- 媒体根目录、磁盘路径或内部对象 Key；
- 其他用户资料。

## 11. 最新资料传播

### 11.1 当前和公开主页

- 当前个人主页展示最新头像、昵称、性别、公开年龄和简介；
- 他人公开主页展示相同公开字段；
- `showAge=false` 或没有出生日期时不展示年龄；
- 空简介不展示空白占位；
- 设置页保存成功后返回个人主页可看到新资料。

### 11.2 历史内容与互动

- 用户过去发布的笔记展示最新头像和昵称；
- 用户过去发表的评论展示最新头像和昵称；
- 既有通知中的发起者展示最新头像和昵称；
- 搜索用户卡片展示最新头像和昵称；
- 搜索结果中的笔记作者展示最新头像和昵称；
- 不为历史笔记、评论或通知复制旧昵称、旧头像快照；
- 更新资料不改变内容创建时间、互动时间、通知时间或排序。

### 11.3 页面外壳和会话

- 登录后的左侧“我”入口展示最新头像；
- 首页、个人页、通知页、搜索页和公开主页不得继续显示旧昵称首字；
- 如果当前会话摘要包含昵称，需要在保存成功后刷新或同步；
- 不要求用户退出后重新登录才能看到新资料；
- 不使用 Redis 缓存资料。

## 12. 安全与隐私

- 服务端从会话确定被修改用户，不接受客户端用户 ID；
- 邮箱、小蓝书号和内部对象 Key不能通过更新 DTO 修改；
- 完整出生日期仅在本人私有设置接口返回；
- 公开接口只返回经过隐私开关计算的年龄；
- 年龄计算使用服务端日期；
- 昵称和简介按纯文本输出，防止 HTML/脚本注入；
- 头像必须安全解码和重新编码，不原样公开用户上传文件；
- 移除图片元数据；
- 防止路径穿越、对象 Key 枚举和任意文件删除；
- 删除头像时必须验证对象属于当前用户；
- 日志不记录完整出生日期、邮箱、简介正文、头像二进制或本地路径；
- 上传大小、像素和并发受限，避免内存和解码攻击。

## 13. 自适应与可访问性

- 遵守 SPEC-005；
- 桌面最低支持宽度 `960 CSS px`、高度 `600 CSS px`；
- 页面连续自适应，不枚举固定分辨率组合；
- 空表单、加载和保存状态不得制造 HTML 根元素假滚动；
- 表单超出视口时由正常页面主内容滚动；
- 裁剪对话框内部内容可访问且不形成不可达双重滚动；
- 不得出现横向根溢出或按钮裁切；
- 低于支持范围时仍可访问全部字段和操作；
- 所有输入具备可见标签、说明、错误关联和自动完成语义；
- 性别、公开年龄开关和头像状态不能只依赖颜色；
- 裁剪支持键盘移动、缩放、确认和取消；
- 对话框支持 Escape、焦点陷阱和关闭后焦点恢复；
- 保存成功、失败和版本冲突具备辅助技术可感知状态；
- 未保存确认支持键盘并恢复合理焦点。

## 14. 性能与可靠性

- 资料读取避免无界查询；
- 头像处理限制为单文件和固定最大大小；
- Sharp 或等价处理设置像素上限和解码保护；
- 公开内容查询只增加必要用户头像字段，避免逐条额外查询；
- 新对象 Key保证缓存更新；
- 不引入 Redis、消息队列或新媒体服务；
- 存储失败、数据库失败和版本冲突均有可测试补偿；
- 快速重复点击保存最多产生一次有效保存；
- 页面卸载后旧请求不得覆盖后来页面状态；
- 当前没有生产数据支持固定响应时间预算，后续依据指标复审。

## 16. 验收标准

### AC-001：数据迁移

- 空库和历史库成功部署；
- 新字段默认值符合规则；
- 既有用户继续显示默认头像；
- 既有用户资料、内容和互动不被修改。

### AC-002：私有设置访问

- 登录用户只能读取自己的完整设置；
- 未登录返回现有登录流程；
- 登录成功恢复 `/settings/profile`；
- 公开接口不返回邮箱和完整出生日期。

### AC-003：昵称、性别和简介

- 昵称按 `2～20` 规则保存且允许重复；
- 性别只接受三个受控值；
- 简介可空、最多 `100` 字并按纯文本展示；
- 非法值不产生部分更新。

### AC-004：出生日期和年龄

- 出生日期可设置和清空；
- 未来、无效和超过 `120` 岁日期被拒绝；
- 年龄由服务端正确计算，包括生日当天和闰日边界；
- 数据库不保存年龄数字。

### AC-005：年龄隐私

- 默认和现有用户不公开年龄；
- 只有有效生日且用户主动开启时公开整数年龄；
- 清空生日自动关闭公开年龄；
- 任何公开 API 不返回完整生日。

### AC-006：头像输入安全

- 只接受真实 JPEG、PNG、WebP；
- 超过 `5 MiB`、低于 `512×512`、动图、损坏或伪装文件被拒绝；
- 服务端不信任扩展名和 MIME；
- 错误不泄露存储路径。

### AC-007：裁剪和输出

- 裁剪固定 `1:1`，支持拖动和缩放；
- 裁剪区域至少 `512×512`；
- 输出为 `512×512 WebP`；
- 不放大小图；
- 元数据被移除，透明区域安全合成；
- 裁剪具备键盘和对话框语义。

### AC-008：头像更换、删除和缓存

- 更换后立即展示新头像；
- 删除后恢复当前昵称首字头像；
- 新头像使用新对象 Key，不被旧浏览器缓存覆盖；
- 不删除其他用户头像或笔记图片。

### AC-009：整体保存和失败补偿

- 一次保存全部字段共同成功；
- 字段、图片、存储、数据库或版本失败时不出现部分字段成功；
- 失败保留表单和原资料；
- 新暂存文件被清理；
- 旧文件清理失败可追踪并可重试，不形成静默孤立文件。

### AC-010：版本冲突

- 两个窗口读取同一版本后，先保存者成功；
- 后保存者获得稳定 `409`；
- 冲突请求不覆盖最新资料或产生新头像孤立文件；
- 重新加载后可以基于新版本保存。

### AC-011：设置页交互

- 设置入口、返回、加载、重试、保存、取消和错误状态正确；
- 骨架稳定约 `300ms`；
- 保存期间不重复提交；
- 成功返回当前用户个人主页，且展示最新资料；
- 失败保留用户输入。

### AC-012：未保存修改保护

- 内部导航、取消、浏览器后退、刷新和关闭均按规则提示；
- 放弃和继续编辑行为正确；
- 保存成功后不再错误提示；
- 对话框支持键盘和焦点恢复。

### AC-013：公开资料传播

- 当前主页和公开主页展示最新公开字段；
- 历史笔记、评论、通知、用户搜索和笔记搜索展示最新头像与昵称；
- 默认头像随昵称变化；
- 不需要重新登录；
- 排序和互动数据不受影响。

### AC-014：自适应与可访问性

- `960×600` 及支持范围内无裁切、横向溢出、假滚动或双重滚动；
- 表单和裁剪对话框在连续尺寸变化下可用；
- 字段、开关、按钮、错误和异步状态具有正确语义；
- 关键流程可通过键盘完成。

### AC-015：安全、OpenAPI 和回归

- 服务端只修改会话用户；
- 邮箱、小蓝书号和内部对象 Key不可越权修改；
- 上传、对象 Key和删除防止路径穿越和枚举；
- OpenAPI 成功及错误响应与真实接口一致；
- 认证、个人主页、内容、互动、搜索和通知直接回归通过；
- 常规静态检查、测试、构建和适用 Browser E2E 通过。

## 17. 明确允许延后

- 修改邮箱、小蓝书号和账号安全设置；
- 头像/昵称内容审核；
- 资料修改频率限制；
- 资料历史和回滚；
- 用户自定义隐私策略；
- 独立头像对象存储或 CDN；
- Redis 资料缓存；
- 管理员资料管理后台；
- App 端。

## 18. 风险

- 自定义头像会影响笔记、评论、通知、搜索和共享页面外壳，需要统一头像映射，避免局部仍使用昵称首字；
- PostgreSQL 与文件存储不能天然跨资源事务，需要明确暂存、补偿和待清理机制；
- 生日和年龄存在时区边界，必须使用纯日期和服务端日期计算；
- 多窗口版本冲突若仅依赖客户端会导致静默覆盖，必须由服务端条件更新；
- 裁剪对话框、未保存确认和 `beforeunload` 容易产生浏览器差异，需要三浏览器关键覆盖；
- 头像 URL 缓存若复用旧 Key会显示旧图，必须使用新 Key；
- 公开资料字段扩展必须继续遵守邮箱和完整出生日期白名单。
