# SPEC-010 实施计划

- Spec：`specs/spec-010-profile-settings/spec.md`
- 当前 Spec 状态：Confirmed
- 计划状态：Ready for Implementation
- 负责人：协调开发 Agent
- 实施约束：确认后只创建一个新的实施 Agent，数据库、后端、媒体、前端和 E2E 必须由同一 Agent 串行完成；实施 Agent 不得创建子 Agent。

## 1. 实施目标

- 扩展用户资料数据模型并完成兼容迁移；
- 建立私有设置读取和带版本的统一保存 API；
- 建立安全头像裁剪、标准化、存储、替换、删除和补偿；
- 实现 `/settings/profile` 页面和个人主页入口；
- 统一所有公开响应中的头像与最新昵称；
- 完成年龄隐私、未保存保护、自适应和可访问性；
- 补齐正式测试和 Browser E2E。

## 2. 预计影响范围

### 数据库

- `backend/prisma/schema.prisma`
- 新迁移及历史库兼容测试
- 头像清理状态模型或等价可追踪机制

### 后端

- `profile` 模块、DTO、类型和 OpenAPI；
- `media` 模块的头像专用安全处理；
- notes、interactions、notifications、search 的统一头像映射；
- auth 会话摘要同步所需逻辑；
- 相关单元和集成测试。

### 前端

- `/settings/profile` 页面；
- 头像裁剪对话框和表单；
- 个人主页设置菜单；
- 共享头像组件或映射；
- 当前主页、公开主页、笔记、评论、通知和搜索适配；
- 未保存确认和版本冲突；
- 组件测试。

### E2E

- 新增 SPEC-010 正式 E2E；
- 更新受影响认证、资料、内容、互动、搜索和通知回归；
- 常规 CI 不运行 Browser E2E。

## 3. 实施顺序

### 阶段 A：数据和迁移

1. 增加生日、年龄公开、简介和头像引用；
2. 确定资料版本实现；
3. 增加可追踪头像清理机制或等价方案；
4. 完成空库和历史库迁移；
5. 验证旧用户继续使用默认头像且不公开年龄。

### 阶段 B：头像处理

1. 建立头像专用上传限制；
2. 验证真实格式、大小、像素、动画和最低尺寸；
3. 服务端执行 `512×512 WebP` 标准化；
4. 移除元数据并处理透明背景；
5. 接入既有 MediaStorage；
6. 实现暂存、提交、补偿和旧文件清理；
7. 使用失败注入测试全部清理路径。

### 阶段 C：资料 API

1. 实现私有设置读取；
2. 实现统一保存和字段校验；
3. 实现服务端年龄计算；
4. 实现 `profileVersion` 条件更新和 `409`；
5. 返回最终私有设置、公开资料和新版本；
6. 补齐权限、隐私、错误和 OpenAPI。

### 阶段 D：公开资料传播

1. 建立统一头像 DTO 和映射；
2. 更新当前主页和公开主页；
3. 更新笔记及笔记搜索作者；
4. 更新评论作者；
5. 更新通知发起者；
6. 更新用户搜索；
7. 更新共享侧边栏和登录会话状态；
8. 防止 N+1 和旧头像缓存。

### 阶段 E：设置页面

1. 增加设置菜单入口；
2. 创建页面外壳和稳定骨架；
3. 实现纵向表单、只读字段和校验；
4. 实现裁剪、拖动、缩放、预览和删除；
5. 实现统一保存、错误保留、重复提交保护和成功后返回个人主页；
6. 实现版本冲突重载；
7. 实现未保存确认；
8. 完成键盘、焦点、自适应和滚动。

### 阶段 F：验证与交接

1. 运行修改范围定向测试；
2. 运行迁移和媒体故障测试；
3. 运行受影响前后端回归；
4. 运行格式、Lint、类型、数据库校验和构建；
5. 运行 SPEC-010 Chromium E2E；
6. 如实记录未运行完整矩阵的实施阶段依据；
7. 返回协调 Agent，由新的验收 Agent 独立验收。

## 4. 测试矩阵

| 层级 | 核心验证 |
| --- | --- |
| 数据库 | 空库/历史库、新字段默认值、版本、头像引用和清理状态 |
| 资料服务 | 字段校验、年龄、隐私、原子保存、冲突和权限 |
| 媒体 | 类型、大小、像素、尺寸、裁剪、WebP、元数据、透明底和补偿 |
| 前端 | 表单、裁剪、骨架、错误保留、冲突、未保存确认和键盘 |
| 传播 | 当前/公开主页、笔记、评论、通知、搜索、共享侧边栏 |
| E2E | 编辑闭环、删除头像、多窗口冲突、失败补偿、三浏览器关键行为 |
| 布局 | `960×600`、常用桌面视口及连续尺寸变化 |

## 5. 风险控制

- 不把年龄数字写入数据库；
- 不让公开 DTO 包含邮箱或完整生日；
- 不复用旧对象 Key覆盖头像；
- 文件和数据库失败均需要补偿证据；
- 不允许多窗口最后写入静默覆盖；
- 统一头像映射，禁止在各服务继续复制昵称首字逻辑；
- 不引入 Redis、CDN、新对象存储或无依据依赖；
- 不扩大为账号安全、审核或管理后台。
