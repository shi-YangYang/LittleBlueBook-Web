## 1. 实施目标

- 建立安全的结构化本地法律资料配置；
- 交付用户协议、隐私政策、帮助反馈和关于我们页面；
- 建立权威条款版本、接受历史和重新确认门禁；
- 把登录、注册、重新认证和现有会话接入版本化接受；
- 完善侧边栏“更多”和“关于我们”；
- 落实 14 周岁门槛和出生日期校验；
- 完成兼容迁移、OpenAPI、自动化测试和 Browser E2E。

## 3. 实施顺序

### 阶段 A：配置模型

1. 增加示例 JSON 和精确忽略规则；
2. 实现服务端运行时读取、模式校验、占位检测和安全错误；
3. 让 Next 法律页面保持动态服务端渲染；
4. 建立本地开发与生产容器的固定配置路径；
5. 验证客户端包、日志和错误不包含真实配置；
6. 验证 Docker 镜像无真实文件且只读挂载后可用。

### 阶段 B：数据库与版本服务

1. 建立不可覆盖的接受历史模型及唯一/查询索引；
2. 定义后端当前协议版本常量；
3. 建立公开版本元数据和私有接受状态；
4. 完成空库及 SPEC-011 历史库迁移；
5. 补齐 OpenAPI 和权限测试。

### 阶段 C：认证闭环

1. 获取验证码时绑定后端当前版本；
2. 验证成功后在注册或登录事务中写入接受记录；
3. 处理挑战过期、版本变化、失败和并发幂等；
4. 扩展会话恢复的待重新确认状态；
5. 在后端统一阻止待确认会话的认证写操作；
6. 实现重新确认与退出登录。

### 阶段 D：法律和信息页面

1. 起草符合 Spec 章节要求的用户协议；
2. 按当前真实数据流起草隐私政策；
3. 实现共享长文页面结构、目录和配置注入；
4. 实现帮助 FAQ、GitHub Issues 警告与链接；
5. 实现关于我们页面；
6. 验证配置缺失时的安全降级。

### 阶段 E：前端入口与菜单

1. 替换三个认证弹窗中的“功能开发中”条款按钮；
2. 保证新标签页打开及原表单状态不丢失；
3. 实现全局重新确认对话框；
4. 实现登录前后“更多”菜单；
5. 将“关于我们”接到 `/about`；
6. 统一重复侧边栏实现或以最小风险共享行为。

### 阶段 F：年龄门槛

1. 在协议接受文案中加入 14 周岁声明；
2. 后端资料保存增加 14 周岁边界校验；
3. 前端日期选择和字段错误同步；
4. 为历史异常资料建立受限状态；
5. 验证生日当天、闰日和并发更新。

### 阶段 G：验证与交接

1. 运行配置解析、安全和构建产物探针；
2. 运行迁移、认证、接受历史、资料年龄和权限定向测试；
3. 运行受影响前后端回归、Lint、类型和构建；
4. 运行 SPEC-012 Chromium E2E；
5. 对新标签页和焦点风险运行 Firefox/WebKit 定向 E2E；
6. 清理一次性配置、测试产物和临时脚本；
7. 返回协调 Agent，由新的独立验收 Agent 执行完整验收。

## 5. 风险控制

- 不把真实法律资料写入任何 tracked 文件或测试夹具；
- 不让客户端决定权威条款版本或接受时间；
- 不在版本变更时静默把旧接受记录升级为新版本；
- 不用前端门禁替代后端写操作授权；
- 不把“打开条款”误认为“接受条款”；
- 不修改既有迁移，使用新的兼容迁移；
- 不在条款中虚构许可、备案、跨境合规或产品能力；
- 不扩展为未成年人监护同意、站内工单或账号注销；
- 不修改 CI 手动触发与 Browser E2E 边界。
