# SPEC-009 实施计划

- Spec：`specs/spec-009-notification-center/spec.md`
- 当前 Spec 状态：Accepted
- 计划状态：Completed
- 负责人：协调开发 Agent
- 实施约束：确认后只创建一个新的实施 Agent，完整串行处理数据库、后端、前端和 E2E；实施 Agent 不得创建子 Agent。

## 1. 实施目标

- 建立 PostgreSQL 通知模型和迁移；
- 在四类既有互动写流程中事务性创建通知；
- 建立通知查询、未读数量和幂等已读 API；
- 将所有现有页面的“通知”入口接入真实路由和未读徽标；
- 实现 `/notifications` 页面、四个 Tab、列表、空态、错误、分页和目标跳转；
- 完成登录恢复、自适应滚动、可访问性和相关回归。

## 2. 预计影响范围

### 数据库

- `backend/prisma/schema.prisma`
- 新的版本化迁移
- 迁移和数据约束测试

### 后端

- 新增通知模块、控制器、服务、DTO 和 OpenAPI schema；
- 调整点赞、收藏、评论和关注写入事务；
- 调整相关后端单元/集成测试；
- 注册通知模块。

### 前端

- 新增 `/notifications` 页面；
- 新增通知 API 类型和数据访问；
- 扩展共享页面外壳或通知入口；
- 接入未读徽标、登录意图恢复和目标跳转；
- 增加通知页面与组件测试。

### E2E

- 新增通知业务 E2E；
- 更新现有布局、认证和社交互动回归；
- 不把 Browser E2E 加入常规 CI。

### 文档

- 更新 Spec 状态和验收记录；
- 若实现发现不改变外部行为的技术澄清，可同步记录；
- 任何实质范围变化必须返回协调 Agent 和用户确认。

## 3. 实施顺序

### 阶段 A：数据库与迁移

1. 增加通知类型和通知模型；
2. 建立接收者、发起者、笔记、评论关系；
3. 建立分页、分类和未读索引；
4. 确认目标删除采用保留通知的关系策略；
5. 验证空库和历史库迁移；
6. 不回填上线前历史互动。

### 阶段 B：通知后端

1. 建立通知列表查询；
2. 实现四个 Tab 的服务端过滤；
3. 实现稳定游标解析、作用域绑定和非法游标拒绝；
4. 实现未读总数；
5. 实现单条幂等已读；
6. 实现全部幂等已读；
7. 补齐权限、错误和 OpenAPI。

### 阶段 C：互动事务接入

1. 点赞从未建立到建立时写入通知；
2. 收藏从未建立到建立时写入通知；
3. 评论创建时写入通知；
4. 关注从未建立到建立时写入通知；
5. 排除本人动作；
6. 保持取消操作不写通知；
7. 验证重复请求、取消重建、并发和事务回滚。

### 阶段 D：共享通知入口

1. 将左侧“通知”统一改为真实路由；
2. 登录后加载未读数量；
3. 实现 `1～99`、`99+` 和零状态；
4. 未登录时复用登录弹框；
5. 登录成功恢复 `/notifications`；
6. 避免在各页面复制不一致的徽标逻辑。

### 阶段 E：通知页面

1. 创建页面外壳和四个 URL Tab；
2. 实现稳定 `300ms` 骨架、空态、错误和重试；
3. 实现通知行、评论两行预览、缩略图和相对时间；
4. 实现分页加载更多；
5. 实现单条已读、全部已读和未读同步；
6. 实现详情、公开主页和目标失效处理；
7. 处理快速切换 Tab 和已读请求竞争；
8. 完成键盘、辅助技术、自适应高度和滚动。

### 阶段 F：验证与交接

1. 运行修改范围格式、Lint 和类型检查；
2. 运行数据库校验和迁移测试；
3. 运行通知及受影响互动测试；
4. 运行前后端构建；
5. 运行 SPEC-009 Chromium E2E；
6. 如实记录未运行项和分层依据；
7. 返回协调 Agent，由新的独立验收 Agent 继续验收。

## 4. 测试矩阵

| 层级 | 核心验证 |
| --- | --- |
| 数据库 | 空库/历史库迁移、外键、可空目标、索引、不回填历史互动 |
| 后端 | 四类生成、本人排除、幂等、取消重建、事务、权限、游标、已读 |
| 前端 | URL Tab、骨架、空态、失败、徽标、已读、跳转、竞争、键盘 |
| E2E | 双用户互动→通知→已读→跳转、一键已读、登录恢复、目标删除 |
| 回归 | SPEC-007 社交互动、共享导航、详情、个人页、公开主页、搜索页 |
| 布局 | `960×600`、常用桌面视口及连续尺寸变化，无假滚动和双重滚动 |

## 5. 风险控制

- 在修改互动事务前先锁定 SPEC-007 现有行为测试；
- 通知创建只发生在真实状态变化，不按请求次数生成；
- 分页游标绑定用户和 Tab，避免跨域读取；
- 评论删除后不保留正文快照；
- 徽标以服务端未读数为准，乐观更新必须可收敛；
- 不引入 Redis、WebSocket、消息队列或额外基础设施；
- 不扩大为私信、系统通知、回复或推送设置。
