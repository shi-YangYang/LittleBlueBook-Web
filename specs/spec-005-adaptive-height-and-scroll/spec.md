## 1. 背景

现有页面为了贴近参考设计，保留了较多固定组件尺寸，同时逐步增加了页面级固定高度、嵌套 `100vh` 计算和高度媒体查询。个人页和发布页曾因此在首次加载、刷新或未被测试覆盖的中间视口高度出现无意义的 `html` 根滚动条。

本 Spec 不再针对单个像素高度追加补丁，而是统一现有页面的高度计算、内容伸缩和滚动容器归属，使布局在已确认桌面范围内连续自适应。

## 2. 已确认目标

- 对现有页面进行页面高度与滚动模型的统一改造；
- 消除内容能够完整容纳时出现的根滚动条、双重滚动条和内容裁切；
- 内容真实超过可用空间时，由已定义的容器提供正常滚动；
- 页面在窗口连续缩放、首次进入、刷新和站内导航时保持一致；
- 保留当前视觉结构、品牌风格和业务行为；
- 不再以大量固定宽高组合或孤立高度断点作为适配方式。

## 3. 范围

### 3.1 本期包含

- 首页 `/`；
- 当前用户个人页 `/profile`；
- 发布页 `/publish`；
- 笔记详情页 `/explore/[noteId]`；
- 登录弹框和会话失效后的重新认证弹框；
- 公共侧栏、顶部区域和上述页面共享的布局容器；
- 加载、空状态、错误状态、短内容、长内容和多行媒体状态；
- 浏览器返回后的列表滚动位置恢复回归；
- 与本次改造相称的组件测试和 Browser E2E。

### 3.2 本期不包含

- App 端；
- 完整移动端 Web 视觉设计；
- 对现有页面进行视觉重设计；
- 新增、删除或改变业务功能；
- 后端、数据库、接口或媒体存储改造；
- 推荐算法、虚拟列表或无限滚动性能重构；
- 自定义或隐藏浏览器原生滚动条；
- 引入新的布局、样式或测试依赖。

## 4. 兼容范围

- 完整支持的桌面 Web 范围为 CSS 视口宽度不低于 `960px`、高度不低于 `600px`；
- 两项下限彼此独立，不构成固定分辨率组合；
- 支持范围内任意可用宽高应连续自适应，不得只保证少量截图尺寸；
- 低于支持范围时允许页面自然滚动，但所有内容和操作仍须可访问、不得被永久裁切；
- 本期浏览器范围为项目现有 Playwright 配置中的 Chromium、Firefox 和 WebKit；
- Browser E2E 只在本地实施与独立验收中运行，不加入常规 CI。

## 5. 通用布局规则

### 5.1 尺寸使用边界

- 按钮、头像、图标、边框、圆角和局部间距可以继续使用固定尺寸；
- 页面外壳、主内容区和承担滚动职责的容器不得依赖固定页面高度；
- 页面级布局优先使用动态视口单位、Flex、Grid、内容尺寸、`minmax()`、`clamp()` 和必要的最小/最大约束；
- Flex 或 Grid 中需要滚动的子项必须具备正确的可收缩条件，避免默认最小内容尺寸撑开根元素；
- 不得通过增加多个相邻的视口高度媒体查询修复单点溢出；
- 只有布局结构确实改变时才允许使用媒体查询，并须验证断点两侧连续、无断档。

### 5.2 溢出处理

- 不得通过全局 `overflow: hidden` 掩盖页面溢出；
- 只有弹框打开等明确需要锁定背景页面的状态可以临时禁止背景滚动；
- 不得同时让根页面和主要内部内容区承担同一方向的滚动；
- 真实溢出的内容必须可以通过鼠标滚轮、触控板、键盘和滚动条完整访问；
- 内容没有超过可用空间时，`html` 和 `body` 不得因为边距折叠、滚动槽、最小尺寸或取整误差产生假滚动条；
- 页面不得通过隐藏滚动条但保留未知溢出的方式通过验收。

## 6. 页面滚动归属

| 页面或状态 | 主要滚动容器 | 行为要求 |
| --- | --- | --- |
| 首页 | 文档根页面 | 信息流未超过视口时不滚动，超过后自然滚动 |
| 个人页 | 文档根页面 | 空状态或一行内容可容纳时不滚动，真实内容超过后自然滚动 |
| 发布页 | 文档根页面 | 初始状态和第一行图片可容纳时不滚动，第二行或其他内容超过后自然滚动 |
| 笔记详情页 | 右侧详情内容区 | 页面外层保持视口内稳定，右侧长内容独立滚动，左侧媒体不被右侧内容撑高 |
| 登录与重新认证弹框 | 弹框内容区 | 背景页面锁定；弹框超过可用高度时内部滚动，关闭后恢复原背景滚动状态 |

任一页面如果因为用户内容、字体渲染或低于最低支持范围而无法满足“不滚动”条件，应优先保证内容完整可访问，不得为了隐藏滚动条压缩到不可用或裁切内容。

## 7. 页面状态与生命周期

- 首次直接访问、浏览器刷新和站内导航必须得到一致的滚动归属；
- 加载状态切换为成功、空状态或错误状态时，不得遗留错误的 `body` 锁定样式；
- 异步数据和图片加载不得将页面永久撑出横向滚动；
- 打开弹框时记录并锁定背景滚动，关闭或组件卸载时必须恢复原状态；
- 从首页或个人页进入详情，再通过浏览器返回时，应恢复离开前的列表滚动位置；
- 普通链接跳转继续遵循浏览器和 Next.js 的既有滚动行为，本期不建立新的全局滚动状态管理系统；
- 连续调整窗口宽高时不得要求刷新页面才能恢复正确布局。

## 8. 页面专项要求

### 8.1 首页

- 侧栏和主内容区不得以相互矛盾的固定视口高度造成双重滚动；
- 信息流卡片按现有列布局展示，不改变卡片视觉比例和内容顺序；
- 登录弹框打开和关闭不得改变关闭后的首页滚动位置；
- 页面真实内容较长时必须可以滚动到底部。

### 8.2 个人页

- 资料头部、统计区、Tab 和内容区使用单一连续纵向布局；
- 加载骨架、空状态、一行笔记和多行笔记不得使用互相冲突的高度算法；
- 空状态和一行笔记在内容可容纳时不得产生根滚动；
- 第二行及更多内容只有在真实超过可用高度时才产生根滚动；
- 三个 Tab 切换后滚动模型保持一致。

### 8.3 发布页

- 顶部区域、媒体面板和文案面板共同适应可用视口，不使用针对某个高度的紧凑布局补丁；
- 初始状态及第一行预览在支持范围内可完整容纳时不得产生根滚动；
- 第二行预览、长文案、错误提示或重新认证流程造成真实溢出时允许页面自然滚动；
- 所有上传预览、删除按钮、输入区域、话题占位和发布按钮始终可访问；
- 发布成功进入详情和未保存内容离开确认行为不得回归。

### 8.4 笔记详情页

- 详情页外层尺寸由可用视口决定，不同时设置互相冲突的固定高度和最小高度；
- 左侧媒体区与右侧详情区在支持范围内完整落入视口；
- 右侧作者、正文、占位互动和评论区域内容较长时仅由右侧内容区滚动；
- 左侧多图切换、返回按钮及右侧固定交互区域不得因滚动被裁切；
- 低于最低支持范围时可以转为整体自然滚动，但不得丢失内容。

### 8.5 登录与重新认证弹框

- 弹框尺寸受当前动态视口约束，不得高于可用空间后仍禁止内部滚动；
- 背景锁定不得改变页面宽度、制造滚动槽跳动或在关闭后留下 `overflow` 样式；
- 短视口下所有邮箱、验证码、协议和操作按钮均可访问；
- Escape、关闭按钮、焦点管理和原有认证流程保持不变。

## 9. 可访问性

- 真实滚动区域可以通过鼠标、触控板和键盘操作；
- 页面不得依赖隐藏滚动条作为默认视觉方案；
- 键盘焦点进入内部滚动区后，聚焦内容必须能够滚动到可见范围；
- 弹框内部滚动不得形成键盘陷阱；
- 浏览器缩放导致 CSS 视口缩小时，按兼容范围和低于范围的规则处理，不裁切核心操作；
- 尊重项目已有 `prefers-reduced-motion` 规则，不新增不必要的滚动动画。

## 10. 技术约束

- 不新增依赖；
- 不修改后端、数据库、接口和媒体文件；
- 不通过 JavaScript 持续监听并写入元素像素高度来代替 CSS 布局；
- 允许在确有需要时使用一次性的浏览器几何读取完成测试断言，但不得成为页面运行依赖；
- 应收敛重复或互相覆盖的页面级高度规则，保持布局职责可追踪；
- 必须保留当前认证、发布、详情、导航和内容展示行为。

## 11. 测试策略

- 测试关注布局不变量，不把每个测试视口变成产品断点；
- 选择最低支持边界附近、常见桌面和大桌面三类代表性视口；
- 通过同一页面连续改变视口宽高，验证不刷新也能正确重排；
- 每类页面至少覆盖加载、空或短内容、真实长内容三种状态；
- 检查 `html`、`body` 和预定滚动容器的 `clientHeight`、`scrollHeight`、横向溢出和可滚动到底部能力；
- 覆盖首次直接访问、刷新、站内导航、浏览器返回和弹框打开/关闭；
- Chromium、Firefox、WebKit 均验证关键滚动行为；
- 常规 CI 继续只执行静态检查、单元/集成测试和构建，不运行 Browser E2E。

## 12. 验收标准

### AC-001：兼容边界与连续自适应

- 在宽度不低于 960 CSS px、高度不低于 600 CSS px 的桌面范围内连续调整窗口时，页面无需刷新即可正确重排；
- 不存在只在某个中间高度出现的裁切、横向滚动、假纵向滚动或双重滚动；
- 低于最低支持范围时，核心内容和操作仍可通过自然滚动访问。

### AC-002：通用滚动归属

- 每个页面只有已定义的主要纵向滚动容器；
- 没有真实内容溢出时不出现假滚动；
- 真实内容溢出时可以完整滚动到底部；
- 没有使用全局隐藏溢出来规避失败。

### AC-003：首页

- 短信息流无假滚动，长信息流由文档根页面自然滚动；
- 侧栏与内容区不形成相互竞争的纵向滚动；
- 登录弹框关闭后首页滚动位置不发生异常跳动。

### AC-004：个人页

- 加载、空状态和一行笔记在内容可容纳时无根滚动；
- 多行笔记真实超过可用高度后由根页面自然滚动；
- 首次进入、刷新、站内导航和三个 Tab 切换的滚动结果一致。

### AC-005：发布页

- 初始状态及第一行图片在内容可容纳时无根滚动；
- 第二行图片、长内容或错误信息真实超出后可以自然滚动；
- 不存在针对单个高度区间的紧凑布局补丁；
- 上传、删除、编辑、重新认证、离开确认和发布成功行为不回归。

### AC-006：笔记详情页

- 支持范围内详情页外层不产生根滚动；
- 右侧长内容独立滚动且可以到达末尾；
- 左侧媒体区、返回按钮和固定交互区域不被裁切；
- 低于支持范围时仍可访问全部详情内容。

### AC-007：认证弹框

- 弹框打开时背景正确锁定，关闭后完整恢复；
- 矮视口下弹框内部可以滚动并访问所有操作；
- 不出现背景与弹框同时滚动、页面宽度跳动或残留锁定。

### AC-008：导航与滚动恢复

- 从信息流进入详情并使用浏览器返回后恢复原列表滚动位置；
- 首次访问、刷新和站内导航不会产生不同的滚动容器；
- 调整窗口尺寸后不需要刷新才能恢复正确状态。

### AC-009：跨浏览器与回归

- Chromium、Firefox、WebKit 的关键滚动场景通过；
- 代表性视口和连续尺寸变化检查通过，不将测试样本写成新的页面断点；
- 现有认证、个人页、发布、详情、导航和内容测试继续通过；
- 格式、Lint、类型检查、前端测试、构建和本地 Browser E2E 通过。

## 13. 风险与防护

- 页面共用同一全局样式文件，修改公共规则可能影响多个路由；实施必须先建立滚动归属基线，再逐页收敛；
- 浏览器滚动槽、动态视口单位和 Flex 最小尺寸存在差异，必须跨三种浏览器验证；
- 过度使用内部滚动会损害键盘和触控板体验，只允许详情页和弹框使用已明确的内部滚动；
- 不得为了满足“不出现滚动条”而压缩、遮挡或隐藏真实内容；
- 既有未提交工作必须保留，不得借本次重构整理无关样式。
