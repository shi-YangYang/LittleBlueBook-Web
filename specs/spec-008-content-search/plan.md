# SPEC-008 实施计划

- Spec：`specs/spec-008-content-search/spec.md`
- 当前 Spec 状态：Accepted
- 计划状态：Completed
- 负责人：协调开发 Agent
- 实施约束：完整任务只能交给一个新的实施 Agent，不得按数据库、后端、前端、公开主页或 E2E 并行拆分。

## 1. 实施目标

在不引入独立搜索服务、不实现视频系统的前提下，完成搜索模态框、独立搜索结果页、图片笔记搜索、用户搜索、视频正式空分类和他人公开主页，并保持现有登录、互动、频道、滚动与隐私边界。

## 2. 实施前提

- 用户明确确认完整 `spec.md`；
- Spec 状态由协调 Agent 更新为 `Confirmed`；
- PostgreSQL 18 环境可以安装可信扩展 `pg_trgm`；
- 当前工作区的 SPEC-007 改动已由用户提交，实施 Agent 开始前检查实际 Git 状态；
- 不存在尚未确认且会改变搜索结果或公开主页行为的问题。

## 3. 实施阶段

### 阶段一：数据库搜索基线

- 新增幂等 `pg_trgm` 扩展迁移；
- 为笔记标题、正文和用户昵称建立 GIN trigram 索引；
- 检查小蓝书号和频道名称查询的现有索引；
- 验证空库和历史库无损迁移；
- 使用代表性数据检查包含查询的执行计划。

### 阶段二：搜索后端

- 建立搜索模块或等价清晰职责；
- 实现关键词规范化、长度校验、拆分、去重和模式字符安全处理；
- 实现图片笔记多字段 AND 查询、分级排序和稳定游标；
- 实现用户搜索、聚合统计、关注状态和稳定游标；
- 实现视频空分页结果；
- 避免笔记卡片和用户统计 N+1。

### 阶段三：公开用户后端

- 增加公开用户资料读取；
- 增加指定用户公开笔记分页；
- 复用现有关注接口和互动统计语义；
- 对当前用户、匿名用户、无效会话和不存在用户处理正确；
- 使用明确的公开 DTO，禁止泄露邮箱和年龄。

### 阶段四：共享搜索模态框

- 抽取共享搜索入口和模态框组件；
- 接入首页、当前用户个人页、搜索结果页和他人公开主页；
- 将模态框定位在完整视口的顶部水平中心，不以右侧内容区作为居中参照；
- 实现预填、校验、Enter、关闭、遮罩、Esc、焦点进入与恢复；
- 提交后关闭并导航，关闭不导航；
- 保证背景滚动锁定与恢复。

### 阶段五：搜索结果页

- 建立 `/search` 页面；
- 解析和规范 `keyword`、`type`；
- 实现【笔记】【视频】【用户】Tab 和 URL 同步；
- 复用笔记瀑布流、卡片点赞和登录弹框；
- 实现用户纵向列表、关注与公开主页导航；
- 实现稳定骨架、空、失败、重试和加载更多；
- 处理请求取消和旧响应覆盖。

### 阶段六：他人公开主页

- 建立 `/users/[userId]` 页面；
- 展示公开资料、统计、关注按钮和单一【笔记】Tab；
- 当前用户转到 `/profile`；
- 复用笔记卡片和分页；
- 处理匿名访问、登录恢复、404、空状态与返回搜索状态。

### 阶段七：自适应与可访问性

- 保证 `960×600` 最低范围；
- 验证模态框背景锁定、搜索结果单滚动容器和公开主页内容阈值；
- 完成对话框、Tab、焦点、状态和错误语义；
- 进行连续尺寸变化检查，不增加大量固定视口补丁。

### 阶段八：自动化与文档

- 数据库扩展、索引、无损迁移和查询计划测试；
- 后端关键词、排序、分页、隐私和可选会话测试；
- 前端模态框、URL、Tab、请求竞争、用户卡片和公开主页测试；
- 正式 Browser E2E 覆盖匿名搜索、登录关注、笔记搜索和返回状态；
- 更新 OpenAPI 和必要开发文档。

## 4. 建议实现顺序

1. 数据库迁移与索引；
2. 关键词规范化和笔记查询；
3. 用户查询与统计；
4. 公开用户 API；
5. OpenAPI；
6. 共享搜索模态框；
7. 搜索结果页与三个 Tab；
8. 用户卡片与关注；
9. 他人公开主页；
10. 自适应、可访问性和自动化。

该顺序只用于降低集成风险，不授权创建多个实施 Agent。

## 5. 测试计划

### 数据与后端

- 空库和历史库迁移；
- `pg_trgm` 扩展与 GIN 索引；
- 中文、英文大小写、模式字符和多关键词 AND；
- 标题、正文、作者、频道命中；
- 笔记分级排序与稳定游标；
- 用户昵称和小蓝书号排序；
- 非法关键词和非法游标；
- 匿名、有效会话、无效会话；
- 用户卡片粉丝数、笔记数和关注状态；
- 公开主页字段白名单与 404；
- 代表性查询计划和批量聚合。

### 前端

- 搜索入口只打开模态框；
- 模态框校验、提交、关闭和焦点；
- 结果 URL、刷新、返回和 Tab 同步；
- 笔记卡片复用和点赞不误导航；
- 视频固定空状态；
- 用户卡片、自己/他人导航和关注；
- 公开主页、隐私、空状态和登录恢复；
- 请求竞争、取消、首次错误和加载更多错误；
- 骨架最短展示；
- 键盘与辅助技术属性；
- 根滚动、模态框滚动锁和连续尺寸。

### Browser E2E

- 匿名用户从首页打开模态框并搜索标题；
- 搜索正文、作者和频道名称均返回同一真实笔记；
- 多关键词 AND 和排序正确；
- 切换笔记、视频、用户并刷新恢复；
- 视频显示真实空状态；
- 用户搜索进入公开主页；
- 未登录关注触发登录并只恢复一次；
- 已登录关注/取消在搜索结果、公开主页和详情保持一致；
- 返回搜索页恢复关键词和用户 Tab；
- 当前用户结果进入 `/profile`；
- 公开主页不显示私密字段；
- 最低视口和连续尺寸无假滚动或双重滚动；
- 初次实施运行 SPEC-008 相关 Chromium 场景；
- 初次独立验收运行一次完整 Browser E2E。

- `backend/prisma/schema.prisma`
- `backend/prisma/migrations/`
- 新增搜索后端模块或等价职责文件
- `backend/src/profile/`
- `backend/src/notes/`
- `frontend/app/page.tsx`
- `frontend/app/profile/page.tsx`
- `frontend/app/search/`
- `frontend/app/users/[userId]/`
- `frontend/app/_components/`
- `frontend/app/_lib/`
- `frontend/app/globals.css`
- 前后端测试与 `e2e/tests/`
- OpenAPI

不应影响：

- SMTP 凭据与邮件发送；
- 图片上传和本地媒体存储；
- 视频媒体系统；
- 推荐算法；
- 频道定义与排序；
- Redis 数据；
- CI/CD 和生产部署工作流。

## 7. 验证层级

- 实施过程：只运行当前数据库、后端或前端改动的定向测试；
- 初次实施交付：运行适用静态检查、前后端测试、构建和 SPEC-008 Chromium Browser E2E；
- 初次实施不机械运行完整三浏览器 E2E；
- 初次独立验收：运行一次完整 Browser E2E；
- 小范围返工：只运行历史失败和受影响回归，除非触发 `.ai/rules/testing.md` 的升级条件；
- 协调 Agent 不在实施或验收已有可信证据后重复运行同一工作区状态的相同测试。

## 8. 风险控制

- 搜索 SQL 必须参数化；
- 使用公开 DTO 和字段白名单；
- 用户统计使用批量查询，避免 N+1；
- 游标必须与排序等级一致；
- 请求竞争必须防止旧结果覆盖；
- 模态框必须共享，避免多页面行为分叉；
- 不把视频空分类扩大为视频系统；
- 不复制第三方品牌资产；
- 不新增外部搜索依赖；
- 实施 Agent 遇到 Spec 歧义必须返回协调 Agent。

## 9. 交付门禁

- 用户明确确认完整 Spec；
- 协调 Agent 更新状态为 `Confirmed`；
- 创建一个新的单一实施 Agent 完成全部范围；
- 实施 Agent 返回后永久退役；
- 创建一个身份独立的验收 Agent；
- 初次独立验收运行一次完整 Browser E2E；
- `FAIL` 时创建新的单一返工 Agent，再创建新的独立复验 Agent；
- 最新独立验收 `PASS` 后交由用户确认；
- 用户确认后更新为 `Accepted` 并提供中文 Conventional Commit 信息。
