## 1. 背景

首页和当前用户个人主页已经具有顶部搜索入口，但当前点击后只提示“功能开发中”。项目已经具备公开笔记、频道、用户资料、点赞和关注等数据，却没有从关键词发现内容与创作者的能力。

本 Spec 将顶部搜索入口改为真实搜索流程，建立独立搜索结果页，并补充他人公开主页，使用户能够通过笔记内容、作者和频道名称找到公开内容，通过用户昵称或小蓝书号找到用户。

## 2. 已确认目标

- 点击顶部搜索入口时先在当前页面打开搜索模态框，不立即跳转；
- 用户在模态框内提交有效关键词后关闭模态框，并进入独立搜索结果页；
- 搜索结果页提供【笔记】【视频】【用户】三个分类 Tab；
- 【笔记】搜索当前已有的图片笔记；
- 【视频】作为正式分类存在，但在视频发布能力建立前显示稳定空状态；
- 【用户】搜索用户昵称和小蓝书号；
- 搜索结果允许未登录用户访问；
- 点击用户结果进入该用户的公开主页；
- 他人公开主页展示公开资料、统计、关注状态和其发布的公开笔记；
- 搜索使用 PostgreSQL `pg_trgm` 和 GIN 索引，不引入独立搜索服务或 Redis 搜索缓存；
- 搜索页面、模态框和公开主页遵守既有自适应高度、滚动归属和可访问性基线。

## 3. 范围

### 3.1 本期包含

- 首页、当前用户个人主页、搜索结果页和他人公开主页的共享搜索入口；
- 搜索模态框的打开、输入、校验、提交、关闭、焦点恢复和键盘行为；
- 独立搜索结果页及可刷新、可返回、可分享的查询 URL；
- 【笔记】【视频】【用户】三个搜索分类；
- 笔记标题、正文、作者昵称和所属频道名称匹配；
- 用户昵称和小蓝书号匹配；
- 搜索排序、游标分页、加载更多、加载、空、失败和重试状态；
- 搜索结果卡片与现有笔记详情、点赞和登录弹框的衔接；
- 用户搜索结果卡片及关注/取消关注；
- 他人公开主页及公开笔记列表；
- PostgreSQL `pg_trgm` 扩展、必要 GIN 索引和无损迁移；
- 搜索与公开主页 REST API、OpenAPI、单元、集成、组件和 Browser E2E。

### 3.2 本期不包含

- 视频发布、视频上传、视频存储、转码、封面提取或视频播放；
- 评论搜索；
- 话题模型、话题搜索或话题详情；
- 搜索联想、自动补全、搜索历史、热门搜索或热词推荐；
- 关键词高亮；
- 综合搜索 Tab；
- 高级筛选、用户自选排序、时间范围或频道筛选器；
- 他人收藏列表、他人点赞列表、关注列表或粉丝列表；
- 公开年龄或邮箱；
- 用户私信、用户举报、拉黑或屏蔽；
- Elasticsearch、OpenSearch、Meilisearch 或其他独立搜索服务；
- Redis 搜索缓存；
- 搜索行为驱动推荐算法。

## 4. 搜索入口与模态框

### 4.1 入口

- 首页和当前用户个人主页现有顶部搜索占位改为真实搜索按钮；
- 搜索结果页和他人公开主页也提供同一共享搜索入口；
- 搜索入口的默认文案改为“搜索感兴趣的内容”；
- 搜索结果页入口展示当前关键词；
- 点击入口只打开模态框，不在该次点击时改变 URL 或离开当前页面。

### 4.2 模态框结构

- 模态框采用小蓝书蓝色作为主操作色，整体视觉参考当前小红书和抖音 Web 搜索入口的信息层级，但不得复制其商标、文案、素材或具体品牌表达；
- 模态框位于整个页面的顶部区域并相对完整视口水平居中，顶部保留合理呼吸空间；不得相对右侧主内容区、搜索栏容器或其他局部区域居中；
- 模态框采用自适应宽版对话框，包含搜索输入框、搜索按钮和关闭按钮；
- 打开后焦点进入搜索输入框；
- 从搜索结果页打开时预填当前关键词，其他页面默认空白；
- 模态框不展示搜索结果、搜索历史、热门词或联想列表；
- 输入期间不自动发送搜索请求；
- 按 Enter 或点击搜索按钮提交；
- 点击关闭按钮、点击遮罩或按 Esc 均关闭模态框且不执行搜索；
- 关闭后焦点返回触发搜索入口；
- 模态框自身不产生无意义滚动，页面根元素不得因模态框打开出现假滚动或布局抖动。

### 4.3 提交行为

- 关键词先去除首尾空白并规范连续空白；
- 有效关键词提交后立即关闭模态框并导航到搜索结果页；
- 默认进入【笔记】Tab；
- URL 使用：

```text
/search?keyword=<URL 编码关键词>&type=note
```

- 空关键词不导航、不请求，并在模态框内提示“请输入搜索内容”；
- 超过长度限制的关键词不导航、不请求，并在模态框内提示明确限制；
- 关闭模态框不保存历史记录，也不改变当前页面。

## 5. 关键词规则

- 去除首尾空白后长度必须为 `1～50` 个 Unicode 字符；
- 连续空白按一个分隔符处理；
- 按空白拆分为多个关键词；
- 重复关键词去重；
- 多关键词采用 AND 语义：每个关键词都必须至少命中该结果的一个允许搜索字段；
- 单个关键词可以命中不同字段，例如一个关键词命中作者昵称、另一个命中标题；
- 中文使用子串匹配；
- 英文匹配不区分大小写；
- `%`、`_`、反斜线和其他模式字符按普通用户文本安全处理，不允许改变查询结构；
- 所有查询必须参数化，不得拼接未经处理的 SQL；
- 关键词不得写入应用错误日志、分析日志或服务器异常响应；本期不建立搜索行为采集。

## 6. 搜索结果页

### 6.1 页面结构

- 搜索结果页保留现有左侧全局菜单和顶部操作区；
- 主内容区不显示首页频道栏；
- 主内容区显示当前搜索关键词和【笔记】【视频】【用户】三个 Tab；
- 选中 Tab 使用小蓝书蓝色和非颜色辅助状态表达；
- Tab 支持鼠标、Enter、Space、左右方向键、Home 和 End；
- 切换 Tab 保留关键词，并更新 URL 的 `type`：
  - `note`
  - `video`
  - `user`
- 浏览器刷新后根据 URL 恢复关键词、选中 Tab 和对应结果；
- 浏览器前进、后退能够恢复对应搜索状态；
- 缺失或非法 `type` 安全回退到 `note`；
- 缺失或无效关键词时不发起搜索，显示引导用户重新搜索的空白状态。

### 6.2 笔记 Tab

- 只展示当前系统支持的图片笔记；
- 结果继续使用现有笔记卡片和瀑布流；
- 卡片展示封面、标题、作者和真实点赞数据；
- 点击卡片进入现有笔记详情；
- 点击点赞区域不触发卡片导航；
- 未登录点击点赞打开现有邮箱登录弹框，并按 SPEC-007 规则恢复一次互动；
- 有效会话返回当前用户点赞状态和可点赞状态；
- 无效或过期会话不得阻断公开搜索结果。

### 6.3 视频 Tab

- 【视频】Tab 是正式可选择、可刷新和可由 URL 恢复的分类；
- 由于当前项目没有视频发布和视频数据，本期固定显示“暂无视频内容”；
- 不生成演示视频、伪造视频记录或把图片笔记伪装为视频；
- 不因空结果提示“功能开发中”；
- 未来视频功能必须通过新的 Spec 接入真实查询，不在本 Spec 预先实现媒体模型。

### 6.4 用户 Tab

- 采用纵向用户列表，不使用笔记瀑布流；
- 每个用户卡片展示：
  - 头像；
  - 昵称；
  - 小蓝书号；
  - 粉丝数；
  - 公开笔记数；
  - 关注或已关注按钮；
- 不展示邮箱、年龄、登录时间或其他私密字段；
- 点击用户卡片进入他人公开主页；
- 当前用户点击自己的搜索结果时进入 `/profile`；
- 当前用户自己的结果不显示关注按钮；
- 未登录点击关注时打开现有邮箱登录弹框；
- 登录后关注意图按 SPEC-007 的幂等规则只执行一次；
- 搜索结果中的关注状态与笔记详情及公开主页一致。

## 7. 搜索字段与排序

### 7.1 笔记搜索字段

每个关键词可以匹配：

- 笔记标题；
- 笔记正文；
- 作者昵称；
- 笔记所属公开频道名称。

不匹配：

- 评论；
- 邮箱；
- 小蓝书号；
- 媒体文件名或对象 Key；
- 隐藏的内部频道字段；
- 点赞、收藏或关注数据。

### 7.2 笔记排序

结果采用确定性分级排序：

1. 完整标题与完整规范化关键词相同；
2. 标题包含全部关键词；
3. 标题命中部分关键词，其他关键词由正文、作者昵称或频道名称补足；
4. 全部关键词只由正文、作者昵称或频道名称补足。

同一等级内按 `createdAt DESC, id DESC` 稳定排序。

分页游标必须包含足以恢复排序位置的信息，不得因为加载下一页产生重复、遗漏或顺序跳动。

### 7.3 用户搜索字段与排序

用户搜索只匹配：

- 昵称；
- 小蓝书号。

排序等级为：

1. 昵称完全匹配；
2. 昵称包含全部关键词；
3. 小蓝书号匹配。

同一等级内使用稳定、不可随机的次级排序；实现可以使用创建时间和用户 ID，但不得使用邮箱。

## 8. 分页、加载与错误状态

- 笔记和用户结果均使用游标分页；
- 默认每页 `20` 条；
- 客户端允许的单页上限为 `50` 条；
- 加载更多沿用现有信息流的自动加载模式；
- 新关键词或切换 Tab 时取消不再需要的旧请求；
- 旧请求晚于新请求返回时不得覆盖当前关键词或当前 Tab 的结果；
- 首次搜索和切换分类展示稳定骨架屏；
- 骨架屏在请求开始后至少稳定显示约 `300ms`，避免空结果时一闪而过；
- 已有结果加载更多时保留已加载内容；
- 空结果：
  - 笔记或用户：`没有找到与“关键词”相关的内容`
  - 视频：`暂无视频内容`
- 首次加载失败显示“搜索失败，请稍后重试”和【重新加载】；
- 加载更多失败保留已有结果，并提供局部重试；
- 重试必须使用当前关键词、分类和游标；
- 错误状态不得泄露 SQL、索引、堆栈、邮箱、Cookie 或内部对象 Key。

## 9. 他人公开主页

### 9.1 路由与访问

- 路由使用 `/users/:userId`；
- 未登录用户可以访问；
- 不存在的用户返回稳定 `404` 页面或等价安全状态；
- 当前用户访问自己的用户路由时跳转到 `/profile`；
- 从搜索结果进入公开主页后，浏览器返回应恢复原搜索关键词和 Tab。

### 9.2 公开资料

公开主页展示：

- 头像；
- 昵称；
- 小蓝书号；
- 性别；
- 关注数；
- 粉丝数；
- 获赞与收藏；
- 关注或已关注按钮；
- 该用户发布的公开笔记。

明确不展示：

- 邮箱；
- 年龄；
- 登录时间；
- 收藏笔记；
- 点赞笔记；
- 会话或认证信息。

### 9.3 内容与互动

- 公开主页只提供【笔记】一个 Tab；
- 当前阶段展示该用户的图片笔记；
- 未来真实视频功能建立后，可以由后续 Spec 扩展同一公开内容列表；
- 笔记按发布时间倒序并使用现有卡片、游标和加载状态；
- 没有笔记时显示“还没有发布笔记”；
- 未登录点击关注打开现有邮箱登录弹框；
- 登录用户可以关注和取消关注；
- 关注自己被服务端拒绝，界面不提供伪可用按钮；
- 关注状态和统计更新必须以服务端结果为准。

## 10. 数据与搜索技术

### 10.1 PostgreSQL 搜索基线

- PostgreSQL 是搜索数据的唯一真实来源；
- 启用可信扩展 `pg_trgm`；
- 为笔记标题、笔记正文和用户昵称建立适合 `LIKE/ILIKE` 包含搜索的 GIN trigram 索引；
- 小蓝书号保留现有唯一索引，并根据实际查询方式增加必要索引；
- 频道名称数据量小，可以使用直接关联匹配；如实现增加 trigram 索引，必须有查询计划依据；
- 不复制业务数据到 Redis；
- 不引入搜索服务、消息队列或异步索引同步。

### 10.2 迁移规则

- 迁移使用 `CREATE EXTENSION IF NOT EXISTS pg_trgm` 或等价幂等方式；
- 空数据库可以安全执行；
- 含既有用户、频道、笔记、媒体和互动的数据可以无损执行；
- 迁移不得改写现有标题、正文、昵称、小蓝书号或频道名称；
- 索引建立失败必须使迁移明确失败，不得静默退化；
- 开发、测试、CI 和生产 PostgreSQL 环境都必须支持该扩展；
- 回滚或后续替换搜索方案时不得破坏原始业务数据。

### 10.3 查询要求

- 搜索 SQL 必须参数化；
- 避免为每张结果卡片单独查询作者、频道、点赞或统计；
- 用户搜索的粉丝数和笔记数不得形成无界 N+1；
- 搜索只选择页面需要的公开字段；
- 支持稳定游标，不使用无界 Offset 作为主要分页方式；
- 不以随机数、客户端排序或前端过滤替代服务端真实搜索。

## 11. API 契约

实际路径可以遵循现有 NestJS 模块约定，但必须提供以下语义：

### 11.1 搜索 API

- 搜索图片笔记：
  - 输入关键词、游标和每页数量；
  - 返回笔记卡片页、下一页游标和当前用户点赞状态；
- 搜索视频：
  - 当前返回空分页结果；
  - 不返回伪造数据；
- 搜索用户：
  - 输入关键词、游标和每页数量；
  - 返回公开用户卡片、粉丝数、笔记数和当前用户关注状态。

### 11.2 公开用户 API

- 读取指定用户公开资料和统计；
- 分页读取指定用户公开笔记；
- 关注写操作继续使用 SPEC-007 已有接口，不建立第二套关注语义。

### 11.3 错误语义

- 空或超过长度的关键词：`400`；
- 非法或不属于当前查询的游标：`400`；
- 用户不存在：`404`；
- 公开读取无须登录；
- 关注写操作无会话：`401`；
- 关注自己：沿用 SPEC-007 的稳定 `4xx` 业务错误；
- 服务端错误使用项目统一安全响应结构。

所有新增和扩展接口必须生成与实际响应一致的 OpenAPI schema。

## 12. 视觉与交互参考

- 搜索结果页的信息架构参考当前小红书和抖音 Web 搜索页的共同规律：
  - 固定全局导航；
  - 顶部保留当前查询；
  - 水平分类 Tab；
  - 内容结果与用户结果使用不同列表形态；
- 本项目只借鉴布局和交互规律；
- 不复制第三方 Logo、商标、图片、用户内容、文案、图标资产或源代码；
- 主色沿用小蓝书蓝色；
- 搜索结果页不显示第三方页面的登录限制，本项目按已确认规则允许匿名搜索；
- 参考地址：
  - `https://www.xiaohongshu.com/search_result/`

## 13. 自适应布局与滚动

- 支持 `960×600` 及以上连续桌面视口；
- 不为少量固定宽高组合编写页面专用高度补丁；
- 搜索模态框在支持范围内完整可见，必要内容滚动属于模态框内部；
- 模态框打开时锁定背景滚动，关闭后恢复原位置；
- 搜索结果页内容不足一屏时不产生无意义根元素滚动条；
- 结果自然超过视口时只产生一个明确的页面滚动容器；
- 用户列表和笔记瀑布流不得形成双重滚动；
- 公开主页只有一行笔记时不产生假滚动，进入后续行时可自然滚动；
- 低于最低支持范围时仍保证输入、关闭、Tab、结果和关注操作可访问。

## 14. 可访问性

- 搜索入口是具有明确名称的按钮；
- 搜索模态框具有 `dialog` 语义、可感知标题和模态属性；
- 打开时焦点进入输入框，关闭后返回触发按钮；
- Tab 使用正确 `tablist`、`tab`、`tabpanel` 语义；
- 搜索按钮、关闭、重试、关注和加载更多均可由键盘操作；
- 当前 Tab、关注状态和加载状态不能只用颜色表达；
- 骨架屏和异步结果使用适当的 busy/status 语义，但不得频繁打断辅助技术；
- 错误提示与对应输入或结果区域建立可理解关联；
- 用户头像和笔记封面具有合理替代文本或明确装饰属性。

## 15. 安全与隐私

- 匿名搜索响应不得包含邮箱、年龄、登录时间、会话标识或内部凭据；
- 用户搜索和公开主页不得支持通过邮箱反查用户；
- 小蓝书号是已确认的公开稳定标识；
- 搜索关键词按普通文本处理，防止 SQL 注入和模式字符滥用；
- 搜索接口需要基本的请求频率保护或复用现有公共读取限流边界；
- 不把搜索关键词写入包含用户身份的长期日志；
- 媒体响应继续只暴露稳定公开 URL，不暴露服务器路径和对象 Key；
- 过期或伪造 Cookie 不得让公开搜索整体返回 `401`。

## 16. 性能与一致性

- `pg_trgm` GIN 索引必须实际存在并能被代表性包含查询使用；
- 搜索结果分页不得随加载产生重复或遗漏；
- 搜索结果、笔记详情和公开主页的点赞、关注及统计状态保持一致；
- 快速连续提交不同关键词时，只展示最新查询；
- 切换 Tab 时取消或忽略过期请求；
- 不要求本期建立生产级搜索延迟 SLA，但必须通过代表性数据验证查询不会退化为明显无界 N+1；
- 若未来真实数据证明 PostgreSQL 搜索成为瓶颈，再根据决策记录复审独立搜索服务。

## 17. 验收标准

### AC-001：搜索迁移与索引

- 空库和含既有数据的数据库均可执行迁移；
- `pg_trgm` 扩展和必要 GIN 索引实际存在；
- 既有用户、频道、笔记、媒体和互动数据不变；
- 代表性标题、正文和昵称包含查询具有可验证的索引能力。

### AC-002：搜索模态框

- 首页、个人页、搜索页和公开主页入口均打开共享模态框；
- 点击入口本身不导航；
- Enter 和搜索按钮提交有效关键词后关闭模态框并进入结果页；
- 空值和超长值不请求、不导航并显示准确错误；
- 关闭按钮、遮罩和 Esc 正常工作，焦点正确进入和恢复；
- 模态框相对完整页面在顶部水平居中，不得落在右侧内容区域的局部中心；
- 背景无滚动抖动或假滚动。

### AC-003：笔记搜索

- 标题、正文、作者昵称和频道名称均可命中图片笔记；
- 多关键词使用 AND 语义；
- 中文子串和英文大小写不敏感匹配正确；
- 不匹配评论、邮箱和内部媒体字段；
- 匿名、有效会话和无效会话下的公开结果边界正确。

### AC-004：排序与分页

- 标题完全匹配、标题包含和其他字段命中的优先级符合规则；
- 同等级按发布时间和 ID 稳定倒序；
- 每页默认 `20` 条并使用游标；
- 加载多页没有重复、遗漏或顺序跳动；
- 非法游标返回安全 `400`。

### AC-005：搜索结果页面

- URL 可以恢复关键词和【笔记】【视频】【用户】Tab；
- 切换 Tab 保留关键词并更新 URL；
- 笔记结果复用现有卡片、详情和点赞交互；
- 不显示首页频道栏；
- 前进、后退和刷新行为稳定；
- 新旧请求竞争时只保留最新结果。

### AC-006：视频空分类

- 【视频】Tab 可选择、可刷新、可由 URL 恢复；
- 稳定显示“暂无视频内容”；
- 不出现图片冒充视频、演示数据或“功能开发中”提示；
- 本期没有视频上传、存储或播放实现。

### AC-007：用户搜索

- 昵称和小蓝书号可以命中；
- 排序优先级符合规则；
- 卡片显示头像、昵称、小蓝书号、粉丝数、笔记数和正确关注状态；
- 响应不包含邮箱和年龄；
- 点击他人进入公开主页，点击自己进入 `/profile`。

### AC-008：他人公开主页

- 匿名用户可访问存在的公开主页；
- 展示已确认公开字段、真实统计和公开笔记；
- 不展示邮箱、年龄、收藏或点赞列表；
- 不存在用户显示安全 `404`；
- 自己的公开路由转到 `/profile`；
- 返回后恢复原搜索状态。

### AC-009：关注闭环

- 用户搜索结果和公开主页可以关注、取消关注；
- 未登录操作打开现有邮箱登录弹框；
- 登录后意图只恢复一次；
- 关注状态与详情、搜索结果和公开主页一致；
- 自关注无伪可用入口且服务端继续拒绝。

### AC-010：状态、失败与重试

- 骨架屏至少稳定展示约 `300ms`，不一闪而过；
- 笔记/用户无结果和视频空状态文案正确；
- 首次失败可重试；
- 加载更多失败保留已有结果并可局部重试；
- 重试使用当前关键词、Tab 和游标；
- 错误响应不泄露内部信息。

### AC-011：布局与可访问性

- `960×600` 及以上连续视口没有关键裁切、假滚动或双重滚动；
- 模态框、Tab、结果、关注和重试可由键盘与辅助技术操作；
- 当前 Tab、关注和加载状态不只依赖颜色；
- 公开主页一行内容无假滚动，后续行可自然滚动；
- 搜索结果足够多时只有一个明确页面滚动容器。

### AC-012：回归、OpenAPI 与自动化

- 搜索、公开主页、隐私、排序、游标和请求竞争具有自动化覆盖；
- OpenAPI 与实际响应一致；
- 首页、频道、登录、发布、详情、当前用户个人页和社交互动无回归；
- 初次实施运行相关 Chromium Browser E2E；
- 初次独立验收运行一次完整 Browser E2E；
- 格式、Lint、类型、数据库校验、单元/集成测试和构建通过。

## 18. 风险与防护

- `pg_trgm` 需要数据库扩展权限，实施前必须在现有 PostgreSQL 18 Docker 环境验证；
- 多字段 AND 匹配和排序可能产生复杂 SQL，必须使用参数化查询并检查代表性查询计划；
- 用户统计不能为每个结果逐条查询；
- 搜索模态框应抽取为共享组件，避免首页、个人页和搜索页行为分叉；
- 公开主页必须使用明确公开 DTO，禁止直接返回 User 数据模型；
- 视频 Tab 只保留正式空状态，禁止顺手扩大为视频系统；
- 不因参考第三方页面而复制其素材、登录限制或未确认功能。
