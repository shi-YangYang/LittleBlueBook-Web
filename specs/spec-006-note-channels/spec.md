## 1. 背景

首页当前显示“推荐、数码、汽车……”等频道按钮，但除“推荐”外均为不可用占位。笔记发布流程也没有频道字段，后端无法按频道筛选内容。

本 Spec 建立频道数据、发布选择、首页筛选、URL 状态、分页和详情展示的完整闭环。“推荐”继续作为全站公开笔记聚合入口，不实现推荐算法。

## 2. 已确认目标

- 登录用户发布笔记时必须选择一个频道；
- 每篇笔记只能属于一个频道；
- 首页点击具体频道后只展示该频道的笔记；
- “推荐”展示所有公开笔记，包括历史未分类笔记；
- 频道状态写入 URL，刷新、复制链接和浏览器前进后退均可恢复；
- 个人主页继续展示当前用户的全部笔记；
- 笔记详情展示新笔记所属频道；
- 使用数据库频道表管理稳定代码、中文名称、顺序和状态；
- 本期新增“其它”频道，不提供“视频”频道。

## 3. 范围

### 3.1 本期包含

- 频道数据表、系统频道种子和数据库迁移；
- 笔记与频道的一对多关系；
- 历史笔记回填内部未分类频道；
- 公开频道列表接口；
- 发布接口频道校验和持久化；
- 发布页频道单选交互；
- 首页推荐聚合信息流；
- 首页频道导航、频道深链接和频道信息流；
- 频道信息流的游标分页、加载、空状态、错误和重试；
- 笔记详情频道标签；
- 个人主页全部笔记回归；
- OpenAPI、单元、集成、迁移和 Browser E2E。

### 3.2 本期不包含

- 频道管理后台；
- 用户创建、修改、排序、启用或停用频道；
- 一篇笔记选择多个频道；
- 用户关注频道；
- 频道封面、简介、运营位、榜单或推荐算法；
- 按频道筛选个人主页笔记；
- 首页卡片展示频道标签；
- 修改历史未分类笔记的频道；
- 视频发布或“视频”频道；
- 话题功能；
- 笔记编辑、删除、审核、私密发布或可见性系统。

## 4. 频道定义

### 4.1 推荐

- “推荐”是虚拟聚合入口，不是数据库频道；
- 发布者不能选择“推荐”；
- 推荐信息流继续使用现有公开推荐接口和发布时间倒序；
- 推荐包含所有公开笔记，不因频道启用或停用而隐藏既有笔记；
- 推荐包含迁移后的历史未分类笔记；
- 本期不增加热度、随机、兴趣或个性化算法。

### 4.2 公开频道

公开频道顺序固定为：

| 顺序 | 稳定代码 | 中文名称 |
| --- | --- | --- |
| 1 | `digital` | 数码 |
| 2 | `automotive` | 汽车 |
| 3 | `gaming` | 游戏 |
| 4 | `sports` | 运动 |
| 5 | `fitness` | 健身 |
| 6 | `outdoors` | 户外 |
| 7 | `fashion` | 穿搭 |
| 8 | `food` | 美食 |
| 9 | `workplace` | 职场 |
| 10 | `relationships` | 情感 |
| 11 | `home` | 家居 |
| 12 | `travel` | 旅行 |
| 13 | `other` | 其它 |

规则：

- 稳定代码作为数据库、API 和 URL 身份，中文名称只用于展示；
- 本期所有公开频道均启用且可发布；
- “其它”与其他公开频道行为一致，用于无法明确归类的笔记；
- “视频”从首页频道导航移除，也不出现在发布选择中。

### 4.3 内部未分类频道

- 系统创建稳定代码为 `uncategorized` 的内部频道；
- 中文内部名称为“未分类”，但本期不面向普通用户展示；
- 该频道不出现在公开频道接口、首页导航和发布选择中；
- 所有 SPEC-006 上线前的既有笔记迁移到该频道；
- 历史未分类笔记继续出现在推荐和发布者个人主页；
- 历史未分类笔记详情不显示频道标签；
- 本期不提供重新分类入口。

## 5. 数据模型与迁移

频道至少包含：

- 唯一标识；
- 唯一、不可随展示文案改变的稳定代码；
- 中文名称；
- 唯一或稳定的显示顺序；
- 是否启用；
- 是否允许发布；
- 创建与更新时间。

笔记：

- 新增非空频道外键；
- 每篇笔记只关联一个频道；
- 频道与笔记采用限制删除或等价保护，不得因删除频道级联删除笔记；
- 增加适合频道筛选和倒序游标分页的组合索引；
- 保留现有作者、发布时间和幂等发布约束。

迁移必须：

- 在空数据库中安全创建全部系统频道；
- 在含既有笔记的数据库中先创建内部未分类频道并完成回填，再建立非空外键；
- 不修改既有笔记 ID、作者、标题、正文、图片、发布时间或幂等键；
- 可以安全执行一次，且频道种子初始化可重复执行而不产生重复数据；
- 验证公开频道代码、顺序和内部频道状态符合本 Spec。

## 6. 公开频道接口

- 提供无需登录的公开频道列表接口；
- 只返回启用且面向普通用户的频道；
- 返回稳定代码、中文名称和显示顺序；
- 按显示顺序升序返回；
- 不返回内部数据库 ID、内部未分类频道或不必要的管理字段；
- 频道读取失败使用项目统一错误结构，不泄漏数据库信息。

频道列表是首页导航和发布选择的共同权威来源，前端不得分别维护两套可能不一致的频道数组。

## 7. 发布流程

### 7.1 发布页交互

- 在正文区域下方、“添加话题”上方增加“选择频道”字段；
- 字段使用清晰的单选语义，初始不默认选中任何频道；
- 用户点击后打开频道选择面板；
- 面板只展示公开、启用且可发布的频道，并按服务端顺序排列；
- 选择后字段展示当前频道中文名称，用户可以在发布前更换；
- 频道列表加载期间展示稳定加载状态；
- 加载失败时显示“频道加载失败，请重试”和重试操作；
- 未选择频道时发布按钮不可用，并提供可理解的必填提示；
- “其它”可正常选择；
- “推荐”“未分类”和“视频”不得出现在选择面板。

### 7.2 可访问性

- 频道字段和选择面板可以通过键盘完成打开、移动、选择和关闭；
- 使用 `radiogroup`/`radio`、`listbox`/`option` 或语义等价实现；
- 当前选项向辅助技术暴露选中状态；
- Escape 可以关闭选择面板，并把焦点返回触发按钮；
- 错误提示与字段建立可访问关联；
- 不能只依赖颜色表示当前频道。

### 7.3 发布与会话边界

- 发布 multipart 请求新增必填 `channelCode`；
- 服务端按稳定代码查找频道；
- 不存在、停用、内部或不可发布频道统一拒绝，使用明确的 `4xx` 业务错误；
- 频道校验必须在创建笔记前完成；
- 会话失效触发重新认证时，已选择频道与标题、正文、图片一并保留；
- 重新认证成功后可以继续原发布流程；
- 同一用户、同一 `clientRequestId` 重试时返回第一次成功创建的笔记，不得因后续请求传入不同频道而修改原笔记；
- 发布成功后进入详情页，详情展示已持久化频道。

## 8. 首页频道导航

### 8.1 导航与 URL

- 首页频道顺序为“推荐”加第 4.2 节公开频道；
- 点击“推荐”时 URL 为 `/`；
- 点击具体频道时 URL 为 `/?channel={稳定代码}`；
- 当前频道具有清晰选中态；
- 切换频道立即重置当前列表、游标和错误状态，再加载目标频道第一页；
- 刷新、直接打开链接、复制链接和浏览器前进后退均恢复 URL 对应频道；
- 切换频道不打开“功能正在开发中”提示；
- “视频”不再显示。

### 8.2 无效频道 URL

- URL 包含未知、内部、停用或不可公开的频道代码时，不得静默展示其他频道的数据；
- 页面显示“频道不存在或已停用”；
- 提供“返回推荐”操作并清除无效频道参数；
- 不向用户暴露内部频道或数据库信息。

### 8.3 频道信息流

- 频道信息流无需登录即可访问；
- 只返回频道代码完全匹配的笔记；
- 按 `createdAt DESC, id DESC` 稳定排序；
- 沿用现有游标分页和每页数量边界；
- 游标不能用于跨频道继续分页；服务端应将频道身份纳入游标校验或使用等价方式防止混用；
- 切换频道时不得保留上一频道的卡片或下一页游标；
- 新发布笔记回到对应频道后应出现在该频道列表顶部，也应出现在推荐顶部。

## 9. 状态与错误处理

频道导航：

- 频道列表加载时保持布局稳定；
- 频道列表加载失败时显示错误和重试，不伪造本地频道列表；
- 公开频道为空属于配置错误，提供稳定错误状态。

频道笔记：

- 首次加载使用现有信息流加载状态；
- 每次进入或切换频道时，首屏骨架状态至少展示 `300ms`；接口在 `300ms` 内快速返回空数据或错误时，也不得出现单帧闪烁；
- 接口自身耗时超过 `300ms` 时，不再额外叠加固定等待时间；
- 没有笔记时显示“该频道还没有笔记”；
- 首次加载失败显示“频道内容加载失败，请稍后重试”并提供重试；
- 加载更多失败保留已加载内容和当前频道，并允许重新加载；
- 切换频道应取消或忽略旧请求结果，避免旧频道数据覆盖新频道。

发布页：

- 频道加载失败不影响已填写标题、正文和图片；
- 发布接口返回频道错误时保留全部草稿并提示重新选择；
- 服务端内部错误不得显示原始数据库信息。

## 10. 推荐、个人主页与详情

### 10.1 推荐

- 推荐继续展示所有公开笔记；
- 新增频道不改变推荐的排序、分页和公开访问规则；
- 历史未分类笔记继续展示；
- 推荐卡片本期不增加频道标签。

### 10.2 个人主页

- “我 → 笔记”继续展示当前用户全部笔记；
- 不按频道过滤，也不新增频道筛选控件；
- 公开频道、其它频道和历史未分类笔记均可展示；
- 卡片本期不增加频道标签。

### 10.3 笔记详情

- 新发布笔记详情展示频道中文名称标签；
- 标签使用服务端返回的频道信息，不根据 URL 或前端数组推断；
- 点击标签进入该频道首页深链接；
- 历史内部未分类笔记不展示频道标签；
- 频道停用后，既有笔记详情仍可访问，但频道标签不可继续导航到已停用频道；可以只展示名称或隐藏导航能力；
- 不展示稳定代码、数据库 ID 或内部频道状态。

## 11. API 与数据安全

- 发布接口仍依赖服务端会话认证；
- 频道列表、推荐、频道信息流和笔记详情保持公开；
- 未登录用户必须能够加载公开频道列表，频道读取不得依赖会话 Cookie；
- 本地非生产环境同时允许配置的回环前端来源及其 `localhost`/`127.0.0.1` 等价来源，避免浏览器因开发地址别名阻止公开频道请求；
- 生产环境仍只允许明确配置的前端来源，不得因本地兼容规则扩大跨域范围；
- 客户端不能通过提交数据库频道 ID 绕过频道状态校验；
- 服务端忽略或拒绝额外的内部状态字段；
- 频道筛选必须在数据库查询中完成，不能获取全部笔记后由前端过滤；
- 频道代码长度和字符集受约束，未知值返回安全业务错误；
- 频道游标、推荐游标和个人页游标不得错误混用；
- OpenAPI 同步频道列表、发布字段、频道信息流和详情返回结构；
- 日志不得记录 Cookie、SMTP 凭据或不必要的用户数据。

## 12. 性能与一致性

- 频道信息流查询使用频道、创建时间和 ID 的组合索引；
- 频道列表数据量小，本期不引入 Redis 缓存；
- 切换频道不会并发追加上一频道分页结果；
- 推荐和频道信息流对同一笔记使用相同卡片结构；
- 发布事务必须保证笔记、频道关系和图片元数据一致创建；
- 发布失败时沿用现有媒体清理规则，不遗留孤立文件。

## 13. 兼容性与回归

- 保留 SPEC-002 的登录、注册、会话恢复和重新认证；
- 保留 SPEC-003 的个人主页和全部笔记展示；
- 保留 SPEC-004 的图片、标题、正文、发布幂等、推荐、详情和本地媒体规则；
- 保留 SPEC-005 的自适应高度和滚动模型；
- 不新增依赖；
- 普通频道业务回归以 Chromium 为主；
- Firefox 和 WebKit 重点验证频道选择面板、URL 前进后退和切换频道时的请求竞态；
- Browser E2E 不进入常规 CI。

## 14. 测试策略

按照决策 0004 分层验证：

- 实施过程：频道数据、迁移、发布校验、筛选和前端状态的定向测试；
- 初次实施交付：格式、Lint、类型、单元/集成测试、构建及频道相关 Browser E2E，不运行完整 Browser E2E；
- 初次独立验收：独立迁移验证、AC-001 至 AC-012 关键检查，并运行一次完整 Browser E2E；
- 若发生小范围返工：只验证历史失败项和受影响回归，除非风险升级；
- 所有未运行项按分层策略如实记录。

## 15. 验收标准

### AC-001：频道数据与公开列表

- 数据库存在 13 个公开频道和 1 个内部未分类频道；
- 稳定代码、中文名称、顺序、启用和可发布状态正确；
- 公开接口只返回 13 个公开频道并按顺序排列；
- “推荐”“未分类”和“视频”不出现在公开列表。

### AC-002：迁移与完整性

- 空数据库和含既有笔记的数据库均可安全迁移；
- 所有既有笔记关联内部未分类频道，其他字段不变；
- 笔记频道外键非空，删除频道不能级联删除笔记；
- 频道筛选和分页索引存在；
- 系统频道初始化重复执行不会产生重复记录。

### AC-003：发布页频道选择

- 发布页在正文和话题占位之间展示必填频道字段；
- 不默认选择频道；
- 面板只显示 13 个公开可发布频道，“其它”可选；
- 键盘、Escape、焦点恢复和选中语义正确；
- 加载、失败、重试和必填提示符合 Spec。

### AC-004：发布校验与幂等

- 未选择频道不能发布；
- 有效频道随 multipart 请求提交并正确持久化；
- 未知、停用、内部或不可发布频道被服务端拒绝；
- 401 重新认证保留已选频道和全部草稿；
- 同一幂等请求不会因重试参数变化修改原笔记；
- 发布失败沿用媒体清理规则。

### AC-005：推荐聚合

- 推荐展示所有公开频道、其它频道和历史未分类笔记；
- 推荐保持公开访问、倒序和游标分页；
- 新发布笔记出现在推荐顶部；
- 推荐卡片不新增频道标签。

### AC-006：首页频道导航与 URL

- 导航顺序为推荐加 13 个公开频道；
- 频道点击不再显示开发中提示；
- 推荐对应 `/`，具体频道对应 `/?channel={code}`；
- 刷新、直达、复制链接和前进后退恢复频道及选中态；
- “视频”不显示；
- 无效或停用频道显示错误和返回推荐操作。

### AC-007：频道信息流

- 具体频道只展示属于该频道的笔记；
- 排序和游标分页稳定；
- 跨频道游标被拒绝或不能产生错误数据；
- 切换频道不会混入上一频道的卡片、错误或游标；
- 空状态、首次失败、重试和加载更多失败符合 Spec；
- 新笔记出现在所属频道顶部。

### AC-008：个人主页与详情

- 个人主页继续展示当前用户全部笔记，不按频道过滤；
- 新笔记详情展示正确频道标签并可进入对应频道；
- 历史未分类笔记详情不展示频道标签；
- 卡片不新增频道标签；
- 停用频道不会导致既有笔记详情不可访问。

### AC-009：安全与公开边界

- 发布仍要求有效会话；
- 频道列表和频道信息流公开可访问；
- 客户端不能提交数据库 ID 或内部状态绕过校验；
- 内部频道和数据库字段不通过公开接口泄漏；
- 错误结构不包含数据库细节或凭据。

### AC-010：性能与一致性

- 频道查询使用合适组合索引；
- 笔记、频道和图片元数据保持一致；
- 发布失败不遗留孤立媒体；
- 并发切换频道不会由旧请求覆盖当前频道；
- 不引入无依据的 Redis 缓存或新依赖。

### AC-011：兼容性与回归

- 认证、重新认证、个人主页、发布、推荐、详情、返回滚动恢复和自适应布局不回归；
- Chromium 完成频道完整业务流；
- Firefox 和 WebKit 的频道面板、URL 历史和请求切换关键场景通过；
- 普通 CI 范围不改变。

### AC-012：自动化与文档

- 数据迁移、频道服务、发布校验、频道筛选、游标隔离和前端状态具有自动化覆盖；
- OpenAPI 与实际接口一致；
- 频道相关 E2E 纳入版本控制；
- 实施和验收遵守分层验证策略并如实记录未运行项；
- 格式、Lint、类型、单元/集成测试和构建通过；
- 初次独立验收完成一次完整 Browser E2E。

## 16. 风险与防护

- 迁移必须先回填频道再建立非空约束，避免已有笔记迁移失败；
- 频道身份使用稳定代码，不使用可变中文名称；
- 推荐与具体频道查询不能共享缺少频道身份的游标；
- 前端切换频道时必须防止异步竞态；
- 发布选择不能在重新认证后丢失；
- 数据库频道表不代表本期授权开发管理后台；
- 不得因为“其它”存在而自动把未知频道代码映射到其它。
