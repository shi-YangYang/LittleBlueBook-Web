# SPEC-016 实施计划

- Spec：`specs/spec-016-following-feed-and-social-graph/spec.md`
- 当前 Spec 状态：Accepted
- 计划状态：Completed
- 负责人：协调开发 Agent
- 实施约束：只有用户确认完整 Spec 后才能创建一个新的单一实施 Agent；数据库、后端、前端和 E2E 必须由同一 Agent 串行完成；实施 Agent 不得创建子 Agent。

## 1. 实施目标

- 在首页建立可恢复 URL 状态的关注信息流；
- 复用现有笔记卡片展示关注账号全部可见图文和视频；
- 将当前用户私有关注列表扩展为自己与他人的公开关注/粉丝列表；
- 建立关注、回关、取消关注、互关状态和权威统计联动；
- 统一拉黑、封禁、年龄限制和治理过滤；
- 保持现有通知与互关私信语义不回归。

## 2. 预计影响范围

### 数据库

- 复用 `UserFollow` 关系和 `createdAt`；
- 审查粉丝侧稳定排序查询计划，必要时新增兼容复合索引；
- 不改写历史关系、通知、会话或笔记数据。

### 后端

- Notes 关注信息流接口、过滤、游标和 OpenAPI；
- Profile/Search 或独立用户关系模块的公开关注、粉丝列表；
- 统一关系项 DTO、查看者关系状态和互关状态；
- 当前用户/公开主页统计使用相同可见性口径；
- 现有关注写接口的权威统计响应、通知和私信回归；
- Safety 过滤、会话切换和并发测试。

### 前端

- 首页【关注】Tab、`feed=following` 路由状态和登录门禁；
- 关注信息流骨架、双空状态、分页、失败保留和搜索入口；
- 抽象现有 `FollowingDialog` 为统一关系列表模态框；
- 当前用户粉丝入口与公开主页关注/粉丝入口；
- 用户行关注、回关、取消确认和互关标识；
- 统计同步、身份缓存隔离、焦点和滚动模型。

### E2E

- 新增 SPEC-016 永久 Chromium 主流程；
- Firefox/WebKit 只覆盖模态框焦点、URL 历史和滚动差异；
- 迁移探针、拉黑/封禁/恢复、通知和私信直接回归；
- 常规 CI 配置保持不变。

## 3. 实施阶段

### 阶段 A：查询协议与索引

1. 定义关注信息流与公开关系分页 DTO、业务码和 OpenAPI；
2. 统一公开关系用户项和查看者状态结构；
3. 审查 `UserFollow` 两个方向的查询计划；
4. 必要时增加粉丝侧复合索引及历史兼容迁移；
5. 补空库和 SPEC-015 历史库迁移探针。

### 阶段 B：关注信息流后端

1. 实现认证门禁和 `following` 范围游标；
2. 使用数据库联结过滤有效关注作者和可见笔记；
3. 复用现有卡片映射、互动状态和媒体权限；
4. 覆盖历史笔记、编辑不置顶、取消/重关注和分页并发；
5. 补游标篡改、跨用户复用、拉黑、封禁和隐藏测试。

### 阶段 C：公开关系列表后端

1. 抽取统一关系查询服务；
2. 实现自己与公开用户的关注/粉丝分页；
3. 批量映射公开资料、当前查看者关系和互关状态；
4. 统一统计的可访问过滤口径；
5. 处理匿名、登录、自身、不可访问所有者和并发关系变化。

### 阶段 D：关系写入联动

1. 复验关注/取消关注幂等和并发；
2. 返回足以更新当前用户统计的权威结果；
3. 保持关注通知、取消不通知和重新关注通知；
4. 复验互关私信发送资格与历史会话保留；
5. 复验拉黑原子删除关系和解除不恢复。

### 阶段 E：首页关注信息流

1. 增加【关注】并与推荐/频道互斥；
2. 实现 `feed=following`、刷新、前进和后退；
3. 未登录打开现有登录模态框，登录后原地加载；
4. 接入骨架、分页、失败保留、重试和两类空状态；
5. 处理退出、切换账号、会话失效和旧响应竞争。

### 阶段 F：统一关系列表模态框

1. 从现有关注模态框抽取 `following/followers` 和 `me/public` 模式；
2. 接入当前用户【我的粉丝】入口；
3. 接入公开主页【TA 的关注】【TA 的粉丝】入口；
4. 实现匿名登录触发、关注、回关、已关注和互关标识；
5. 实现取消确认、统计同步、错误保留、内部滚动与焦点恢复。

### 阶段 G：集成与验收准备

1. 更新永久单元/集成和 Browser E2E；
2. 验证迁移与查询计划；
3. 运行受影响 lint/typecheck、定向测试和生产构建；
4. 运行一次 Chromium SPEC-016 主流程；
5. 运行 Firefox/WebKit 差异场景；
6. 清理一次性产物并返回实施报告。

## 4. 数据与一致性重点

- 公开统计与列表使用同一过滤语义，避免数字泄露不可见关系；
- 关注信息流不能先无界加载全部关注账号或全部笔记；
- 游标必须绑定范围、所有者和查看者，不能跨上下文重放；
- 关系写入后的 UI 更新只是即时反馈，数据库仍是权威来源；
- 拉黑删除关系和封禁保留关系的语义必须区分；
- 退出或切换账号必须清除私人信息流和关系按钮状态。

## 6. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 公开关系列表泄露受限账号 | 后端统一可见性过滤并让统计共享口径 |
| 关注信息流随关系增长变慢 | 联结查询、稳定索引、20 条游标和查询计划验证 |
| 快速切换显示错人列表 | 请求键绑定所有者/类型，取消或忽略旧响应 |
| 退出后泄露私人信息流 | 会话变化清除私人缓存，未登录不请求接口 |
| 关系操作后多个页面状态不一致 | 即时同步已加载状态，重新加载以数据库为准 |
| 拉黑/封禁语义混淆 | 拉黑删除关系，封禁保留关系但过滤，分别测试恢复 |
| 取消关注破坏私信历史 | 只改变发送资格，不删除会话和消息 |
| 模态框造成双滚动 | 独立内部滚动并按 SPEC-005/014 验收 |

## 7. 实施交接门禁

- 用户已确认完整 Spec；实施、返工与独立验收已经按单 Agent 串行流程完成，当前状态为 `Accepted`；
- 实施阶段不运行完整 Browser E2E；首次独立验收只运行一次完整 Browser E2E，失败后仅在相关修改完成后复验历史失败项和受影响回归；
- 实施 Agent 不得创建子 Agent、改变关系公开范围、引入推荐算法或实时推送；
- 出现新的产品、隐私或数据保留决策时必须返回协调开发 Agent。
