# 代码与文件变更规则

## 范围

- 只修改任务明确授权的文件和必要的直接依赖。
- 不进行与任务无关的重构、格式化、重命名或依赖升级。
- 发现相邻问题时先报告，不擅自扩大范围。
- 不覆盖、删除或回滚用户及其他 Agent 的无关改动。

## 角色边界

- 协调开发 Agent 默认只修改治理文档、Spec、决策和协作材料。
- 实施 Agent 可以修改任务授权范围内的业务代码。
- 验收 Agent 不得修改业务代码。

## 实施要求

- 改动必须可追溯到已确认 Spec 或返工项。
- 优先使用项目现有模式和依赖。
- 新增依赖、公共接口、数据库结构或跨模块耦合前，检查是否需要决策。
- 错误处理、权限校验和输入边界不得因“正常路径可用”而省略。
- 不引入真实凭据、个人信息或不应进入仓库的运行数据。

## 工作区保护

- 开始前检查工作区状态。
- 将已有改动视为用户资产，除非任务上下文明确说明其来源。
- 修改与已有改动重叠时，保留其意图并在报告中说明。
- 未经明确授权，不执行清理、重置、强制覆盖或批量删除。

## 文档同步

当实现改变已确认的接口、配置、运行方式或用户可见行为时，应按任务授权同步相关文档。若文档变化意味着需求变化，必须先走决策和 Spec 重新确认流程。
