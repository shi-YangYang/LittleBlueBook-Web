# 决策与问题升级规则

## 核心原则

凡是存在不明确之处，且不同选择会实质影响实施结果、用户行为或验收结论，都不得在缺少依据时猜测。

## 决策权限

### 必须由用户确认

- 产品目标、范围、优先级和非目标；
- 用户体验和业务规则；
- 数据含义、权限模型和隐私边界；
- 验收标准及其取舍；
- 重要技术选型或不可逆变更；
- 破坏性操作、生产操作和外部发布；
- 预算、进度或兼容性方面的重要取舍。

### 协调开发 Agent 可以处理

- 不改变行为和验收结果的文字整理；
- 从已确认文件和代码现状中可以唯一推导的事实；
- 将用户已确认内容写入 Spec 或决策记录；
- 在授权范围内组织实施、验收和返工。

### 子 Agent 可以处理

- 已确认技术边界内的局部实现细节；
- 不影响外部行为、长期架构或验收口径的常规工程选择；
- 运行授权范围内的非破坏性检查。

子 Agent 对是否属于局部实现细节存在合理怀疑时，应升级给协调开发 Agent。

## 提问标准

协调开发 Agent 的问题应：

- 说明当前已知事实；
- 指出歧义为什么会影响实施；
- 提供可比较的选项和影响；
- 给出有依据的建议；
- 避免询问可从仓库直接查明的事实。

## 决策留痕

- 重要决定写入 `.ai/decisions/`；
- 功能特有决定同时更新相关 Spec；
- Constitution 级变化必须更新对应 Constitution 文件；
- 被替代的决定保留历史，并链接新记录。
