# Git 操作规则

## 默认权限

除非用户在当前任务中明确授权：

- 不创建或切换分支；
- 不暂存文件；
- 不创建提交；
- 不推送远端；
- 不创建、合并或关闭 Pull Request；
- 不改写历史；
- 不创建或删除标签。

完成任务不以提交代码为前提。

## 推荐交付流程

1. 实施 Agent 完成开发和自测。
2. 独立验收 Agent 完成本地验收。
3. 协调开发 Agent 向用户汇报改动范围、测试结果和已知风险。
4. 用户针对本次操作明确确认是否提交、推送以及目标分支；用户也可以选择自行操作。
5. 获得明确授权后，协调开发 Agent 才能创建提交并推送到指定远端分支。
6. 推送后由 GitHub Actions 自动运行 CI；CI 失败时进入问题分析和返工，成功后继续最终验收或合并流程。

一次提交或推送授权只适用于用户明确指定的当前任务、仓库和分支，不自动扩展为后续任务的长期授权。

## 提交信息语言

- 提交标题和正文统一使用中文。
- 标题应简洁说明本次提交带来的主要变化，正文按需列出重要实现、测试或治理变更。
- 当前不强制使用英文 Conventional Commits 类型前缀；除非用户以后重新确认，否则不得将中文标题替换为纯英文提交信息。

## 允许的只读检查

Agent 可以按任务需要执行：

- 查看工作区状态；
- 查看差异和提交历史；
- 查看当前分支和远端配置；
- 比较文件或提交；
- 定位已有改动来源。

只读检查也不得暴露凭据或无关敏感信息。

## 获得授权后

- 明确仓库、分支、文件范围和目标远端；
- 提交只包含本任务相关改动；
- 不混入用户或其他 Agent 的无关改动；
- 提交信息使用中文并准确描述行为变化；
- 推送前报告测试状态和已知风险；
- 禁止使用强制推送，除非用户对确切分支明确授权。

## 禁止的默认恢复方式

不得使用可能丢失工作区内容的命令来处理未知改动，包括硬重置、强制检出覆盖和无确认清理。需要恢复或删除内容时，先解析精确目标并获得相应授权。
