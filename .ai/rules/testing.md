# 测试与验证规则

## 原则

- 每项验收标准都应有可执行或可观察的验证方式。
- 测试强度应与改动风险相称。
- 实施 Agent 的自测不能替代独立验收。
- 所有报告必须区分“通过”“失败”“未运行”和“无法运行”。

## 实施阶段

实施 Agent 至少应：

- 运行直接覆盖改动的测试；
- 运行适用的类型检查、静态检查或构建；
- 检查受影响的异常路径和边界条件；
- 对新增或修复的行为补充适当的自动化测试；
- 记录命令、结果和未运行项原因。

## 验收阶段

验收 Agent 应：

- 不依赖实施 Agent 的结论，独立运行关键检查；
- 按 Spec 验收项逐项记录证据；
- 验证失败路径、权限、数据边界及相关回归；
- 区分环境问题、测试问题、实现问题和 Spec 问题；
- 不通过修改代码让测试“变绿”。

## 失败处理

- 不得隐藏、删除或忽略失败测试。
- 已知与当前任务无关的失败也要记录，并说明判断依据。
- 若测试环境缺失，报告具体缺失项和恢复验证所需条件。
- 不得在没有证据时将偶发失败标记为无关。

## 验收证据

可接受的证据包括：

- 测试或构建命令及退出结果；
- 可复现的操作步骤和观察结果；
- 相关日志、截图或输出文件；
- 精确的文件位置和代码检查结论。

敏感信息不得写入验收证据。

## 常规 CI 范围

- `ci.yml` 不安装浏览器，也不运行 `pnpm test:e2e`；
- 常规 CI 仍通过根级 `pnpm lint` 和 `pnpm typecheck` 检查 `e2e/` 源码；
- Browser E2E 由具体 Spec 的实施和独立验收在本地按风险运行，不得因移出 CI 而省略 Spec 明确要求的浏览器验收；
- 未来如需发布前浏览器门禁，应通过新的已确认决策建立独立手动工作流或发布前 Smoke E2E，不直接恢复到常规 CI。

## E2E 测试版本控制

- `e2e/` 中的 Playwright 配置、测试脚本、测试辅助代码和必要的非敏感测试夹具属于可复用项目源码，必须纳入 Git。
- SPEC 要求新增或调整端到端场景时，对应 E2E 测试脚本必须随业务实现一同交付，不得只保存在临时验收目录。
- `playwright-report/`、`test-results/`、`blob-report/`、截图、录像、追踪文件和其他单次运行产物不纳入 Git；需要长期保存的验收证据应整理为不含敏感信息的文本记录。

## 临时测试副本与自动清理

- 只有在验证干净安装、隔离构建或其他必须使用独立工作区的场景中，才创建项目临时副本。
- 临时副本必须创建在仓库根目录 `test/` 下的任务专属子目录中，例如 `test/spec-001-acceptance-round-1/`；不得创建到 `%TEMP%`、`C:\Users\...\AppData\Local\Temp` 或仓库外的其他位置。
- 创建副本时必须排除根目录 `test/` 本身，防止递归复制；还应按测试目标排除 `.git/`、`node_modules/`、构建产物、测试产物、真实环境文件、本地数据和媒体目录。
- 创建、使用和删除前必须解析并核对绝对路径，确认目标严格位于当前仓库根目录的 `test/` 内。禁止对仓库根目录、`test/` 以外路径或未解析变量执行递归删除。
- 测试脚本或 Agent 必须使用等价于 `try/finally` 的清理流程：无论测试通过、失败或中途出现可处理异常，都自动删除本轮创建的临时验收脚本和其他一次性测试文件。
- 任何 `node_modules/` 均不属于自动清理范围。已存在或本轮生成的 `node_modules/` 可以保留以避免后续重复安装；未经用户明确要求，不得为了清理临时验收文件而删除它。
- 如果任务专属子目录中仍保留 `node_modules/`，可以保留承载这些依赖目录所需的父目录；除此之外的一次性脚本、项目副本文件和测试产物仍须清理。
- 只有在没有需要保留的 `node_modules/` 且任务专属子目录已经清空时，才删除该子目录；根目录 `test/` 已为空时可以一并删除，不得删除其他任务创建的子目录。
- 若回合或进程被强制中断而无法执行自动清理，协调开发 Agent 恢复时必须先确认没有相关进程正在使用临时文件，再按上述规则清理；不得同时删除保留的 `node_modules/`。
- 实施报告或验收报告必须记录临时副本路径、用途、一次性文件清理结果，以及所有保留的 `node_modules/` 路径。临时副本和其中生成的文件不得作为长期验收证据；需要保留的证据应整理为不含敏感信息的文本记录。
