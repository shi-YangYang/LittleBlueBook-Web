# 测试与验证规则

## 原则

- 每项验收标准都应有可执行或可观察的验证方式。
- 测试强度应与改动风险相称。
- 实施 Agent 的自测不能替代独立验收。
- 所有报告必须区分“通过”“失败”“未运行”和“无法运行”。

## 实施阶段

实施 Agent 至少应：

- 运行直接覆盖改动的测试；
- 运行适用的类型检查、静态检查或构建；
- 检查受影响的异常路径和边界条件；
- 对新增或修复的行为补充适当的自动化测试；
- 记录命令、结果和未运行项原因。

## 验收阶段

验收 Agent 应：

- 不依赖实施 Agent 的结论，独立运行关键检查；
- 按 Spec 验收项逐项记录证据；
- 验证失败路径、权限、数据边界及相关回归；
- 区分环境问题、测试问题、实现问题和 Spec 问题；
- 不通过修改代码让测试“变绿”。

## 失败处理

- 不得隐藏、删除或忽略失败测试。
- 已知与当前任务无关的失败也要记录，并说明判断依据。
- 若测试环境缺失，报告具体缺失项和恢复验证所需条件。
- 不得在没有证据时将偶发失败标记为无关。

## 验收证据

可接受的证据包括：

- 测试或构建命令及退出结果；
- 可复现的操作步骤和观察结果；
- 相关日志、截图或输出文件；
- 精确的文件位置和代码检查结论。

敏感信息不得写入验收证据。
