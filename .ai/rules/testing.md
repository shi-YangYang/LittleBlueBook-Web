# 测试与验证规则

## 原则

- 每项验收标准都应有可执行或可观察的验证方式。
- 测试强度应与改动风险相称。
- 实施 Agent 的自测不能替代独立验收。
- 所有报告必须区分“通过”“失败”“未运行”和“无法运行”。

## 实施阶段

实施 Agent 至少应：

- 运行直接覆盖改动的测试；
- 运行适用的类型检查、静态检查或构建；
- 检查受影响的异常路径和边界条件；
- 对新增或修复的行为补充适当的自动化测试；
- 记录命令、结果和未运行项原因。

## 验收阶段

验收 Agent 应：

- 不依赖实施 Agent 的结论，独立运行关键检查；
- 按 Spec 验收项逐项记录证据；
- 验证失败路径、权限、数据边界及相关回归；
- 区分环境问题、测试问题、实现问题和 Spec 问题；
- 不通过修改代码让测试“变绿”。

## 失败处理

- 不得隐藏、删除或忽略失败测试。
- 已知与当前任务无关的失败也要记录，并说明判断依据。
- 若测试环境缺失，报告具体缺失项和恢复验证所需条件。
- 不得在没有证据时将偶发失败标记为无关。

## 验收证据

可接受的证据包括：

- 测试或构建命令及退出结果；
- 可复现的操作步骤和观察结果；
- 相关日志、截图或输出文件；
- 精确的文件位置和代码检查结论。

敏感信息不得写入验收证据。

## 临时测试副本与自动清理

- 只有在验证干净安装、隔离构建或其他必须使用独立工作区的场景中，才创建项目临时副本。
- 临时副本必须创建在仓库根目录 `test/` 下的任务专属子目录中，例如 `test/spec-001-acceptance-round-1/`；不得创建到 `%TEMP%`、`C:\Users\...\AppData\Local\Temp` 或仓库外的其他位置。
- 创建副本时必须排除根目录 `test/` 本身，防止递归复制；还应按测试目标排除 `.git/`、`node_modules/`、构建产物、测试产物、真实环境文件、本地数据和媒体目录。
- 创建、使用和删除前必须解析并核对绝对路径，确认目标严格位于当前仓库根目录的 `test/` 内。禁止对仓库根目录、`test/` 以外路径或未解析变量执行递归删除。
- 测试脚本或 Agent 必须使用等价于 `try/finally` 的清理流程：无论测试通过、失败或中途出现可处理异常，都自动删除本轮创建的任务专属临时子目录。
- 删除任务专属子目录后，如果根目录 `test/` 已为空，可以一并删除空的 `test/` 目录；不得删除其他并行任务创建的子目录。
- 若回合或进程被强制中断而无法执行自动清理，协调开发 Agent 恢复时必须先确认没有相关进程正在使用该副本，再清理遗留的任务专属目录。
- 实施报告或验收报告必须记录临时副本路径、用途及清理结果。临时副本和其中生成的文件不得作为长期验收证据；需要保留的证据应整理为不含敏感信息的文本记录。
