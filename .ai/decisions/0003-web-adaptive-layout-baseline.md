# 0003：Web 页面自适应布局基线

- 状态：Accepted
- 日期：2026-07-27
- 决策人：用户
- 记录人：协调开发 Agent
- 关联：`constitution/tech-stack.md`、`specs/spec-005-adaptive-height-and-scroll/`

## 背景

首页、个人页、发布页和笔记详情页在迭代中使用了若干固定高度、嵌套视口高度计算和针对具体高度的媒体查询。它们能够匹配少量目标截图，但曾在未被列举的中间视口高度产生无意义根滚动条。继续追加固定宽高组合和断点补丁会让页面行为越来越依赖测试样本，不能形成真正连续的自适应布局。

## 决策问题

确定当前 Web 项目的最低桌面兼容范围，以及页面高度、滚动归属和浏览器验收应采用固定分辨率适配还是连续自适应模型。

## 备选方案

### 方案 A：固定分辨率与高度断点适配

- 说明：为常见宽高组合分别设置尺寸和媒体查询；
- 优点：容易精确贴合指定截图；
- 代价与风险：组合数量持续增长，相邻像素区间容易出现断档，测试和维护成本高。

### 方案 B：连续自适应布局

- 说明：定义最低兼容边界，通过 Flex、Grid、动态视口单位和内容驱动尺寸形成连续布局；
- 优点：不依赖枚举所有屏幕尺寸，窗口变化时行为一致，更容易建立统一滚动模型；
- 代价与风险：需要重构现有页面级高度计算，并明确每类页面的滚动容器。

## 最终决定

采用方案 B：

- 桌面 Web 的最低支持范围为 CSS 视口宽度不低于 `960px`、高度不低于 `600px`；
- 宽度和高度是两条独立下限，不代表只支持 `960×600` 或其他固定分辨率组合；
- 在支持范围内，页面必须随可用空间连续自适应，不得为通过某个具体宽高测试而添加孤立补丁；
- 低于支持范围时仍须保证内容可滚动、可访问且不被裁切，但不要求维持完整桌面视觉比例；
- 验收以滚动归属、内容可访问性、无假滚动、无裁切和无双重滚动为准；
- 浏览器测试选择少量小、中、大代表性视口并执行连续调整窗口检查，不枚举大量固定宽高组合；
- 真正存在内容溢出时保留可见且可操作的滚动能力，不以隐藏滚动条掩盖布局问题。

## 理由

- 最低边界提供明确的兼容性合同，同时不把页面实现绑定到某一个物理显示器分辨率；
- CSS 视口像素会自然反映浏览器缩放和系统显示缩放，比按设备型号或物理像素适配更可靠；
- 连续自适应可以直接避免此前由高度断点空档造成的根滚动条；
- 行为型验收比逐一验证固定尺寸更能反映真实用户调整窗口时的体验。

## 影响

- SPEC-005 将统一现有页面的高度计算和滚动归属；
- 局部按钮、图标、头像等仍可使用固定尺寸，页面级容器不得依赖密集的固定高度补丁；
- Browser E2E 继续保留在本地实施和独立验收流程，不进入常规 CI；
- 后续新增页面应遵循相同的最低兼容边界和滚动原则。

## 后续复审条件

当项目正式支持移动 Web、需要嵌入 WebView、最低设备范围发生变化，或出现必须使用独立滚动容器的新型页面时重新评估。
