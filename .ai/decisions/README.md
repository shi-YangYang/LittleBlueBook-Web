# 决策记录

本目录保存会影响后续开发的重要项目决策，避免关键结论只存在于对话上下文中。

## 何时创建决策记录

以下事项通常需要记录：

- 产品范围、业务规则或验收口径；
- 架构、数据模型、接口和关键技术选型；
- 安全、隐私、兼容性和性能基线；
- 工作流、Agent 权限和职责边界；
- 对已有重要决策的修改或废弃；
- 存在多个合理方案且选择会产生长期影响的事项。

普通实现细节、可从代码直接看出的局部选择和无长期影响的修正通常不需要单独记录。

以下内容也不应仅因项目初始化而创建为决策：

- 已由用户直接规定的 Agent 职责和协作约束；
- 对现有规则、目录和工作流的说明；
- 尚未比较备选方案的初始化约定；
- 对 `AGENTS.md`、`constitution/`、`.ai/workflows/`、`.ai/prompts/` 或 `.ai/rules/` 内容的重复转述。

这些内容应直接写入对应的权威文件。只有后续确实出现需要权衡的选项，并由用户作出会影响项目的选择时，才创建决策记录。

## 命名规则

```text
NNNN-short-kebab-case-title.md
```

编号按目录中已有最大编号递增，例如：

```text
0001-sdd-multi-agent-collaboration.md
```

## 状态

- `Proposed`：已提出，尚未确认；
- `Accepted`：已确认并生效；
- `Superseded`：已被新决策替代；
- `Deprecated`：不再推荐，但可能仍有历史使用；
- `Rejected`：讨论后未采用。

若决策被替代，应在旧记录和新记录中互相链接，不覆盖历史内容。

## 决策流程

1. 协调开发 Agent 识别决策点和可选方案。
2. 用户确认选择。
3. 协调开发 Agent 创建或更新决策记录。
4. 相关 Constitution、Spec、工作流或代码同步引用该决策。

新记录使用 `_template.md`。
